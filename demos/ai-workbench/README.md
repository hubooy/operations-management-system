# AI 工作台交互 demo

此目录是独立、本机、合成数据的 UI 原型，展示 AI 对话重构、Markdown 排版、真实 HTTP SSE 传输及新版模型配置设计。没有修改生产 AI 页面或 Django 逻辑，不访问业务数据库，不调用供应商，也不收集真实密钥。

## 启动与体验

在此目录运行 `npm ci`，再运行 `npm run dev`；打开 http://127.0.0.1:3100/。保持终端运行即可预览，Ctrl+C 只停止本 demo。端口占用时失败，不接管已有服务。

- 默认打开经营复盘，全部指标、商品和建议均为固定合成示例。
- 新建对话、会话搜索与切换、追问、复制、停止生成可以交互；刷新后恢复初始状态。
- 点击“重播流式效果”或发送问题，服务端通过 `text/event-stream` 分段发送固定回答。不是收齐全文后在浏览器伪装打字。
- 普通问题映射经营复盘，补货/库存问题映射补货示例，格式/代码问题映射排版示例；不是任意问题的真实 AI 推理。
- “任务详情 → 下次请求场景”可选择正常、中途断开、生成失败。部分回答会保留，不自动重发。
- “AI 管理”展示四组设置：容量与生成、模型与连接、工具与执行、风格与费用。保存只更新当前页面内存；这些参数不驱动供应商请求或正式执行。
- Markdown 使用 react-markdown / remark-gfm，支持表格、列表、引用、代码和任务清单。禁用原始 HTML；沿用安全 URL 处理，外部图片不加载。流式时对未完成表格和常用控制符进行显示缓冲，原始消息不被改写。

构建 `npm run build` 只生成此目录的 `dist`。SSE 中间件只在 `npm run dev` 下提供，因此静态产物不代表完整在线 AI 服务。不要使用它替换生产 Worker 或部署入口。

## 当前代码核查

基线 `af22d2714903e2dd96ffc5b3c83114fcd986335f`：

| 问题       | 当前实现                                                                                                    | 影响与后续设计                                                                                |
| ---------- | ----------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 最大输出   | `app/ai-assistant-view.tsx` 输入框与 `backend/ai_assistant/configuration.py` 同时限定 128–8,192，默认 4,096 | 同事截图的 65,536 是当前上限的 8 倍。需要同时修正配置契约和请求执行；仅改输入框无效。         |
| 上下文窗口 | 当前配置未提供独立模型上下文容量                                                                            | 不能据输出 tokens 推断可读取的历史长度；需要真实容量、输入/历史/工具结果/输出预留与压缩策略。 |
| 温度       | 当前 UI 以千分数表示，服务端 0–1,000                                                                        | demo 改为小数或留空；真实范围和参数是否可省略必须按具体端点验证。                             |
| 工具预算   | 默认 6 轮 / 12 次，保存上限 62 轮 / 74 次                                                                   | 这些是执行约束，不是模型容量。增加轮数还要考虑总时限、单工具调用次数、权限和审计。            |
| 回复渲染   | 当前 `item.content` 直接放入普通 `<p>`                                                                      | Markdown 被显示为纯文本；需在完整页和各模块聊天入口统一替换为安全渲染组件。                   |
| 输出方式   | `backend/ai_assistant/provider.py` 的 `turn()` 读取完整 `bounded_json` 后处理                               | 现有全链路不是增量 token SSE；前端单独增加打字动画不能解决等待和恢复。                        |

默认 4,096 和最高 8,192 会约束长回答；但参数数量、费用单价和上下文声明本身不会提高模型推理质量。项目现有复盘还记录了超时和工具编排失败，不能把扩大输出预算视为这些问题已解决。参考 `docs/AI_CHAT_RELIABILITY_REVIEW_20260910.md`。

## 正式接入范围（尚未实现）

1. Django 作为唯一配置、任务、消息与审计权威；按具体供应商、完整端点、协议和模型验证能力。不能按模型名称硬编码推理参数。
2. 区分模型输出硬上限、每任务预算、上下文容量及压缩门槛；对应 Django migration、配置/读取契约、角色权限和备份清单同步更新。
3. 供应商流 → Django 任务与事件持久化 → 薄 Worker SSE 转发 → React 安全增量排版。区分首段、空闲、总时限，处理代理缓冲、取消传播、终态、截断和工具分片。
4. 事件 ID 与只读回执恢复绑定用户、会话、任务和权限；客户端断线不能自动重放付费模型请求。工具权限和有界执行继续由中央注册表决定。
5. 独立 PostgreSQL 镜像验证迁移、审计、并发、幂等与故障；真实端点场景验收另行按授权执行。UI demo 不替代这些门禁。

## 验证

`npm test` 覆盖真实 HTTP SSE 首事件/增量/完成、UTF-8 跨字节、CRLF/多事件、取消、异常/断开、非 SSE、非法输入/来源、Markdown 安全渲染与不完整表格。`npm run build` 验证 React/CSS 产物。本次不做生产构建、数据库迁移、服务重启或发布。
