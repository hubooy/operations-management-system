# 固定筛查报告的创建与幂等

第四十八批提供 `analysisMode: screening-v1` 的专用创建服务。报告先固定封存范围、商品关联、可选预算、模型和工具目录，并原子创建六节点工作流；此时不运行模型、不扫描筛查候选，也不代表已通过模型容量准入。

目录请求和固定预算准备在最外层事务之外完成。提交只核对当前身份、模型版本、不可变证据及预算准备对象，在同一事务保存预算、报告、工作流、节点、指导和创建事件。后续 HTTP 接入通过私有提交回调把业务变更与完成回执放入同一事务。相同用户与 clientRequestId 的完整请求可找到原结果；请求内容变化拒绝，不另建任务。

新模式禁止 dryRun、空的关联对象和自定义执行协议。每位用户最多四个活动报告、全局最多二十四个。准备失败或最终提交失败不得留下半份报告。映射和预算的四种组合分别验证；五个 Agent 的派发仍必须通过后续完整筛查和当前模型准入。

此批是候选源码，HTTP 注册与整条调度验收另见运行接入批次，不表示生产采用。测试与已修正的测试夹具问题见 [候选证据](evidence/ai-business-screening-creation-candidate.json)。
