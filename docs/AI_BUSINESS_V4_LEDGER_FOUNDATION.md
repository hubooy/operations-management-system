# v4 大规模证据独立物理账（0035，未启用）

0035 仅新增 `ai_business_v4_runs`、`ai_business_v4_sources`、`ai_business_v4_chunks` 和 `ai_business_v4_tool_receipts`。旧 v1–v3 的 67 张 AI 表、64 MiB/2,000 页 CHECK、迁移函数及已存事实保持原样。v4 首档由纯容量合同声明单来源最多 **16,384 页/2 GiB**、整任务最多 **65,536 页/8 GiB**；数据是原拥有方日页或财报月页的规范 JSON，每页仍受 100 行及日页 128 KiB／财报页 38,000 字节限制。一个 v4 run 至少一份日来源和一份财报上下文；完整查询、比较区间、自然月身份、来源序号和摘要在初始单事务目录中固定。

当前物理表没有注册 collector、公开路由、调度器、封存、Agent、模型或文件入口。隔离测试可模拟“块→成功工具收据→来源检查点→父计数”的同一事务：块和收据只能追加；来源/父计数一次增一页，原始 UTF-8 SHA、拥有方来源修订、账号/权限、精确来源查询及日／月页形状都受 PostgreSQL 守卫核验。延期块约束在提交时要求收据及父/来源计数完整，延期父约束阻止单独虚增计数；每页仅检查选中末块及最多 48 个来源计数，不扫描历史全部事实。SQL 日页目前只核原始 current 日期，前期/去年同期的实际推导仍须拥有方完整页校验；隔离负例证明自洽摘要的错基期页可落物理账、但拥有方 validator 会拒绝。v4 计划固定 `sourceAuthorityVerified=false`；没有完整业务重放或 attestation 之前，物理存在不等于可用于报告的权威证据。

数据库初始槽位最多每个无范围管理员 **2 个**、全局 **8 个** v4 run，相应容量上界为每人 16 GiB、全局 64 GiB；目前无取消/清理机制，槽位不会自动释放。AI writer 对新 run/source 仅 SELECT、INSERT、UPDATE，对 chunk/receipt 仅 SELECT、INSERT；AI reader 尚无这些表的 SELECT 权限。版本表清单从 67 变为 71；备份与维护校验只在发现 `0035_business_v4_ledger` 迁移时要求这四表，旧 65/66/67 表历史演练使用冻结清单。

下一阶段仍须独立实现 O(1) 追加拥有方工具桥、长期续读和完整来源类型验证，再做可恢复的单次流式扫描、不可变 attestation 与封存门禁。真实 575,095 行的行宽/页数和磁盘恢复耗时尚未测量；不得将本物理迁移当作采集或报告能力已上线。本文不授权生产迁移、真实数据采集或模型执行。
