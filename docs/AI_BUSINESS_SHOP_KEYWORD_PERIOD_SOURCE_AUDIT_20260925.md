# 店铺与关键词多期来源接线核查（2026-09-25）

本次仅审查仓库代码并运行离线测试；未访问生产事实、平台账号或客户原始行。

## 已有能力

- `backend/netshop/analysis.py` 的 `promotion/京东` 明确指向 `jd_promotion/ad`，推广原始维度可投影“关键词”和“搜索词”，并分别保留花费、展示、点击、平台归因等本域指标。`backend/business_analysis/results.py` 可按 `keyword` 和 `shop` 分组，对同一来源的 `current` 与单个 `previous` 或 `yearAgo` 基期计算比较；日期不全、字段缺失和空分组不会补零。`shop` 是**所选来源的汇总**，不是独立店铺总览或去重 UV。
- `backend/business_analysis/contracts.py` 定义前一等长周期和去年同期（闰日压至当月末）的固定期间。来源页须经完整分页、行数和指标控制汇总核对；每个基期仍须拥有明确来源键、同店范围和完整日期覆盖。

## 本次补上的最小门禁

同店同来源、同日期规则仍不足以证明指标口径相同。此前 `results._compatible` 没有比较两期 `metricSemantics`；`results._group` 也未拒绝分页续读中指标说明改变，因而两期同名指标或同一来源页链可能混用不同含义。本次要求同一页链及两期的 `metricSemantics` 完全一致，否则拒绝发布比较表。店铺与关键词双维度、跨页篡改的负例及旧报告回归测试均通过。门禁只阻断口径漂移，**不赋予来源本身权威性**。

## 仍缺的数据接线

1. 每份实际报告需经已授权的 owning Reader 固定**本期、前一等长周期、去年同期**三个京东推广来源键，逐页封存同一精确店铺、源修订、指标定义和日期覆盖；单次 `build_table` 只接受一个基期，两个基期结果需在同一报告证明下汇合。历史可用性不能由本次静态核查保证。
2. 关键词仅以推广来源的原始“关键词”字段解释；“搜索词”是独立维度。缺关键词值、未出现日期或推广来源缺失时保留 unknown/unavailable，不从商品名、市场榜单词或模型推断关键词；推广归因金额不当 ERP 净销售。
3. 店铺层另需独立、已核口径的店铺交易概况来源。当前 `jd_shop_overview/trade_overview` 只是通用导入，尚无可信表头、日粒度唯一性或 owning 分析源；日店铺 UV 和完整区间去重 UV 的证据门槛见 [专项核查](AI_BUSINESS_JD_SHOP_OVERVIEW_UV_GAP.md)。商品日访客、推广访客与日 UV 求和都不能替代区间去重 UV。
4. 正式同比/环比还要核实际本期、前期、去年同期三份源的可用日期、平台结算成熟度、空值和业务身份；通过纯函数或合成测试不等于真实店铺已完成三期对账。
