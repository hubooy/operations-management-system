# 完整筛查的固定存储

第三十五批候选实现将已完成筛查保存为不可变 run 和分页记录。代码在独立开发分支，尚未生产采用；没有开放新的模型工具或执行协议。历史设计见 [存储设计](AI_BUSINESS_SCREENING_STORAGE_DESIGN.md)，实际合同以本文及代码为准。

`prepare_for_report` 在事务外完整计算，`business_screening_store.publish` 只接受本进程产生的 `VerifiedScreening`。发布短事务重新核验真实账号、报告与工作流、封存目录、来源元数据、固定选择计划、映射和预算绑定，再一次插入父记录、全部页及审计。相同固定键和完全相同内容返回原 ID；不同内容冲突，失败整批回滚。客户端 JSON 或摘要不能恢复可信计算对象。

读取按固定 ID、页组及服务端返回的偏移进行，每次前后重新授权并校验绑定和页摘要。它不重新扫描事实，也不代替每个 Agent 自己的读取回执。全部保留候选不等于全部匹配项，更不等于模型逐行阅读全部事实。

| 限制 | 当前值 |
| --- | ---: |
| binding / manifest | 8192 / 65536 UTF-8 字节 |
| 单页 | 20 项、38000 UTF-8 字节 |
| 单次结果 | 4096 页、16 MiB |
| 单用户 | 20 份、64 MiB |
| 全局 | 200 份、256 MiB |

字节额度包括 binding、manifest 和全部页载荷，独立于原事实、预算与文件额度，不代表数据库物理占用。页保留完整前缀，超宽记录明确失败；空分区也保存终页。成功结果当前没有自动清理，满额后拒绝新增。

迁移 `0023_business_screening_storage` 新增两张表，AI 自有表由 63 增至 65。reader 仅 SELECT，writer 仅 SELECT/INSERT；数据库校验真实绑定、严格 JSON 类型、连续页链、实际 SHA、集合完整性和真实字节。发布配额通过已有 AI revision 行锁串行核验，等待锁后读取最新计数。不可变父行无需额外更新权限：未提交父行只对本事务可见，完整性延迟约束不允许带空余页位提交，已提交结果不能再追加。

全局和每组摘要链从 SHA256(`[]`) 开始，每步为 SHA256(`前一摘要:十进制序号:载荷摘要`)；组内序号从 1 起。实际载荷摘要覆盖页坐标和内容，规范 JSON 另有自身摘要。该合同不同于早期设计的元组表述，以 `screening_storage.py` 和数据库校验的一致实现为准。

备份识别历史无 0023 的 63 表集合；有迁移却缺新表必须失败。两新表非空时拒绝逆迁移。升级演练必须保留原 63 表摘要，真实受限账号发布/回读，并独立恢复全部 65 表后读取原页，禁止恢复时重算替换。

当前仍需新版本角色包、模型容量准入、每 Agent 独立读取证明及报告/文件接线。存储成功不能提前关闭这几项验收。最终测试与失败修复记录见 [本批候选证据](evidence/ai-business-screening-storage-candidate.json)。
