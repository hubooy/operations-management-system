# 吉客云自动化状态机与下载后处理

适用于每日五类数据导入的自动化主路径。本文是浏览器执行与本地 runner 的唯一状态规范；模块业务边界仍以《吉客云五类数据导入可复用工作流》为准。

## 1. 不变边界

- 严格顺序：`products → inventory → inventory_age → sales → combos`。
- 当前模块完成“下载、校验、处理、导入、核验”后，才进入下一模块。
- 每次只修改一个吉客云字段；修改后必须在同一次操作中读回当前值。
- 分仓库存和库龄只接受可按日期查询的历史来源；实时页、无日期框或日期读回不一致不得发布为历史快照。
- 每个模块只允许提交一次查询、点击一次导出；导出意图不明确时先检查状态，禁止直接重试。
- 只接收本轮导出开始时间之后，由下载事件返回的明确文件路径；不得扫描或猜测“最新文件”。
- 任何状态无法证明、登录验证、文件异常、导入失败时，立即进入 `BLOCKED` 并停止后续模块。

## 2. 单标签与运行标识

1. 全流程只复用一个吉客云标签页和一个浏览器控制绑定。
2. 本地系统不再通过浏览器文件选择器导入；下载后统一调用 runner。
3. 开始时生成一个 `RUN_ID`，格式建议为 `YYYYMMDD-HHmmss`；五个模块必须复用同一 `RUN_ID`。
4. runner 会在 `outputs/jackyun-import-runs/<RUN_ID>/run-manifest.json` 中强制检查模块顺序。
5. 每次状态转换记录进入时间、离开时间、耗时和一条可复核证据；这份时间线用于定位浏览器等待、下载或本地处理的真实瓶颈。

## 3. 模块状态机

```text
PRECHECKED
  → ENTER_MODULE
  → VERIFY_FIELD（每次只处理一个字段，操作后立即读回）
  → QUERY_ONCE（仅需要查询的模块）
  → WAIT_TABLE_STABLE
  → ARM_DOWNLOAD
  → EXPORT_ONCE
  → CONFIRM_EXPORT_DIALOG（组合装必经，其余模块按页面实际提示）
  → WAIT_EVENT_AND_FILE
  → HANDOFF_EXACT_PATH
  → RUNNER_VERIFIED
  → MODULE_DONE

任一不可证明状态 → BLOCKED
```

每个状态只接受明确的成功条件，不能用“看起来完成”推进。状态对象至少记录：`module`、`state`、`enteredAt`、`elapsedMs`、`evidence`、`navigationIntentAt`、`queryIntentAt`、`exportIntentAt`、`downloadPath` 和 `failureCode`；所有时间均为带时区的 RFC3339。页面仍加载或动作结果不确定时只轮询读状态，不重复触发动作。

### PRECHECKED

一次性确认北京时间、昨天日期、`http://localhost:3000` 可访问、吉客云已登录、下载目录可写、一个吉客云任务标签页和 `RUN_ID`。执行日不是每月 1 日时，销售区间为本月 1 日至昨天；执行日为每月 1 日时，区间改为上个自然月 1 日至上月最后一天。前检只做一次。

### VERIFY_FIELD

- 先读取当前值；值已正确则不操作。
- 需要修改时，只修改当前字段，并立即读回该字段。
- 一次浏览器调用可以包含“修改一个字段 + 读取同一字段”，不能顺带修改第二个字段。
- 分仓库存的仓库选择必须确认“全选”及页面当前总数；历史仓库数量只作量级参考，不能作为固定值。
- 分仓库存和库龄必须把目标业务日写入历史日期控件并精确读回，记录 `controlReadbackAt`；调用参数或后处理生成的元数据不是源日期证据。

### QUERY_ONCE

- 销售日期必须逐字段确认为 PRECHECKED 算出的月度区间，统计时间类型为发货时间，才允许查询。
- 分仓库存和库龄的日期读回必须发生在 `queryIntentAt` 之前，并与该次唯一查询绑定；读回缺失或不是目标日立即停止。
- 点击前先布置当前模块 MiniUI grid 生命周期与 XHR/Fetch 跟踪，再持久记录 `queryIntentAt`；之后查询按钮只点击一次。控制调用即使报错或返回不确定，也不得再次点击，只能观察本轮刷新证据。

### WAIT_TABLE_STABLE

60 秒是页面级总上限，不是固定等待。满足以下条件即继续：

1. 加载遮罩或刷新标识已消失；
2. 表格存在真实数据行，且不是空表或只有 1～2 行；
3. 需要显式查询的模块必须观察到发生在本轮 `queryIntentAt` 之后的完成证据。销售可使用目标 MiniUI grid 的加载生命周期或当前模块 XHR/Fetch；分仓库存和库龄只接受请求 URL/载荷同时命中当前模块与目标历史日期、同一 requestId 收到 2xx 响应并完成的 XHR/Fetch，非 2xx、缺失响应状态、网络失败或任意 MiniUI 网格生命周期都不能证明历史日期查询。货品/组合装若进入模块后无需再查，则使用进入模块前记录的 `navigationIntentAt` 并核对模块身份。仅凭旧表连续稳定不能推进；
4. 页脚精确总行数或 MiniUI grid 总数连续两次读取一致，两次读取间隔 500～1000 毫秒；将稳定后的页面总行数保存为 `expectedSourceRows`；
5. 分仓库存与库龄的 `snapshotEvidence` 必须继续保存此前精确读回的目标日，并与同一 `queryIntentAt`、`queryRefreshSource`、`queryRefreshCompletedAt`、`tableStableAt` 和后续导出时间保持严格顺序；刷新完成必须位于查询与表格稳定之间。

任一条件无法证明时，在 60 秒内只读取状态，不重复查询。

### ARM_DOWNLOAD

在打开导出菜单前建立当前模块下载窗口，监听条件同时包含：

- 当前文件必须直接位于 `downloadDirectory/jackyun/<RUN_ID>/<module>/`；文件名只作审计，OSS 数字对象名允许通过；
- `exportIntentAt` 时间下界；
- 收集本窗口内所有匹配事件，直到归属判定完成。

同时记录下载目录基线。目录变化仅用于核对事件对应文件是否落地，不能替代下载事件。能力支持时，必须在同一个受支持的浏览器调用里完成“持久监听注册 → 记录 export intent → 点击 → 等待事件”；否则必须证明监听在跨调用期间持续有效。

### EXPORT_ONCE

- 在真实数据行上打开菜单。
- 优先按精确文案定位“导出所有页（限 500000 行）”；组合装使用“导出组合装及子件 → 导出所有页”。
- 组合装选择“导出组合装及子件 → 导出所有页”后，不得直接等待下载；页面会出现导出确认框，必须转入 `CONFIRM_EXPORT_DIALOG`。
- 只有精确文案为 0 个或多个匹配时才截图定位。
- 点击前先持久记录 `exportIntentAt`，之后本模块不得再次点击导出；调用结果不确定时只观察下载窗口。

### CONFIRM_EXPORT_DIALOG

- 组合装必须核对提示文本同时包含“导出列中存在图片列”“最多只能导出2000条”“确定导出”；不把其他弹窗当成该提示。
- 只点击一次“确定”，记录 `exportConfirmation.prompt`、`exportConfirmation.button` 和 `exportConfirmation.confirmedAt`，再进入下载等待；不得重复点击导出或确认。
- 2000 条是图片列导出提示，不直接作为母子关系完整性的证明。无论页面母件是否超过 2000，都按用户规则确认导出；随后仍由 runner 强制核对“页面母件总数 = 第一张表母件行数”、两表母件集合覆盖及最近成功批次 95% 门禁。任何一项不符均在上传前停止。

### WAIT_EVENT_AND_FILE

- 等待一次性浏览器下载事件或白名单 OSS 事件返回绝对路径；仅在共享目录发现一个新文件不算下载事件。
- 事件到达后确认文件位于 `D:\谷歌浏览器`、扩展名为最终 `.xlsx`、不存在对应 `.crdownload`，且大小和修改时间至少间隔 1 秒连续两次不变。
- `downloadProvenance` 必须包含 `RUN_ID`、模块、策略版本、下载 ID、方式、完成时间、原文件名、SHA-256 和字节数；OSS 后备还必须包含白名单 host 与 URL 哈希。
- 本窗口若出现多个当前模块候选：SHA 全相同时只把最早完整事件对应的文件交给 runner，其余记录为 `duplicateIgnored`；出现不同 SHA 时立即 `BLOCKED`，不得自行选择。
- 超时后先核对本轮时间窗口内是否已经有事件或文件；仍无法证明时进入 `BLOCKED`，禁止重新点击导出。

### HANDOFF_EXACT_PATH / RUNNER_VERIFIED

浏览器把同一 schema v2 handoff 中的绝对路径、`RUN_ID`、策略版本、完整导航/查询/稳定/导出/下载时间线和 `downloadProvenance` 直接传给统一 runner；库存和库龄还必须传递历史日期读回、日期绑定网络刷新完成时间和表格稳定组成的 `snapshotEvidence`。runner 将 handoff 时间线和 provenance 纳入输入证据摘要，二次校验后才负责过滤、分片导入及批次核验；C 节点从归档审计重算摘要，并与规范原子 handoff、真实文件、由输出 SHA 推导的批次身份及当前事实归属交叉核验，销售另核验回查的原文件哈希和可选成本来源批次。`duplicate_ignored` 与续跑前缀也必须先通过同样的归档和原子 handoff 复验；`prepared` 不得推进或原地升级为每日正式任务。

## 4. 统一 runner

正常日跑由统一自动化入口同时启动 daily runner 和浏览器 controller。controller 按顺序向 `outputs/jackyun-browser-events/<RUN_ID>/` 写入 `01-products.json`、`02-inventory.json`、`03-inventory_age.json`、`04-sales.json`、`05-combos.json`；组合装事件还必须包含确认框证据。daily runner 会等待精确事件、执行当前模块、写回 `<事件文件>.result.json`，只有结果为 `completed` 才接受下一模块事件。完整浏览器状态保存在 `browser-state.json`，规则来自 `config/jackyun-daily-policy.json`。

正式自动化现统一使用：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-automation-runner.ps1" --run-id <RUN_ID>
```

该入口在同一 Node 进程中并行启动 daily runner 与 `jackyun-browser-controller.ts`。controller 使用独立 Chrome 用户目录和调试端口，不占用用户日常 Chrome；每次查询、导出和组合装确认前先原子持久化动作状态。首次使用专用配置时，先执行以下命令打开专用 Chrome，人工完成吉客云登录，并在 Chrome 提示时选择保存密码：

```powershell
npm run jackyun:login
```

`npm run jackyun:browser -- --check-login` 只返回 `authenticated`、`login_required` 或 `unknown`，不读取或输出账号、密码、Cookie、Token、表单值或页面业务内容。程序不再接受账号密码文件和 `JACKYUN_USERNAME` / `JACKYUN_PASSWORD` 环境变量。日常任务复用 profile 登录态；会话失效时，只在 Chrome 已自动填充两个字段且没有验证码/二次验证时点击一次登录。否则立即停止，等待人工重新验证。

中断后使用相同 `RUN_ID` 续跑：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-automation-runner.ps1" --run-id <RUN_ID> --resume
```

续跑先精确核对 `daily-run-contract.json` 中的 `RUN_ID`、策略版本、快照日、销售截止日、本机 API 根地址和 formal/dry-run 模式；缺少该契约的旧运行，或任一字段不一致，都必须换新 `RUN_ID`，不得升级为当前口径完成。契约一致后，才以 `run-manifest.json` 的连续 `completed` 前缀为权威依据，跳过已完成模块，并从库存清单恢复销售成本源。首模块因登录页或导航失败而阻塞时，只有 `browser-state.json`、`browser-controller-state.json`、事件目录和审计目录共同证明尚未查询、导出、下载或导入，才允许以同一 `RUN_ID` 回到模块入口；这用于定时任务在人工恢复登录后自动接续。页面明确返回 0 行时，只在没有后续动作证据且从未重查的情况下允许一次有记录的查询重试。若导入前因页面当前页行数与文件实际总行数不一致而失败，只有页面“查看总数”精确读回、原文件路径/SHA、失败审计的旧值/实际值及无 import 证据全部一致，才允许修正事件元数据并复用原文件；不得再次导出。controller 仍以 `browser-controller-state.json` 防止重新触发其他已记录的查询、导出或组合装确认；已记录 `exportIntentAt` 但没有下载结果时只恢复监听或明确阻塞，不重复导出。

Chrome 若将吉客云签名 OSS 下载拦截为 `ERR_BLOCKED_BY_CLIENT`，controller 会从 DevTools 下载/网络事件捕获本轮地址，校验 HTTPS 与固定 OSS 白名单后流式下载到 `D:\谷歌浏览器\jackyun\<RUN_ID>\<module>\`。日志只保存 URL SHA-256，不保存签名 URL；统一 runner 以 download ID、完成时间、文件 SHA、字节数、XLSX 结构和精确行数绑定本轮文件，不再依赖人工复制重命名。

Windows 自动化主入口（会自动定位项目所用 Node.js）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-download-runner.ps1" --module <module> --file "<下载事件绝对路径>" --handoff-file "<本轮模块事件 JSON>" --run-id <RUN_ID> --export-start <ISO时间> --expected-source-rows <页面稳定总行数> [模块参数]
```

Node.js 已在 PATH 时也可使用：

```powershell
npm run jackyun:post-download -- --module <module> --file <下载事件绝对路径> --handoff-file <本轮模块事件 JSON> --run-id <RUN_ID> --export-start <ISO时间> --expected-source-rows <页面稳定总行数> [模块参数]
```

模块参数：

```text
products       无额外参数
inventory      --snapshot YYYY-MM-DD
inventory_age  --snapshot YYYY-MM-DD
combos         无额外参数
sales          --as-of YYYY-MM-DD --cost-source <本轮 inventory 原始成本源副本路径>
```

示例：

```powershell
npm run jackyun:post-download -- --module inventory --file "D:\谷歌浏览器\jackyun\20260716-093000\inventory\2525143708216076928.xlsx" --handoff-file "outputs\jackyun-browser-events\20260716-093000\02-inventory.json" --run-id 20260716-093000 --export-start 2026-07-16T01:44:00.000Z --expected-source-rows 22605 --snapshot 2026-07-15
```

runner 强制执行：

- handoff 的 schema、`RUN_ID`、策略版本、模块、文件、完整时间线和页面行数必须与 runner 参数一致；下载事件必须以同一运行身份、ID、SHA-256 和字节数绑定精确文件；
- 库存/库龄必须有目标日与页面读回日相等、且时间顺序为“日期读回 → 查询 → 本轮表格稳定 → 导出”的历史快照证据；单独传 `--snapshot` 会被拒绝；
- 文件必须直接位于本轮 `jackyun/<RUN_ID>/<module>/` 专属目录，文件名不再承担模块身份；
- 文件修改时间不得早于本轮 `export-start`；
- 文件大小和修改时间稳定后才读取；
- 工作表、必需列、真实数据行数和量级校验；
- 文件真实源行数必须与浏览器稳定后的 `expected-source-rows` 精确相等；组合装用第一张母件表与页面总数比对；
- 分仓库存精确剔除 `trim(仓库) == "刷刷仓"` 以及缺失、负数或无法解析的无效固定成本；明确填写 `固定成本价 = 0` 的库存行保留，库存金额按 0 计并参与补货；库龄仅精确剔除刷刷仓；
- 分仓库存同时保存本轮原始副本作为销售成本源；销售读取时自行排除刷刷仓，库存导入副本与销售成本源职责分离且均绑定本轮 SHA；
- 分仓库存/库龄处理文件写入快照日期元数据，销售处理文件写入查询区间元数据；相同日期重试字节和 SHA 保持一致，不同日期即使业务行相同也形成不同批次；
- 组合装数量必须大于 0；两张表的唯一母件集合必须互相覆盖；唯一母件—子件关系数须通过固定量级门禁，且不得低于运营系统最近成功组合批次的 95%；没有成功基线时正式替换导入停止；
- 使用 localhost 分片接口导入并按文件哈希、行数、快照日期核验批次；
- 销售正式调用现有 `sales-import-runner.ts`，并强制使用本轮明确销售文件及本轮库存成本源；
- 同一 `RUN_ID`、同一模块、同一 SHA 且快照/截止日期、页面行数、成本源 SHA、目标服务等输入契约完全一致时，重复调用才返回 `duplicate_ignored`；文件或参数不同均禁止覆盖。

`--run-id` 与 `--export-start` 均不可省略。dry-run 只写 `prepared`，不得推进 `RUNNER_VERIFIED` / `MODULE_DONE`，也不得被每日自动化续跑或汇总成 `completed`；正式运行应使用新的 `RUN_ID`。失败或已完成记录不得被另一文件或另一组参数覆盖。运行清单损坏时必须停止，不能把损坏清单当成新运行覆盖。系统尚无成功组合装批次时，先走人工核验和人工导入建立首个基线；每日自动化不得绕过该门禁。

## 5. 精简成功校验

正常成功路径只生成：

- `daily-run-contract.json`；
- `run-manifest.json`；
- 每模块一个小型 `audit/<module>.json`；
- 原始文件副本；
- 分仓库存和库龄的精确过滤副本；
- 销售 runner 的正式处理文件与既有审计。

审计仅保存文件名、时间、字节数、SHA、工作表、表头、真实行数、异常计数、最多 20 条警告样本、处理数量、批次号和阶段耗时。正常成功路径不得生成完整单元格 `.inspect.ndjson`、预览 PNG 或运行目录专用 `node_modules`。

CLI 成功输出只包含状态、行数、剔除数、批次号和审计路径；完整审计只写文件，不打印到模型上下文。

只有结构漂移、量级异常或人工明确要求排查时，才另外生成预览或异常样本；仍不得输出完整工作簿单元格展开文件。

## 6. 失败语义

runner 或浏览器进入 `BLOCKED` 后：

- 保留当前标签页、原始文件和小型失败审计；
- 不进入下一模块；
- 不再次查询、导出或改用历史文件；
- 报告最后已证明状态、阻塞动作、文件路径（若有）和错误信息。
