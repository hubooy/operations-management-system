# 吉客云五类数据导入可复用工作流

适用范围：以下五类已跑通的吉客云导出与运营管理系统导入流程。其中货品、分仓库存、库龄、组合装使用各自固定聊天框，销售使用独立的“一键销售导入任务”。后续重复执行时，按本手册复用，不在不同模块之间混用文件、规则或导入类型。

每日自动化的浏览器动作、下载绑定和统一后处理入口以 [吉客云自动化状态机与下载后处理](./吉客云自动化状态机与下载后处理.md) 为执行规范；本手册负责五类业务边界。两者冲突时，自动化状态机的安全与串行约束优先。

| 固定聊天框 | 吉客云模块 | 运营管理系统导入类型 | 快照日期 |
| --- | --- | --- | --- |
| 吉客云导入｜货品 | 货品查询（SKU 模式） | `products` | 不适用 |
| 吉客云导入｜分仓库存 | 可按日期查询的历史分仓库存来源 | 分仓库存快照 | 历史日期控件读回的执行日昨天 |
| 吉客云导入｜库龄 | 可按日期查询的历史库龄来源 | `inventory_age` | 历史日期控件读回的执行日昨天 |
| 一键销售导入任务 | 销售单明细账 | 销售明细 | 当月 1 日至执行日的昨天 |
| 吉客云导入｜组合装 | 组合装查询 | `combos` | 不适用 |

每天的固定执行顺序为：货品 → 分仓库存 → 库龄 → 一键销售导入任务 → 组合装。

## 一、所有模块共用的稳定规则

1. 目标系统固定为 `http://localhost:3000/`，不使用 `localhost:5173` 或 `localhost:8000`。
2. 每次只处理一个模块；当前模块完成“导出、下载、文件校验、导入、导入后核验”后，才进入下一个模块。
3. 吉客云页面每次只操作一个字段，操作后读取并核对该字段当前值。查询后等待表格停止刷新，再执行导出；出现“共 N+ 条”时先执行一次“查看总数”，不能用当前页数量代替总数。明确 0 行且尚无导出/下载/导入证据时最多重查一次，仍异常即停止；单个页面操作可等待最多 60 秒。
4. 右键导出时重新确认对应模块的“导出所有页”，只点击一次；不得连续点击或重复创建导出任务。组合装出现 2000 条图片列提示后，核对固定提示文本并只点击一次“确定”。
5. 不打开、不操作“下载记录和系统任务”弹窗。导出前监听浏览器下载事件，确认文件实际保存到 `D:\谷歌浏览器\jackyun\<RUN_ID>\<module>\`；事件必须携带 `RUN_ID`、模块、策略版本、下载 ID、完成时间、原文件名、SHA-256 和字节数。共享目录中仅凭名称和修改时间发现的文件不得认领。
6. 每次必须使用本轮刚下载的原始 `.xlsx`。按运行身份、精确目录、修改时间、大小和 SHA-256 记录来源；原文件名只作审计，不作为模块身份，不复用历史原始文件或处理后的文件。
7. 任何模块发生登录验证、页面异常、导出行数明显异常、文件校验失败或导入失败时：停止后续模块，保留证据并报告原因，不盲目重试。
8. 自动化成功路径不再打开系统“数据导入”页或文件选择器。下载事件返回绝对路径后，统一调用 `tools\jackyun-download-runner.ps1`（或等效的 `npm run jackyun:post-download`）；`--file`、同一 `--run-id`、本轮 `--export-start`、页面稳定总行数 `--expected-source-rows` 和原子生成的 `--handoff-file` 均为必填，不允许扫描“最新文件”。库存/库龄的 handoff 必须同时包含历史日期读回证据，单独传 `--snapshot` 无效。
9. 日常正式入口统一为 `tools\jackyun-automation-runner.ps1`。浏览器使用 `.runtime\jackyun-chrome-profile` 独立配置，不影响用户日常 Chrome；首次人工登录可由 Chrome 保存密码，程序不读取明文凭证。会话过期后仅在 Chrome 已自动填充且无验证码时点击一次登录。中断后以相同 `RUN_ID` 加 `--resume`，按清单从第一个未完成模块继续；自动接续前必须证明该模块尚未查询、导出、下载或导入。
10. 浏览器事件、controller 状态、manifest 和 audit 统一由 Node 原子写入 UTF-8 无 BOM JSON；读取端兼容并剔除历史 BOM。禁止临时使用 PowerShell `Set-Content` 拼接事件文件。
11. OSS 下载被 Chrome 拦截时，由 controller 自动执行固定域名白名单下载。每个文件保存在 `D:\谷歌浏览器\jackyun\<RUN_ID>\<module>\`，记录 download ID、原始文件名、完成时间、字节数和 SHA；不记录完整签名 URL，也不再人工复制为固定中文名称。

## 二、吉客云导入｜货品

### 导出与校验

1. 进入“货品查询”，将模式切换并读回确认为 **SKU 模式**。
2. 等待表格加载出货品编号、货品名称、固定成本价、规格等数据列。
3. 右键任一数据行，确认“导出所有页”后只导出一次。
4. 下载完成后，校验工作表、真实数据行数和必需列：`货品编号`、`货品名称`、`固定成本价`、基础单位。
5. 货品属于主数据，没有快照日期；不要虚构刷刷仓剔除数量。

### 导入与核验

- 导入类型：`products`；接口/页面来源：`/api/imports/erp`，`source=products`。
- runner 直接核对本次导入完成响应中的精确批次号、完成状态、`snapshotDate` 为空以及唯一货品编号数；不通过“最新一批”猜测本轮结果。
- 详细规则见：[货品导出导入操作手册](./货品导出导入操作手册.md)。

## 三、吉客云导入｜分仓库存

### 导出与预处理

1. 进入能按业务日期查询的历史分仓库存来源；若当前入口只有实时库存或没有日期控件，立即停止，不能把实时导出标记成昨天。
2. 只操作“全选”字段；读取并确认已选仓库数为完整公司仓库集合后，再点“确定”和“筛选”。不得只选择当前可见仓库。
3. 快照日期固定为执行日的昨天；设置后精确读回，记录 `controlReadbackAt`，并将其与随后唯一一次查询、`queryRefreshSource`、`queryRefreshCompletedAt`、表格本轮刷新稳定和导出时间绑定为 `snapshotEvidence`。网络后备证据必须由真实模块请求 URL/载荷匹配，库存与库龄还必须含目标日期；页面 `documentURL` 或通知请求不能充当刷新证据。
4. 等待表格停止刷新后，导出所有页并确认实际下载。
5. 原始文件不得改写。复制一份导入副本，仅剔除 `trim(仓库) == "刷刷仓"` 的行；名称相似但不完全相等的仓库必须保留。
6. 明确填写 `固定成本价 = 0` 的库存行保留，库存金额按 0 计并参与补货；缺失、负数或无法解析的成本从导入副本剔除。若工作簿含“可用库存”列，则“库存数量”或“可用库存”任一为负的行也必须剔除，避免服务端库存质量门禁整批拒绝。记录原始行数、刷刷仓剔除行数、无效成本剔除行数、零成本保留行数、负库存剔除行数、最终保留行数、相似仓库名称和输出副本路径。

### 导入与核验

- 导入类型：分仓库存快照；接口/页面来源：`/api/imports/inventory`。
- 快照日期填执行日的昨天。
- runner 核对本轮精确批次、快照日期、保留行数和刷刷仓为 0。
- runner 另保存本轮原始库存副本供销售成本匹配；库存导入使用保留明确零成本、仅剔除无效成本的处理副本。销售成本源仍只属于本轮且会在销售侧排除刷刷仓，销售毛利规则不随库存零成本口径改变。
- 详细规则见：[分仓库存导出剔除与导入操作手册](./分仓库存导出剔除与导入操作手册.md)。

## 四、吉客云导入｜库龄

### 导出与预处理

1. 进入能按业务日期查询的历史库龄来源，将快照日期设置为执行日的昨天并精确读回；若页面只有实时结果或没有日期控件，立即停止。
2. 点击筛选后等待表格停止刷新，再右键导出所有页。
3. 下载完成后，核对文件存在库龄分析所需的货品、仓库、库存和库龄字段，且真实数据行数处于合理量级；只有 1 行或极少量行时视为误导出。
4. 原始文件保留不改写。导入副本中仅剔除仓库名称精确等于“刷刷仓”的行，并记录剔除前后行数。

### 导入与核验

- 导入类型：`inventory_age`；接口/页面来源：`/api/imports/erp`，`source=inventory_age`。
- 快照日期填执行日的昨天。
- runner 确认本轮精确批次已完成、快照日期正确、唯一“仓库+货品编号”行数与处理文件一致，且刷刷仓为 0。

## 五、一键销售导入任务

### 导出、预处理与导入

1. 执行日不是每月 1 日时，日期固定为当月 1 日至昨天；执行日为每月 1 日时，改为上个自然月 1 日至上月最后一天。逐字段设置后必须读回确认，才可查询；当天未结束的数据不导入。
2. 查询后等待表格停止刷新，并读取语义明确的“导出 XLSX 非空明细行数”，再创建一次“销售单明细账”导出任务；不打开或操作“下载记录和系统任务”弹窗。订单数、近似数或当前页数不能作为 `expectedSourceRows`。
3. 监听下载事件，确认本轮新下载的原始 `.xlsx` 已保存至 `D:\谷歌浏览器`。不得复用任何历史原始文件或处理文件。
4. 将下载事件返回的销售文件绝对路径交给统一 runner；runner 在同一 Node 进程中调用正式销售函数，不再启动并解析一个子进程。`一键销售导入.cmd` 仅作人工备用入口，且必须显式传入销售文件、当前运行的库存成本源和截止日期。
5. 任务先精确剔除执行当天的订单明细，再依次完成刷刷仓过滤、店铺白名单过滤、成本匹配、分片导入 `http://localhost:3000/` 和导入后核验；晚于执行当天的异常未来日期仍须报错，不能静默剔除。
6. 文件非空明细行数必须与页面同语义计数精确相等；`>=` 不是完整性证明。记录原始文件 SHA-256、日期范围、精确计数合同、剔除数量、缺失成本数量、批次号、警告与最终核验结果。任何校验失败均停止，不得绕过或手工复用旧文件。

### 销售明细的固定规则

- 白名单、刷刷仓、成本匹配与重复原始文件拦截规则统一维护在 `config/sales-import-policy.json`。
- 销售流程的详细操作规范见：[一键销售导入操作说明](./一键销售导入操作说明.md)。
- 销售任务是每日固定顺序中的第 4 项；货品、分仓库存和库龄完成并核验成功后启动，销售完成后再进入组合装。

## 六、吉客云导入｜组合装

### 导出与校验

1. 进入“组合装查询”，右键数据行后选择“导出组合装及子件”。
2. 展开子菜单后重新确认“导出所有页”，只点击一次。
3. 等待并核对提示同时包含“导出列中存在图片列”“最多只能导出2000条”“确定导出”，只点击一次“确定”，再等待下载；不得因未确认而误判为下载超时。
4. 下载完成后，不得拆分、合并或改写原始文件。
5. 校验至少两张工作表：第一张为母件映射，第二张为母件—子件关系；核对 `货品编号`、`货品名称`、`母件编号`、`编号`、`名称`、`数量` 等必需列。
6. 子件数量必须为大于 0 的数值；母件—子件重复关系以导入器告警为准，不手工改写源表。

### 导入与核验

- 导入类型：`combos`；接口/页面来源：`/api/imports/erp`，`source=combos`。
- 组合装没有快照日期，也不报告刷刷仓剔除数量。
- 2000 条提示不作为完整性证明；runner 仍精确核对页面母件总数与第一张表行数、两张表的母件集合覆盖，并将唯一母件—子件关系数与最近成功组合批次比较。低于历史基线 95% 或没有基线时，在上传前停止。
- 详细规则见：[组合装及子件导出导入操作手册](./组合装及子件导出导入操作手册.md)。

## 七、统一交付记录

每个模块完成后按以下模板记录，并将原始文件、处理副本（如有）和导入结果保存在同一日期运行目录：

```text
聊天框或任务：吉客云导入｜<货品/分仓库存/库龄/组合装> / 一键销售导入任务
导出文件：<绝对路径>
文件证据：<修改时间>；<字节数>；SHA-256=<摘要>
文件校验：<工作表、真实数据行数、必需列、异常情况>
预处理：<不适用 / 刷刷仓剔除 n 行，非白名单店铺剔除 n 行，保留 n 行>
快照日期或销售日期：<YYYY-MM-DD / YYYY-MM-DD 至 YYYY-MM-DD / 不适用>
导入批次：<batch id>
导入结果：新增 <n>；更新 <n>；排除 <n>；警告 <n>；失败 <n>
导入后核验：<完成状态、日期范围、行数、刷刷仓、店铺白名单、组合装不适用等>
runner 审计：<outputs/jackyun-import-runs/RUN_ID/audit/module.json；失败时含 stage>
```

## 八、复用与维护原则

- 货品、分仓库存、库龄、组合装或销售明细任一导入规则变更时，同时更新本手册和对应的专用操作手册或销售配置。
- 新建聊天框时，直接复制本手册中对应模块的章节作为首条任务说明；不要复制历史文件路径、历史批次号或历史下载链接。
- 成功路径只保留清单、小型 JSON 审计、原始副本和必需处理文件；`.inspect.ndjson`、预览图和运行目录专用 `node_modules` 只属于专项排障，不得在每日任务中生成。
