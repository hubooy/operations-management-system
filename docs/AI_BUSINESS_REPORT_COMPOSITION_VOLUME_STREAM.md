# 经营报告推广明细有界分卷候选

`report_composition_volume_stream_v1.build_candidate` 是默认关闭的独立容量子能力。它接受前述 13 表同源预览的拥有方摘要、**同一报告/计划/封存推广来源**的完整行根清单和一次性行流；校验来源键属于该报告选中的推广来源、source revision、证据摘要与连续 `rowIndex`。入口和完成前都必须由拥有方提供当前版本复验回调。该回调只能由服务器实现，不可接收请求方自报的布尔值。

每卷最多 50,000 行及 16 MiB 规范原始行，最多 128 卷。每卷的同一 `Table` 流生成压缩离线 HTML 和 XLSX，随即回读 HTML 解压行 SHA、XLSX manifest 与物理行数。暂存 sink 的 `stage` 只接收当前卷临时文件；完整来源总行数、总摘要、前后复验均通过后才调用 `complete` 并返回 `staged_unpublished` 清单。任何异常都会调用 `abort` 清除所有暂存卷；没有下载入口、Agent 已读或正式发布。

合成 575,095 行（3 列、连续来源行号）实测通过：12 卷、没有截断，HTML 共 3,494,151 字节，XLSX 共 9,394,167 字节；包含 Table 行摘要独立复算在内的分卷生成与回读耗时 290.16 秒，`tracemalloc` 峰值 148.61 MiB。来源根错误、行号断裂、开始或完成时版本变化均拒绝。该测试证明的是**文件分卷与暂存协议容量**，不证明真实 575,095 行已由拥有方完整取回。

原封存 v2 Reader 仍限单来源 2,000 页/64 MiB；13 表基础投影仍限 50,000 行/32 MiB。要完成整份真实报告，还需 v4 完整来源分段、权威行根清单与该暂存 sink 的受保护实现、真实多 Agent 已读/引用、费用准入和受保护发布门禁。财报、B 端与市场仍只作明确的来源上下文；未知包含关系或历史 ERP 身份不得转换为增长数字。
