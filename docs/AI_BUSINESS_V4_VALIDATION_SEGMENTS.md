# v4 大来源可恢复候选证明（0036，未封存）

0036 仅新增不可变的验证尝试与验证分段。一个尝试固定当前无范围管理员的账号版本、父任务版本、完整目录摘要及签名密钥标识；只在**同一个 run 的所有来源都已完成**时建立。此阶段目录严格限京东同店推广 `current`、已请求的 `previous`/`yearAgo` 和恰好一个财务 `monthly_context`。旧 v4 物理账及 v1–v3 语义不变，父任务仍只能是 `collecting/manual`，数据库继续拒绝 `sealed`。

每段按该来源真实序号读取最多 16 页，核验规范原字节、页过滤器与自然月/日期、真实行与控制汇总、成功内部工具审计的完整请求参数 SHA、响应 SHA 及一对一不可变收据。前段末有限状态必须等于下一段起状态；最后一段与来源完成检查点双向对齐。段进度 ≤32,768 UTF-8 字节，以现有受保护 `DJANGO_INTERNAL_SECRET` 派生的独立 purpose HMAC 和显式 key-id 跨进程复验。密钥缺失、轮换未识别、撤权、来源或父版本变化均拒绝继续；旧尝试保留但不得作为新尝试的证明。

单来源最多 1,024 段、每尝试最多 4,096 段、每 run 最多 4 次尝试；每段固定最多 16 页/32 KiB 状态，因此每 run 的持久段状态理论上界为 512 MiB。单段另有 120 秒期限，超时不记成功；真实 575,095 行的页宽、耗时和磁盘峰值尚未验收。段本身由 AI 应用写入，数据库只核身份、序列、容量、账号及不可变性；HMAC 需要应用复验，不能把裸行或 bare `finished` 视为来源权威。

目前财务行存在绕开规范导入直接修改却不推进 `FinanceDataRevision` 的风险。跨时间分段无法由 HMAC 消除该写源竞态，所以所有候选回执均明确 `financeRevisionWriteFenceVerified=false`、`sourceAuthorityVerified=false`、`sealed=false`，并无 Agent、公开路由、renderer、模型或文件交付。待财务写入与修订的原子门禁独立通过，再设计新的封存迁移和重验路径。

现有纯 selector 的可选 `None` 表示本次**不选用已存在的基期来源**，不表示固定 run 物理目录缺源。v4 容量计划要求每个请求的日窗口都存在；请求同比但 run 无 `yearAgo` 来源的计划在创建前就拒绝。真实缺来源披露须另版计划合同，0036 不暗改。
