# 京东商智商品明细 SKU 日数据下载

## 适用范围

本手册用于从京东商智“商品 → 商品明细 → SKU”下载指定日期区间的日维度数据。

- 页面：<https://jdsz.jd.com/szweb/view/product/productDetail.html>
- 下载中心：<https://jdsz.jd.com/szweb/view/reports-center/download-center.html>
- 程序：[`tools/jdsz-product-detail-export.ts`](../tools/jdsz-product-detail-export.ts)
- 默认下载目录：`D:\谷歌浏览器`
- 文件特征：`701455_商品明细_离线_不包括对比时间_分天下载_起始日期_结束日期_*.xlsx`

这不是京东商家后台 `wares-jdm.jd.com` 的商品主数据 SKU 导出，两套流程不可混用。

## 2026-07-20 耗时复盘

本次从第一次重跑到文件最终落盘共用时约 **21 分 05 秒**：

| 口径 | 时间 | 说明 |
| --- | ---: | --- |
| 第一次重跑到最终完成 | 21 分 05 秒 | 包含现场诊断、程序修改、测试和多次安全中止，不代表日常耗时 |
| 正确区间任务开始到最终文件完成 | 4 分 34 秒 | 包含京东后台生成、诊断和恢复等待 |
| 最后一次成功程序运行 | 5.6 秒 | 复用最近一小时内已经生成的同区间任务，只点击一次下载 |

以后命中最近一小时本地已校验 SKU 文件，或命中当前区间 manifest 所指向的任务时，通常只需约 5–10 秒；新建任务时主要耗时来自京东后台生成。

## 本次遇到的坑

### 1. SKU 切换后页面会异步重绘

点击 `SKU` 后立即操作日期，会遇到日期控件被后续重绘清空。仅看到 SKU 文字不代表切换完成。

处理规则：

1. 使用 `role=tab` 定位 SKU。
2. 确认 `aria-selected=true`。
3. 等待数据区加载结束后再操作日期。

### 2. 日历“可见”不等于“可点击”

自定义日历打开时存在约 300 毫秒的过渡期。过渡期内点击日期，控件可能吞掉点击，但自动化框架不会报错。

处理规则：日历出现后等待短暂稳定期。单元格的 CSS 类名可能带动态哈希，按稳定片段识别 `cell-disabled`、`cell-now`、`cell-start`、`cell-end`、`cell-selected`；在派发任何日期点击前，`cell-disabled` 必须失败关闭并明确报“日期尚未开放”。`cell-now` 只是当天标记，绝不能当作起止端点。

### 3. 起止日期连续点击过快

如果起始日期尚未被登记就点击结束日期，结束日期会被当成单日区间。本次现场表现为 7 月 19 日单独选中，页面仍显示实时数据。

处理规则：

1. 点击起始日。
2. 必须看到带 `cell-start` 和 `cell-selected` 的起点状态，且该日未禁用。
3. 再点击结束日。
4. `cell-end + cell-selected` 只能用于诊断；京东可在 hover `secondDate` 时暂时添加它，不能据此继续或再次点击。
5. 最终必须读取页面回显，严格匹配 `当前：2026-07-01 ~ 07-19`；匹配后绝不重复点击结束日，未匹配则失败关闭。

日期状态未匹配时，禁止点击“下载数据”，保存失败截图后退出。

### 4. 下载弹窗是异步出现的

点击“下载数据”后立即查找“分天下载”，可能在弹窗尚未渲染时得到 0 个元素。

处理规则：等待唯一的商品明细下载弹窗出现，确认弹窗同时包含：

- `下载类型`
- `分天下载`
- `不包含对比时间`

逐项检查单选框已经选中后，才点击弹窗内唯一的“确定”。出现其他下载弹窗时立即停止。

### 4.1 单日区间只点一次会误入实时汇总

范围选择器在起止日期相同时仍需要两个端点动作。第一次点击同一天只建立起点，日历仍保持打开，页面顶部仍是“当前：YYYY-MM-DD HH:mm:ss”；第二次点击同一天后才建立终点并应用离线日期范围。

不要点击商品筛选区的“查询”来关闭日历。该按钮属于品类/渠道筛选，不是日期确认；这样继续点击“下载数据”会出现“下载设置”弹窗并生成“实时_汇总下载”文件。该弹窗通常提示最多下载 1000 行，必须在写入任务 manifest 和点击确定前拒绝。只有同时包含“下载类型”“分天下载”“不包含对比时间”的弹窗才可继续。

### 5. “生成中”任务也显示“下载”文字

京东下载中心在任务状态为“生成中”时仍显示下载操作文本。只按“下载”文字判断会提前点击不可用按钮。

处理规则：必须同时满足以下条件：

- 行文件名严格匹配店铺、下载类型和日期区间。
- 取同区间列表中的最新一行。
- 行状态包含 `已生成`。
- 下载按钮可用。

### 6. 超时不等于下载失败

浏览器下载事件或控制桥可能超时，但文件已经开始或完成落盘。收到超时就重复点击会产生重复文件。

处理规则：以文件系统为最终事实来源。

- 首次点击后轮询目标 `.xlsx`，文件稳定即成功。
- 发现匹配的 `.crdownload` 时继续等待，绝不再次点击。
- 初始等待 120 秒；存在临时文件时最多再等 300 秒。
- 只有完整文件和临时文件都不存在时，最多重试一次。

### 7. 重启程序可能重复创建后台任务

进程中断后直接回商品页重新导出，会产生多个同区间任务。

处理规则：启动时依次检查：

1. D 盘最近一小时的同区间完整文件；存在则直接复用。
2. 查找当前 SKU 区间的本地 manifest；存在则只按其中任务 ID 或“标题 + 创建时间”指纹接管。
3. 没有 manifest 时记录同名任务基线，创建一次新任务，并持久化唯一新增行指纹。

下载中心任务标题不包含 SKU/SPU 维度，因此禁止只凭“最近同区间任务”复用；那可能实际是 SPU 任务。

### 8. 下载中心尚未加载完成会污染 baseline

本次曾出现创建前读取到空 baseline、提交后下载中心同时存在多条同名历史任务的情况。此时不能把“同名最新行”当作本轮任务，也不能重新创建。

处理规则：

1. 创建前刷新下载中心，确认同区间历史行已经加载完毕，并连续取得两次相同任务快照后再保存 baseline；首帧空数组只是加载中的可能状态，不能作为 baseline。真正没有历史任务时第二次空快照即可继续，不会固定等待 15 秒。
2. 提交后若 manifest 仍是 `submitting`，只可用“完整标题 + 创建时间紧邻 manifest.createdAt”的唯一行恢复，并立即持久化该行指纹或任务 ID。
3. 标题、创建时间或任务 ID 不能唯一对应时，保留 manifest 并停止；禁止按 SKU/SPU、日期或“最新”猜测。

### 9. 本地开发服务的 multipart 默认只有 1 MiB

`/api/netshop/import` 的业务上限为 25 MiB，但 Vinext 的 Server Action 默认请求体上限为 1 MiB。它会在路由解析前返回纯文本 `413 Payload Too Large`，不会产生导入批次。

处理规则：

1. 在 `next.config.ts` 将 `experimental.serverActions.bodySizeLimit` 与接口上限对齐为 `25mb`，并重启本地开发服务。
2. 仅在确认 413 发生在路由前、没有批次写入后，重传同一份已校验工作簿一次；不要重新下载或拆分后改变日期覆盖。
3. 导入成功后仍需以批次和逐日明细回查为准。

## 稳定执行流程

```text
读取运营管理系统缺失日期
  → 检查 D 盘最近一小时同区间文件
  → 检查当前 SKU 区间的持久化任务 manifest
  → 必要时进入商品明细并选择 SKU
  → 等待 SKU 页面稳定
  → 选择起始日并验证 start 状态
  → 选择结束日并验证 end 状态
  → 验证页面最终日期回显
  → 验证商品明细下载弹窗
  → 选择分天下载、不包含对比时间
  → 创建任务一次
  → 等待最新任务“已生成”且按钮可用
  → 点击下载一次
  → 监控 xlsx / crdownload
  → 验证工作簿日期覆盖和结构
  → 默认通过正式 API 自动导入并回查批次契约（可用 --no-auto-import 只下载）
```

## 运行命令

在 `D:\运营管理系统` 执行：

```powershell
npm run jdsz:product-detail-export -- --start-date 2026-07-01 --end-date 2026-07-19
```

默认会以注册表的 `shopName` 调用 `/api/netshop/import`，提交 `source=jd_sku_daily`、对应的 `expectedDataset`（SKU 为 `sku_daily`，SPU 为 `spu_daily`）和目标日期。使用 `--no-auto-import` 可只下载；使用 `--base-url http://localhost:3000` 可覆盖系统地址。导入响应必须是 `imported` 或 `duplicate`，并且批次数据集、完成状态、零警告、行数和目标日期均匹配，否则脚本失败且不会声称完成。

需要保存日期门禁和弹窗现场截图时：

```powershell
npm run jdsz:product-detail-export -- --start-date 2026-07-01 --end-date 2026-07-19 --debug
```

默认日期是上海时区当月 1 日至昨天。运营管理系统只缺少部分日期时，必须显式传入准确起止日期，不要依赖默认范围。

## 成功判定

必须同时满足：

- SKU 标签处于选中状态。
- 页面日期回显与目标区间完全一致。
- 弹窗选择“分天下载”和“不包含对比时间”。
- 下载中心与 manifest 指纹一致的唯一任务状态为“已生成”。
- D 盘出现匹配的非空 `.xlsx`，且没有对应 `.crdownload`。
- 工作簿可打开，日期覆盖目标区间，无缺日。

## 浏览器显示策略

日常 n8n/runner 使用 `headless=new`，不会主动显示店铺 Chrome。登录失效、验证码、安全验证或店铺登录身份异常时，程序关闭无头实例、打开当前店铺的独立可见 Chrome 并以非零状态停止；manifest 和 runner 审计保持可恢复，禁止在可见窗口打开后自动重放任务确认或下载点击。

首次登录或主动排障使用 `--interactive-login`。如果运行前已有同一调试端口的人工可见 Chrome，程序会复用现有实例，因此该窗口仍然可见；这不属于新弹窗。正常定时任务前应关闭人工登录窗口。
