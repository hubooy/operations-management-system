# 大规模经营证据 v4 设计备忘（部分候选已实施）

2026-09-24 状态：下面保留原设计顺序。0035 独立物理账、京东推广本期内部单页采集与完成来源的只读重放候选已接入隔离分支；段证明、父封存、Agent 阅读证明、正式文件和生产采用仍未完成。内部采集审计现以完整参数摘要绑定长签名游标及响应页，重放可逐页重构和核对请求；这仍不等于京东上游独立数字签名或可用于报告的封存。

参考推广来源约 **575,095 行**。现有读取每页最多 100 行，因此单来源至少需要 `ceil(575095 / 100) = 5,751` 页；若当前期、等长前期和去年同期各有同等规模，仅三段就至少 **17,253 页**。页面可能因 128 KiB 字节上限提前结束，实际页数只能更多。以下均为隔离环境的设计目标，尚未读取真实来源或批准生产迁移。

## 现有硬门禁

- v3 日/财报采集每来源最多 **64 页**；日来源每页最多 100 行，故满页也只容纳 6,400 行。v3 父证据最多 **1,999 个事实页、64 MiB 减封存预留**；旧 PostgreSQL 表另有 `sequence<=2000`、父 `stored_bytes<=64 MiB` 的物理 CHECK。旧共享额度按 64 MiB 基数约为每人 256 MiB、全局 2 GiB。只修改 Python 常数无法安全扩容。
- 现有采集在每次追加前后重放已存来源，目录读取也汇总全部块。5,751 页时，仅两次逐次来源重放约需检查 `5751×5752≈3,308 万` 页次，未计目录扫描；大规模运行不能沿用此路径。
- v3 签名封存读取桥首次完整核验只接受 **64 页、8 MiB**，超过则 413，绝不返回部分目录；它没有 Agent 本人持久阅读回执。现有 v2 Agent 目录证明每 job 最多 40 次工具派发，不能直接扩成数万次原始页阅读。
- renderer 4/6/7 的多卷交付总上限 **1 GiB**，单 HTML/XLSX 文件 **256 MiB**、最多 100 卷、每块 512 KiB。现有派生表 SQLite spool 设 `max_page_count=131072`（按常见 4 KiB 页约 512 MiB），单表最多 100 万行。不能仅凭 575,095 行判断最终压缩文件是否能装入；三期合计及其他表还需实际字节预检。

## 分段实施顺序

1. **纯协议与独立物理账（拟 0035）**：定义新的 `business-evidence-v4` 容量档，另建 run/source/chunk/成功工具收据表，保留 v1–v3 的表、CHECK、守卫和已存字节。首个隔离验收档建议单来源 **16,384 页/2 GiB**、整 run **65,536 页/8 GiB**，另立每人 16 GiB、全局 64 GiB 的试验额度和磁盘预留；超过任一限制明确失败，不封存、不截断。2 GiB/来源覆盖参考行数的条件是平均每行规范 JSON 不超过约 **3.73 KiB** 且平均每页至少 **35.1 行**，并非无条件保证。先用获准的只读真实页宽统计验证，再决定生产档。新块以 `(run_id,source_key,sequence)` 唯一索引顺序读/点读，计数用 bigint；每次只验证当前 checkpoint、末块、来源修订与签名工具回执，并在同一事务对来源和父计数 CAS，禁止每页全历史重放。各来源/比较窗口独立身份，不合并重叠销售。
2. **可恢复的一次完整核验（拟 0036）**：来源完成后由独立有界后台 verifier 顺序流式检查每块原始 SHA、类型化页/行链、成功工具审计、精确查询、页序及缺日/缺月语义。按例如 64 页/不超过 8 MiB 形成不可变段证明；崩溃续扫须核对前缀链、来源版本与完整修订。全部段覆盖后生成绑定 run/source 版本、字节/行/页数和证明链的不可变 attestation，再做父任务封存 CAS。普通 AI writer 提供的 DTO 或数据库 `sealed` 字符串不能充当证明；验证签名/角色应与一般写入能力隔离。跨进程读句柄只在核对当前账号、封存、attestation 和签名后签发，短期 HMAC 绑定来源用途；点读仅核选定块和收据，避免每会话重扫数 GiB。正式 AI reader 不应因此获得全量工具审计表权限。
3. **Agent 阅读证明与类型化结果（拟 0037）**：新建 v4 job/角色绑定的目录与分析表阅读回执，核每角色自己的请求、顺序、来源分区和结果摘要，不能借用兄弟 Agent 或 v2 的 40 次派发规则。对几十万行由计算服务流式聚合并保留可追溯行/范围引用，让五 Agent 读取分页的店铺、品类、SPU、SKU、关键词、同比/环比和 B 端类型化表；原始明细由文件流水交付，不把几十万行塞进模型上下文。财报继续仅为自然月背景，不按日摊销到 SKU 或与 ERP/B 端/广告归因金额相加。独立复核和人工审核保持必需。
4. **版本化文件容量（必要时拟 renderer 8）**：在旧 renderer 1–7 不变的前提下，先按实际行数、列数、流字节与临时磁盘估算完整 XLSX/HTML，再决定是否建立更大容量档。按表/日期/店铺分片输出完整明细、稳定清单与 SHA；XLSX 遵守单 sheet 行上限，HTML 使用分页索引而非一次性巨量 DOM。任何单卷、总字节或临时空间超额均保持未发布，不能把半成品标成 ready。

## 权威来源、续读和验收

现有 sales、netshop、market 拥有方 continuation **已经**能在原签名 cursor 真正过期、且 `sourceRef/revision/lastId` 与当前权限仍一致时安全验签续读；AI 侧不自行解码或续签。v4 可复用该语义，但还需在隔离环境验证超过一小时、跨进程及长暂停恢复。来源修订、账号范围或完成批次变化时必须停止旧代并重新规划，不能混页。

纯合成验收至少覆盖 575,095 行及三窗口、16,384/65,536 页与 2/8 GiB 边界、行宽导致提前换页、缺页/重复/乱序、审计缺失、修订切换、撤权、并发 CAS、段扫描崩溃续接和 HMAC 跨进程失效。以 1,000 与 6,000 页对比追加查询量，证明近似常数级每页工作；完整核验须只扫描每块一次、内存有界。拟 0034→0035/0036 的每个迁移都要在隔离 PostgreSQL 中证明旧 **67 张 AI 表**、renderer 1–7 字节及原 ACL 不变、前后备份可独立恢复、空表可逆迁移、有事实或 attestation 时拒绝丢失性回退。生产前还需获准的只读真实行宽/页数、磁盘峰值、备份和恢复耗时测量；本备忘不授权采集、迁移或部署。
