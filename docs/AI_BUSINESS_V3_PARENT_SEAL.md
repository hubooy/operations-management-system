# v3 混合来源内部封存（0033）

只有内部 `business_v3_seal.finish` 能尝试封存。它先逐一重读拥有方的财报/日来源完整页链、当前管理员身份及 0032 不可变工具收据，再锁定父任务和全部来源做版本、计数与收据链 CAS。0033 数据库门禁只开放 `collecting/manual → sealed/manual` 这一跳；所有来源须完成，每个事实页有唯一成功工具收据，父/来源/块的数量与字节吻合。原 v1/v2 迁移守卫及报告、renderer 字节保持不变。

封存记录保留每个来源的目录键、域、查询与检查点摘要、完整来源修订、页/行/字节、收据链。日来源用观察行日期位图和缺行日计数披露窗口；`0` 表示当天无已观察行，绝不补成零销售或零投放。当前主数据不作为逐日事实。财报保留自然月发布位图、缺月、真实批次发布摘要和详细覆盖摘要，不做按日摊销或 SKU 利润推断。不同来源的读取时间不一致，封存不宣称跨来源原子快照。

已封存证据只能通过内部 `business_v3_seal.verify` 重新核验完整目录、拥有方页链、全部收据和封存摘要；数据库 `status=sealed` 本身不构成权威证明。当前仍设 `sourceAuthorityVerified=false`、`persistentEvidenceVerified=false`、`reportGenerationSupported=false`。公开旧证据列表/详情/完成接口不显示或接受 v3，报告、Agent、文件及定时执行继续关闭。

隔离验证使用新旧 PostgreSQL 门禁用例与独立 `0032→0033` 备份/恢复演练；没有正式数据读取、生产迁移或部署。
