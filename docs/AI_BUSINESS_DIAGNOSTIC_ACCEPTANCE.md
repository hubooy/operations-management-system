状态：**验收设计，尚未执行本组六卡的完整模型验收**。本文不记录生产数据，不宣称已调用模型、建议有效或原五阶段任何阶段完成。所有“合成甲店/乙店”、商品、渠道与金额均为人为构造的小样；下面的期望值是人工复算标准，不是实测通过记录。

## 使用方式与共同门禁

先将小样构造成真实 owning-reader 接受的合成事实，采集、封存后生成分析表；不能把本页数字直接塞进模型回复充当真实工具证据。金额均为**整数分**，百分比仅用于解释；明细保留 `sourceKey/sourceRef/sourceRevision/evidenceDigest`、精确平台/店铺/渠道、日期窗口和分析行身份。每卡各运行“完整来源”和“关键来源缺失”两版，不把 `null`、缺行或缺日补零。小样的聚合数须分解到相应期间每日，使声明的日期覆盖与实际事实一致。

默认本期为 2026-08-01 至 2026-08-07，环比为 2026-07-25 至 2026-07-31，同比为 2025-08-01 至 2025-08-07；第 4 卡用 2026-08-07 单日及前一日，第 5 卡专测闰日，第 6 卡基期为 2026-08-01 至 2026-08-30，分别覆盖默认区间。甲、乙均为京东合成店，使用独立来源键；跨平台变体只使用该平台实际支持的数据集。所有卡共同要求：

- 事实、假设、缺口、动作分开表达。`factsVerified` 只代表结构化数值引用核验，不能证明文字因果或方案有效。
- 每个动作包含现有 `object/change/prerequisites/successMetric/observationDays/rollback/priority/ownerRole/budgetImpact`，对象必须落到精确店铺及渠道/商品/关键词或明确的数据核查范围。下面阈值均是**本验收小样的人工规则**，不是生产默认规则。
- 至少两名专业分析 Agent 的结论应在整合稿中对账，独立复核应指出口径冲突；不能靠多 Agent 数量证明分析正确。每个 Agent 的读取证明单独检查。
- 读完目录、读取一页分析表、下载全量文件是不同覆盖。没有完整扫描与可信覆盖证明，不准声称“全部商品均无异常”。纯筛查模块返回 `prepared_unpublished`；第41–51批新增的持久发布、各角色包和真实回执必须共同核验，不能只凭纯计算返回值认定已发布或模型已阅读。
- HTML、XLSX、结构化引用采用同一封存事实与固定参数。数字、空值、缺失状态、单位、来源和期间须一致；人工复算列不是凭空新增的源字段，也不能伪造为现有工具指标。

## 卡 1：甲店推广费上升、归因金额下降，乙店却改善

**问题：** 优先查哪些店铺和关键词，哪些变化只是算术分解，哪些还缺解释证据？

**合成输入：** 同一 `jd_promotion/ad` 口径，以下每行是一店一关键词的期间合计；实际夹具拆为每日行。字段为 `spendCents/clicks/reportedOrderLines/reportedGmvCents`，关键词放在实际 `dimensions.keyword`。本例各词的 `impressions=clicks×10`。

| 店铺 / 关键词 | 环比花费 / 点击 / 订单行 / 归因金额 | 本期花费 / 点击 / 订单行 / 归因金额 |
| --- | --- | --- |
| 合成甲店 / K1 | 60000 / 600 / 30 / 300000 | 90000 / 600 / 24 / 240000 |
| 合成甲店 / K2 | 40000 / 400 / 20 / 200000 | 50000 / 500 / 16 / 160000 |
| 合成乙店 / K1 | 50000 / 500 / 20 / 200000 | 50000 / 500 / 25 / 250000 |

**应识别及手算：** 甲店花费 100000→140000（+40%），归因金额 500000→400000（−20%），ROAS 5→20/7≈2.857143。K1、K2 分别贡献花费增量 30000、10000，归因金额减量 60000、40000。甲店 CPC 为 100→140000/1100≈127.272727 分，订单行转化率为 5%→40/1100≈3.636364%，下降约 1.363636 个百分点；这些比率须先合计分子分母再算。乙店 ROAS 4→5，不能被甲店问题覆盖，也不能把跨店同名 K1 合并成同一执行对象。

**禁止结论：** 不得把归因金额称为净销售、增量收益或利润；不得把 CPC 上升认定为竞争加剧的已证实原因。归因窗口默认未知，日期齐全仍不证明两期归因成熟度一致。关键词表、SKU 表和店铺表是同批事实的不同聚合，不能再次相加；商品日访客也不能变成店铺去重 UV。

**最低动作：** 高优先级由甲店投放运营核对 K1 的归因窗口、词匹配和投放变更；在可比前提确认后，提出人工小步限额试验（例如 K1 上限下调 10%，暂不把差额自动拨给乙店）。观察 7 天或达到明确复盘花费先到者，以 CPC、订单行转化率、ROAS 并列验收；若归因未成熟、样本不足则停止判优，若成熟且达到样本门槛后 ROAS 比试验前可比值再下降 10%，进入人工回退评估。明确预算影响、责任角色，不直接执行投放。

**缺失版 / 真实模型项：** 去掉甲店一日或把 K1 归因金额设 `null`，要求改为缺口，不能沿用 −20%结论。真实模型须主动优先定位 K1、解释乙店差异、提出可证伪假设而非复述表格；是否会在全表后页发现 K1，须另用全表读取或可信筛查证据验证。

## 卡 2：退款侵蚀 ERP 毛利，不能把账面差额写成退款因果证明

**问题：** 甲店精确 ERP 渠道 C1 的 SKU-A 毛利为何下降，如何区分退款、成本和费用？

**合成输入：** 来源 `erp_sales`，日期为发货业务日 `business_date`。正向行 `allocated_amount_cents=1000000`；环比退款行 −100000、本期退款行 −300000。源成本期间合计分别 600000、550000，源费用分别 50000、60000。`reportedGrossProfitCents` 故意取环比 310000、本期 170000，与重算毛利不同。乙店 C1 的同名 SKU-A 净销售/成本均保持 500000/350000，单独保留。映射时使用明确同平台同店当前主数据；另设一行商家编码歧义的未分配销售，不能挤入 SKU-A。

| 字段 | 甲店环比 | 甲店本期 |
| --- | ---: | ---: |
| positiveSalesCents | 1000000 | 1000000 |
| refundCents（负向金额绝对值） | 100000 | 300000 |
| netSalesCents | 900000 | 700000 |
| costCents | 600000 | 550000 |
| grossProfitCents | 300000 | 150000 |
| feeCents | 50000 | 60000 |

**应识别及手算：** 净销售=正向金额−退款绝对值；毛利=净销售−源成本。毛利变动 −150000=净销售变动 −200000−成本变动（−50000）。退款额/同期正向金额为 10%→30%，仅是两类同期金额之比，不是已关联原订单的退款率；它不是当前分析协议新增字段。费用上升 10000，但 `grossProfitCents` 本身未扣费用。人工派生“重算毛利减源费用”可核为 250000→90000，但不得冒充源净利润，结构化引用仍只引用已有毛利和费用字段。

**禁止结论：** 源报告毛利与重算毛利差 10000/20000 应列对账项，不任挑一种掩盖差异。不知道退款原销售期、订单及成本回冲规则，不能说“本期售出商品退款率 30%”或“退款造成全部利润下降”。当前主数据关联不能证明历史 SKU 归属；不得将 SKU 毛利按关键词花费比例分摊成关键词利润。

**最低动作：** 高优先级由销售核算与售后负责人对甲店 C1/SKU-A 及歧义桶核查退款期间、成本冲回和源毛利差异；7 天核对退款额、成本额、毛利差额及未分配金额，预算影响为“暂不据此调整投放”。缺少可追溯来源时保留缺口；口径修正后须重新封存/复算并撤销旧结论，不能悄改旧报告。中期 30 天观察可比退款金额趋势，不能承诺纠正后毛利必然恢复。

**缺失版 / 真实模型项：** 缺 ERP 来源、映射歧义或某期缺日应分别披露；不得把未分配金额丢掉让 SKU 合计看似对平。现有 `SalesOrderLine.cost_amount_cents` 为非空整数，不能向真实数据库夹具硬塞 `null`，假装已具备“源成本缺失”识别；来源未提供成本是否曾被导入过程写成零，需要单独核对来源及导入合同，非空字段不证明实际成本可靠。真实模型应把“账面桥接已成立”与“退款业务原因待核”分开，主动要求必要的售后证据而不索取无关客户信息。

## 卡 3：B 端、平台商品销售与 ERP 销售可能重叠

**问题：** B 端占比是否提高，甲乙店应如何分配关注，能否计算“零售+B 端总销售”？

**合成输入：** 同期甲店 `jd_sku_daily/sku_daily` 的 SKU-X `paymentCents=1000000`、`productDayVisitors=100`；`jd_b2b/b2b` SKU-X `paymentCents=400000`；精确 ERP 渠道 C1 的 `netSalesCents=850000`。甲店环比分别为 800000、200000、700000。乙店同 SKU 编号的本期三数为 600000、100000、500000。所有平台商品数据 `reportedOrders/paymentQuantity` 保持独立原字段，缺失变体将 B 端 `reportedOrders` 设为 `null`。

**应识别及手算：** 分来源并排展示：甲店平台商品金额 +25%，B 端金额 +100%，ERP 净销售约 +21.428571%；乙店单独呈现。可人工核算 B 端金额/平台商品金额从 25%→40%，但必须标为“跨来源金额比”，在包含关系、期间及退款口径获证实前不能称业务占比。甲店平台金额+B 端金额=1400000 的算术正确，不代表真实总销售；1000000−400000=600000 也不能被认定为零售销售。商品日访客 100 仅是累计量，不能计算真实跨日去重 UV。

**禁止结论：** 不凭“商用商品”判断 B 端成交；不把 ERP、SKU、SPU、B 端金额求和；不把同名 SKU 的甲乙店身份折叠；B 端订单为空不能用 GMV/客单价倒推订单。`jd_b2b` 的存在也不证明与平台商品销售互斥或包含。

**最低动作：** 高优先级由渠道运营为甲店分别核对 B 端与平台/ERP 的口径说明，7 天内完成精确来源、期间和包含关系对账；指标为可解释差额及仍未确定的重叠范围，预算影响为“未核清前不按所谓 B 端占比重分预算”。14 天后只对获验证的独立口径做结构观察；发现包含关系不成立即撤销占比和零售残差建议。乙店不能因为同 SKU 就被套用甲店方案。

**缺失版 / 真实模型项：** 移除 `b2b` 来源时应说“缺 B 端事实”，不把缺源解释为零 B 端。真实模型必须抵抗用户问题中的错误前提“请直接加起来”，主动解释可比性并保留可执行的对账步骤。

## 卡 4：市场 TOP 样本上涨伴随换榜，不能推全市场增长

**问题：** 同一精确类目、范围、SKU 榜单维度和价格筛选下，市场机会是否变好？

**合成输入：** `market_daily_top`，两个单日作为本期和环比，`shopName=""`。环比商品 M1/M2 的 `sampleGmvLowerCents/sampleGmvUpperCents` 分别为 60000/120000、40000/80000；本期 M1/M3 分别为 90000/180000、60000/120000。`sample.rank` 每日为 1/2，保留实际样本成员和源区间。另构造一条覆盖同日的周榜记录，作为应排除项，不参与日榜合计。

**应识别及手算：** 逐日样本合计区间为 [100000,200000]→[150000,300000]。现有样本区间变化下界=150000/200000−1=−25%，上界=300000/100000−1=200%，状态为 `observed_sample_interval`。样本成员从 {M1,M2} 变成 {M1,M3}，有一进一出；M2 未入榜不等于零销量。周/月重叠记录须列排除信息，不能与日榜叠加。

**禁止结论：** 不把中点 150000→225000 的 +50% 当精确成交增长；不说全行业上涨 50% 或我店份额下降。市场来源不属于甲店或乙店，不能凭标题/品牌把榜单商品自动归入自家 SPU。即使固定样本商品 M1 的区间变化，也不证明全市场或稳定竞争强度变化。

**最低动作：** 市场运营以“该精确条件下 M1/M3”为观察对象，连续 14 天核查在榜天数、排名、源价格区间及榜单口径；在相同筛选且逐日数据齐全后再提出小范围选品评估，预算影响暂为研究工时。榜单条件改变或日期缺失时停止趋势结论、回到重新收集可比样本；不能按一次入榜立即扩大备货/推广。

**缺失版 / 真实模型项：** 去掉一个金额上界应使相应区间比较不可用，不补中点；改变 `scope` 或 `priceBandFilter` 后不得继续直接同口径比较。真实模型须把样本构成变化放进主结论，并将机会表述为待验证假设。

**现有能力边界：** 本卡的两日成员集合差可人工复核原始样本；当前没有独立“入榜/出榜/连续在榜天数”派生表。两行小样被模型正确解释，不等于真实规模下全量榜单变化能力已实现；原始 `sample.rank` 可下载也不等于排名变化已计算。

## 卡 5：同比缺日、负基期与闰日不能统一输出增长率

**问题：** 两店去年同期表现是否改善，缺日及负数应该怎样展示？

**合成输入与复算：** 固定用户原区间为 2024-02-28 至 2024-03-01。现有期间规则得到本期 3 天、环比 2024-02-25 至 2024-02-27 共 3 天、同比 2023-02-28 至 2023-03-01 共 2 天；闰日按去年月份末日钳制。

| 子例 | 现有字段和小样 | 期望 |
| --- | --- | --- |
| 甲店完整同比 | `paymentCents` 本期每日 10000，去年两日各 10000 | 期间总额 30000 对 20000，差 10000、+50%；同时标 3 天对 2 天。人工等天日均均为 10000，并不是日均需求增长 50% |
| 甲店同比缺日 | 去年仅有 02-28 的 10000，缺 03-01 | 覆盖 `missing_dates`；比较 `unavailable`，差额/增长率为空，不补缺日零值或除以已见天数掩盖缺口 |
| 乙店负基期 | 同口径 ERP `netSalesCents` 基期 −10000、本期 5000，双方日期齐全 | 差额 +15000，状态 `negative_baseline`，增长率为空；描述“由负转正”，不能写 −150%增长 |
| 乙店零基期 | 同口径值 0→5000，双方有该对象实际行 | 差额 +5000，`zero_baseline`，增长率为空；无穷大不是有效增长率 |
| 乙店缺基期对象 | 仅有本期 SKU 行，基期无该对象行 | 不能当成上一行的零基期；比较 `unavailable`，说明缺基期对象 |

**禁止结论：** `dates_present` 只证明请求日期上有记录，不证明所有 SKU/订单齐全或业务口径已审定。总额比较与等天数归一化须分栏说明，不能暗改原查询日期以取得漂亮同比。日均为本卡人工核查项；不得假称原分析表已输出该字段。两店任一缺口不能用另一店数据补齐。

**最低动作：** 数据运营优先核对缺失的精确来源和 2023-03-01，3 天内以期望日清单和复取后的控制合计验收，预算影响为零。业务运营对乙店由负转正做退款/冲回核查，7 天观察净销售和正负金额拆分。新来源修正后重新封存并引用新版本；未补齐之前撤回增长排序和基于该排序的预算转移建议。

**真实模型项：** 在一份摘要里同时保留五种状态，尤其不能把“负基期无增长率”误写成“没有改善”，也不能因日期齐全就忽略闰年长度差异。需人工检查正文与 HTML/XLSX 的空值、日期和数值一致。

## 卡 6：预算是假设情景，必须连接有限、可回退的行动计划

**问题：** 给选定的两个推广对象制定 15 天预算，解释压力情景和何时复盘，不能承诺增量利润。

**合成输入：** 使用现有 [预算纯算法](../backend/business_analysis/budget.py)字段。两个对象来自相同 `jd_promotion` 报告口径的两个精确店铺，各绑定合法 `sourceKey/dimension/rowIndex/rowId`，不混入 ERP 毛利或映射结果。各自完整 30 天基期：`spendCents=3000, clicks=300, reportedOrderLines=30, reportedGmvCents=15000`。计划 `totalBudgetCents=10000, reserveCents=1000, horizonDays=15, observationDays=7, reviewAfterSpendBps=2000, minimumClicks=30, minimumOrderLines=3`。两对象权重 2:1，最低预算均 0、最高均 10000，`minimumRoasBps=40000`，责任角色为投放运营。

| 情景 | cpcFactorBps / orderRateFactorBps / orderValueFactorBps / contributionMarginBps |
| --- | --- |
| 效率不变 | 10000 / 10000 / 10000 / 2000 |
| 成本上升且订单效率下降 | 12000 / 8000 / 9000 / 2000 |

**应识别及手算：** 可分配 9000，按权重得到 6000/3000，预留 1000、未分配 0；各对象等 15 天基期花费为 1500，因此加预算分别为 4500/1500。效率不变时 CPC=10 分、订单行率=10%、归因客单=500 分；预测点击 600/300、订单行 60/30、归因金额 30000/15000，合计 45000。假设贡献率 20%后减广告花费，合计 45000×20%−9000=0；盈亏平衡 ROAS=5，不等于计划中用于复盘的最低 ROAS=4。

压力情景金额乘数为 0.8×0.9/1.2=0.6，合计归因金额 27000，假设广告后贡献为 27000×20%−9000=−3600。两对象复盘花费为 1200/600。算法按精确分数中间运算、规定舍入输出，Excel 不应提前逐步舍入造成漂移。

**禁止结论：** “预测归因金额”“假设广告后贡献”不是新收入、增量效果或真实利润；权重 2:1 是用户输入，不是求得的最优预算。跨京东/天猫报告口径混用时，必须分口径展示，不能给合并归因金额保证；贡献率缺省应保持空值，不能取 ERP 毛利率自动补齐。某对象不可测算时，不能把其预测填零或把已知部分冒充全计划总额。

**最低动作：** 投放运营分别对两个固定对象执行人工评估，7 天或达到复盘花费先到者检查覆盖、归因成熟度、点击/订单行门槛、ROAS；满足可比及样本前提后低于最低 ROAS=4 才进入人工暂停/回退评估，缺数据先核查。15 天结束对照实际与两情景，不根据假设收益自动追加预算；30 天中期只提出再次复核后续投方向。每个动作明确优先级、上限、1000 预留的用途限制及原配置回退条件。

**拒绝/缺失变体：** 最低预算之和大于 9000 须完整拒绝；一个对象缺 `reportedGmvCents`、基期花费为 0 或缺日时为不可测算；低样本保留 `low_sample_scenario`，不得宣称达到统计置信。计划改动后旧预览和旧摘要失效，须重新免费试算并显式创建，不能替换已固定报告参数。

**真实模型项：** 能否发现“ROAS=4 仍低于假设保本 5”的决策冲突，说明需由用户明确是贡献保本还是带上限的测试目标，而不是悄改输入；能否提出近期/中期有先后依赖的计划，并在建议中准确保持两情景、对象绑定与人工回退边界。

## 如何记录一次真正的验收

六卡不是原参考报告的全部功能清单。计划/单元及匹配方式、关键词×商品联合诊断、市场精确价格带分组与榜单变化、市场商品到自家 SPU 的明确关联、月度财报净利润仍须各自定义字段与验收；本组六卡不能替这些项目销项。当前 `results.VIEWS` 只有店铺、品类、SPU、SKU、关键词、搜索词、逐日、品牌八维；底层聚合器支持部分多字段分组，不等于工具、引用和文件已提供这些联合视图。财报尚未进入本经营证据协议的 `netshop/sales/market` 来源集合，不能用 ERP 毛利代替。完整对应关系另见 [参考质量对照](AI_BUSINESS_REFERENCE_QUALITY.md)。

每张卡独立记录候选 commit、夹具版本及摘要、封存版本、固定计划/映射/预算摘要、完整源/表清单、各 Agent 实际读取范围、模型名称与配置、调用次数/费用、原始输出和人工修订。合成 provider 替身只能验协议及工程链路，不能填“真实模型通过”；未运行填“未运行”。固定问题至少重复两次真实调用并保留失败样本，避免挑选单次最好输出。

人工复核逐卡按证据准确性、缺口披露、因果边界、动作可执行性、跨 Agent 一致性五项各 0—2 分记录；每项都须写对应事实或原句。暂定放行要求为每卡至少 9/10、无单项 0，且数值/身份/期间引用全部正确。错店、漏报关键缺口、跨源重复加总、市场区间伪精确、负/零基期伪增长、预算假设冒充事实、未读全量却声称全面诊断，任一出现即该卡不通过，不能以平均分抵消。

顺序为：确定性表与人工复算 → 合成完整链路及双文件一致 → 实际模型多 Agent 诊断与独立复核 → 在另行明确的真实来源和成本范围内做业务验收。本文六卡只规定质量门禁；正式采用、真实投放效果和用户参考报告的视觉/业务深度对照仍分别记录，不能由本文件推定完成。
