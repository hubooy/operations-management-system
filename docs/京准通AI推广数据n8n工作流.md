# 京准通 AI 推广数据 n8n 工作流

## 目标与入口

该流程固定处理京东店铺注册项 `jd-yiyong-director`：

- 业务店铺：志高商用设备旗舰店
- 京准通页面账号标签：志高亿用-总监
- Chromium profile：Default
- 报表入口：`https://jzt.jd.com/custom-report/#/list`，在当前账号列表内按名称唯一选择“AI推广数据自动下载”；禁止跨店复用报表 ID
- n8n 模板：`automation/n8n/jd-promotion-daily.workflow.json`

仓库模板默认保持 `active=false`；实际发布状态以本机 n8n 为准。当前手动入口范围为 `2026-08-20`；定时入口在上海时区每天 10:40 运行。店铺注册表将推广起始日固定为 `2026-07-01`，定时入口每次扫描该日起至上海昨天的运营系统实际覆盖；手动入口扫描填写范围。两种入口都只下载缺失日。

定时和手动入口都必须先调用 `POST http://127.0.0.1:5791/coordination/claim`，以 `workflow key=jd-promotion + n8n execution ID` 原子领取共享 helper。未获授权时每 5 分钟等待，累计 72 次、约 6 小时后失败关闭；领取成功前不得进入 A、启动 Chromium、创建京东任务或调用导入接口。

## A → B → C

### A：固化日期、店铺和执行所有者

A 调用 `POST http://127.0.0.1:5791/jd-promotion/plan`，并携带同一个 n8n execution ID。它先使用平台“京东”与当前店铺复合键读取运营系统推广日期覆盖；只有确认存在缺口后才校验受控店铺注册项和 Default profile。缺口可以跨月，但每轮只按日期升序固化最早 31 个缺失日，并返回扫描范围、最终执行范围和延期数量。覆盖响应范围不一致、包含非法/区间外日期、空 execution ID、跨执行接管、并发或乱序调用均失败关闭。若没有缺口，计划直接进入可复核状态，不检查 Profile、不启动 Chromium。

### B：生成、下载、校验、导入和首次回查

B 调用 `/jd-promotion/run`，严格按 A 中的缺失日期升序逐日执行；每个子任务的起止日期必须为同一天：

1. 打开京准通自定义报表并核验页面显示“志高亿用-总监”。
2. 选择“AI推广数据自动下载”，将自定义日期精确读回为当前单日。
3. 先读取下载中心 baseline；若已有唯一精确范围任务则接管，否则持久化 `submitting` 恢复清单后只点击一次“开始生成”。
4. 下载中心只能接管报表名前缀、起止日期、创建时间和 baseline 共同锁定的唯一任务。任务状态从生成中变为已生成不会改变任务身份。
5. 下载 CSV 后验证 UTF-8、非空、必需表头、连续日期覆盖、账户集合、行数、关键指标和 SHA-256。
6. 以 `source=jd_promotion`、`dataset=ad`、`platform=京东`、精确店铺和单日范围调用运营系统导入接口。
7. 只有返回 `imported` 或 `duplicate`、批次为 `completed`、零告警、行数/日期/店铺/原文件哈希一致且落库回查成功，B 才结束。

京准通若在报表列表显示唯一的“自定义报表已迁移至「报表 - 报表工具」”引导，且明确写明当前入口仍可正常使用，B 可以在核对店铺账号后只点击该引导中唯一的“知道了”，并确认弹窗消失；绝不点击“立即前往”。若引导延迟挂载且精确遮挡了报表入口，只允许重新核对同一引导并补一次可逆的报表入口点击。其他弹窗、多实例、控件歧义或第二次失败均停止，不能绕过遮挡强制点击，也不能重放“开始生成”。

### C：独立复验

C 调用 `/jd-promotion/verify`，逐个重新读取已保存 CSV，重算 SHA-256、行数、日期和账户集合，再按 batch ID 只读查询精确批次；随后再次读取本轮计划日覆盖。文件、批次或覆盖任一不一致，整次 n8n execution 失败。无缺口时 C 只确认扫描范围已经完整覆盖，不执行下载或导入。

## 手工运行与恢复

独立命令行运行：

```powershell
npm run jd:promotion -- --start-date 2026-08-13 --end-date 2026-08-14 --run-id jd-promotion-20260813-14
```

登录失效、验证码、安全验证、生成点击结果未决或下载中心出现多个候选时，执行器保留恢复清单并停止。不得删除清单后重建任务；应先核对当前账号和下载中心，再从 n8n 的 A 节点启动新的完整 execution。账号、密码、Cookie、Token、Session 和 profile 路径都不写入 n8n 工作流。
