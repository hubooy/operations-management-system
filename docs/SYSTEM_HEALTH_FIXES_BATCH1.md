## 1. 客服保存失败提示

原先行内保存失败设置公共错误后，列表回读立即清空同一个错误状态。现在保存错误独立保存，成功回读只清除读取错误；只有明确成功的后续行内保存清除保存错误。回读也失败时，两条错误同时展示在原有提示位置。

失败时先恢复原行，再读取权威数据；写响应缺失版本、503、409、断网都不自动重发 PATCH。409 继续保留详情草稿。保存期间同步拦截重复操作并禁用其他行内标注控件，避免跨行写入并发时互相清除错误。读取期间切换日期后，保存回调刷新当前范围；旧范围的成功回执不会直接覆盖新列表。

真实组件浏览器测试覆盖：503、409、网络失败、200 缺版本、保存与回读双失败、普通刷新、延迟写失败/成功时切换日期、成功后清除错误。网络响应全部合成，没有真实客户和后端写入。详情编辑器原有独立保存提示保留。

## 3. 市场统计卡片

旧实现混用身份、标注行和月快照数量，且价格补识别/阻塞写死为零。新实现对六张已有表进行一次只读 SQL 聚合，在同一语句快照中返回原八个字段。中间快照仅投影计算所需列，没有逐身份查询或把完整结果传回 Python。

- 身份为 `category + scope + ranking_dimension + sku_code`；跨月重复只计一次。
- 待确认价格按身份计数；没有快照的身份仍待处理，不误报完成。
- 当前图片采用 ready 图片缓存非空哈希优先、快照哈希回退，与当前标注图片校验的优先级一致。
- 已有结果必须精确匹配身份、月份和当前图片，且含实际 AI 输出。待复核、批准、拒绝和入库结果均不被当成待重新推理，拒绝结果不会引发自动重跑。
- 同图已确认标准售价对应直接复用；有仍属有效枚举的已入库分类历史对应价格补识别；其余有效 SKU 为完整识别。
- 非 SKU、缺图、缺有效 Prompt/枚举或未被有效替代的三次失败封顶归入阻塞。跨月份存在多个可执行路径时取完整识别、价格识别、同图复用的最高成本；全部路径均不可执行才计阻塞。
- 四类合计等于待标注身份；已完成数是总身份减待标注身份，不代表本日模型调用数。统计用于估算待处理工作，不替代具体任务的模型、权限、认领和复核门禁；本批没有修改任务创建、领取、发送或入库流程。

新增 PostgreSQL 测试直接调用正式 Django 实现，不再只依赖历史 D1 测试。覆盖空库、缺快照、跨月混合路径、同编码跨类目/范围/SKU-SPU、旧图、缓存新图、过期 Prompt、失败封顶及精确替代、拒绝结果、孤立快照和固定单条 SQL。签名 API 测试保持八字段、`no-store`、无签名 401 和受限范围 403。
