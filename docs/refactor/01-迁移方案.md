# TERUISI 运营管理系统前端重构：阶段二迁移方案

> 方案：A（零新增 UI 依赖）
>
> 目标：参考 Ant Design Menu / ProComponents 的信息架构、受控状态、插槽边界和无障碍行为，使用当前 React 19、Next.js 16/Vinext、TypeScript 与 CSS 自主实现；不安装 `antd`、`@ant-design/pro-components` 或新的路由/状态/UI 库。
>
> 本文只定义迁移方案。本阶段不修改前端代码、不改变业务行为、不部署。

## 1. 已确定的架构决策

1. 保留现有 12 个模块及“经营管理 / 系统管理”顺序，不引入不存在的后端 `me.modules` 模型。
2. 第一阶段继续使用 `/` 单页，以 query 参数建立深链；不立即拆成 12 个 Next 路由。
3. 先拆应用外壳、导航、URL、请求边界、Design Token 和无障碍原语，再逐页迁移。
4. 保留当前四角色 `viewer / analyst / operator / admin`、principal scope 与所有服务端权限校验。
5. 保留现有业务 API、金额/日期口径、导入幂等、自动化门禁与 AI 状态机。
6. `app/page.tsx` 采用兼容桥渐进变薄，不进行一次性 5,978 行重写。
7. 当前品牌蓝继续使用 `#4776e6`；不静默改成参考提示词中的 `#2f6bff`。
8. 第一批保留当前“深色侧栏 + 浅色内容”主题。先完成语义 token 覆盖，再以独立批次交付完整深色内容主题。
9. 业务涨跌遵守仓库口径：上涨红、下跌绿；系统成功/失败色与指标涨跌色必须是两套独立 token。

## 2. 范围与非目标

### 本轮重构范围

- 应用壳、导航、顶栏、全局周期、全局搜索、用户区；
- 模块和页内视图的 URL 状态；
- Design Token、基础字号、间距、焦点、响应式和层级；
- 统一请求错误、最新查询、写操作 pending 和数据状态；
- Tabs、Select、Dialog、Drawer、TableShell、表单反馈等公共原语；
- 按风险排序逐模块迁移展示层；
- 真实浏览器、键盘、缩放、移动端和视觉回归。

### 明确非目标

- 不引入 Ant Design、ProComponents、Umi、react-router、dayjs、SWR 或图标库；
- 不把当前 API 改造成 DRF 响应，也不复制 ProTable `request` 协议；
- 不修改后端业务接口、D1/R2 结构、导入数据或 Cloudflare 部署；
- 不因视觉重构重写市场价格、库存、销售、自动化、AI 工具或导入业务口径；
- 不用客户端隐藏按钮代替服务端鉴权；
- 不在第一批同时交付完整暗色内容主题或全面表格列定义引擎。

## 6. 布局重构专案

### 6.1 导航事实源

`navigationCatalog` 保持当前 12 个模块、两组和精确顺序。模块链接使用真实 `<a href>`，当前项使用 `aria-current="page"`；普通左键由客户端接管，Ctrl/Cmd/中键、新标签打开和禁用 JavaScript仍可使用。

导航使用标准网站语义 `<nav><ul><li><a>`，不主动声明 `role="menu"`。这样避免在没有组件库时误用桌面应用菜单语义；Tab/Shift+Tab 与浏览器链接行为保持原生。Ant Menu 的分组、选中、折叠和 Tooltip 作为视觉/状态参考，页面内 `Tabs` 才实现左右方向键、Home/End 和 roving tabindex。

桌面折叠：

- `sidebarCollapsed` 与移动抽屉是两个独立状态；
- 折叠偏好可容错写入版本化 `localStorage`，不进入 URL；
- 按钮动态读作“收起侧边栏 / 展开侧边栏”；
- 折叠项以自研 Tooltip 同时支持 hover/focus，并通过 `aria-describedby` 关联；
- 不再只依赖 `title`。

### 6.2 URL 契约

顶层示例：

```text
/                                                    # BI 看板
/?module=sales                                      # 销售分析
/?module=sales&view=finance                         # 销售 · 财报分析
/?module=shop&view=products&subview=spu             # 网店 · 商品数据 · SPU
/?module=import&source=jd_sku_daily                 # 指定导入来源
/?module=inventory&view=age&period=last15           # 库龄 + 周期
```

壳层拥有的 query：

- `module`：12 个现有 ModuleKey；dashboard 规范化为无参数 `/`；
- `source`：仅在 `module=import` 时接受现有 `ImportSourceKey`；
- `period`：稳定英文枚举，不把中文文案写入契约；
- `month`：`calendar_month` 的 `YYYY-MM`；
- `from/to`：自定义范围的 ISO 日期；
- `view/subview`：在对应模块迁移时由模块自己的白名单解析。

周期值：

| 页面标签 | URL 值 |
| --- | --- |
| 今日 | `today` |
| 昨天 | `yesterday` |
| 近7天 | `last7` |
| 近15天 | `last15` |
| 本月 | `current_month` |
| 月度 | `calendar_month&month=YYYY-MM` |
| 自定义 | `custom&from=YYYY-MM-DD&to=YYYY-MM-DD` |

规则：

- 模块切换、搜索结果跳转、业务内 `onNavigate` 使用 `pushState`；
- 点击当前模块不新增 history；
- 用户完成周期选择后使用 `replaceState`，不为日期控件每次输入制造历史；
- `popstate` 只读取 URL，不再次写回；
- 非法 module/view/source/period 回退安全默认并 `replaceState` 规范化一次；
- 未归壳层所有的 query 和 hash 原样保留；
- n8n 模块隐藏周期控件但不清空周期，返回分析页继续沿用；
- 主动切换模块时按 reduced-motion 偏好滚动到内容顶部并聚焦 `<h1 tabIndex={-1}>`；
- 前进/后退优先保留浏览器滚动恢复。

当前 `range + customStartDate + customEndDate + selectedMonth` 应收敛成判别联合状态，防止四份状态漂移。相对周期仍按 `Asia/Shanghai` 在打开时计算；精确月度/自定义范围可稳定分享。

### 6.3 水合与兼容桥

第一步不让服务端和客户端首帧选择不同模块。可先用稳定的壳级 loading，客户端解析 location 后挂载 `LegacyModuleHost`；随后让薄 `app/page.tsx` 将 `searchParams` 解析为 `initialLocation` 传给 `operations-app.tsx`，消除闪烁。

现有签名继续保留：

```ts
onNavigate(key: ModuleKey, importSource?: ImportSourceKey): void
```

兼容桥内部把它转换为 URL intent。现有十余个业务调用点不需要在外壳提交中同时重写。

### 6.4 移动抽屉与焦点

860px 断点首批保持不变。移动抽屉必须：

- 菜单按钮具有名称、`aria-expanded` 和 `aria-controls`；
- 打开时保存触发按钮、锁定 body 滚动、令 workspace `inert`；
- 初始焦点进入当前项或关闭按钮，Tab/Shift+Tab 圈定；
- 支持 Escape、关闭按钮、遮罩和选择菜单关闭；
- 关闭后恢复触发按钮焦点；
- `popstate` 或卸载时恢复 body/inert，不能锁死页面；
- 从移动断点返回桌面时不覆盖桌面折叠偏好。

### 6.5 sticky 单一发布权

定义：

```css
--app-header-height: 82px;
--app-header-height-mobile: 67px;
--app-sticky-offset: var(--app-header-height);
--app-sidebar-width: 244px;
--app-sidebar-collapsed-width: 72px;
```

只有 `GlobalHeader` 可以成为全局 `top: 0` sticky 页头。市场等模块的局部 sticky 使用 `top: var(--app-sticky-offset)`；不再出现 `top: 72px` 一类字面偏移。header 实际高度变化时由唯一 publisher 更新 CSS 变量，业务组件只消费。

顶栏继续保持唯一模块标题和全局统计周期。静态“3 条通知”在没有数据源前移除 badge 或隐藏入口；“需要帮助”在没有真实页面前改成普通说明或移除伪交互。

## 7. Design Token 与主题

`tokens.css` 作为 CSS 视觉事实源，分层定义：

- 背景：app/surface/subtle/elevated/inverse；
- 文本：primary/secondary/muted/inverse/link；
- 边框和焦点：default/strong/focus-ring；
- 品牌：brand/hover/active/soft；
- 系统状态：success/warning/danger/info 及 soft；
- 指标：metric-up/metric-down/metric-neutral；
- 尺寸：space、radius、shadow、control height、sidebar/header、z-index；
- 排版：body、caption、table、heading 的字号和行高。

迁移规则：

1. 第一批把现有 `--blue / --green / --orange / --red / --shadow` 变成兼容别名；
2. 组件 CSS 只消费语义 token，品牌原色只允许出现在 token 文件；
3. 新增检查：使用的 CSS 变量必须已定义；禁止新增 12px 以下业务文字；
4. 正文/表格目标 13–14px，辅助文字至少 12px；
5. 普通文字对比度至少 4.5:1，焦点、控件边界和状态图形至少 3:1；
6. 保留 `prefers-reduced-motion`，移动端不通过缩成 7–9px 容纳大表；
7. 第一批只交付现有主题的 token 化；完整 `light/dark/system`、持久化与首帧防闪放在全站 token 覆盖后的独立批次。

若未来选择 antd，只允许把本 token 映射到 ConfigProvider；不允许产生第二套品牌值。

## 8. 请求、并发与状态公共层

### 8.1 `requestJson<T>`

- 默认同源、`credentials: "same-origin"`、`cache: "no-store"`；
- 普通对象自动 JSON；`FormData`/二进制不手工设置 Content-Type；
- 非 2xx 抛 `ApiError(status, code, message, details)`，兼容当前 `{error, code}`；
- 401、403、4xx 和 5xx 保持可区分，低层不自动跳转；
- 不记录 Cookie、请求 body、Token、Webhook、模型 Key 或客户原文；
- 不自动重试 POST/PATCH/DELETE，不隐式重放导入、AI 或自动化动作；
- timeout 由调用方覆盖，不用普通 30 秒上限截断现有 90/110 秒模型边界。

迁移按 View 逐步替换直接 fetch，不做全仓机械改写。

### 8.2 `useLatestQuery<T>`

- 只用于幂等查询；key 变化和卸载时 abort；
- 每次请求带 generation，即使底层忽略 signal，旧响应也不得覆盖新状态；
- AbortError 不展示，其他错误必须可见；
- `keepPreviousData` 时显式返回 `refreshing`，不能把旧范围数据伪装成新结果；
- `reload()` 创建新 generation。

### 8.3 `useAsyncAction`

- 管理 `pending/error/run/reset`；
- 默认不重试、不取消已可能产生副作用的旧请求；
- pending 禁止重复提交；
- AI 停止生成等允许取消的动作继续由领域组件显式控制。

### 8.4 数据状态

`DataState` 支持 `loading/error/empty/forbidden/auth-required` 与 page/panel/inline 尺寸；`TableStateRow` 专用于 `<tbody>`。error、forbidden 和 empty 必须文案、颜色和语义不同；loading 使用 polite status，错误使用 alert。

## 9. 表格、表单和枚举策略

### 表格

方案 A 第一批不实现通用列定义引擎，也不改成虚拟列表。`TableShell` 只负责标题、说明、toolbar、滚动区、分页、刷新和状态；页面继续拥有 rows 和原生 `<table>`。

- 服务端筛选放 toolbar；全局列筛选明确为“当前已加载页继续筛选”；
- 分页接受当前 `{page,pageSize,total,returned,truncated}`，不套 DRF；
- 大数据强制服务端分页；
- 操作/选择/图片列增加显式 filter opt-out 后，才更新 `TableColumnFilters`；
- 表头排序和列筛选点击区域分离；
- 所有数据表补 caption 或可访问名称、`th scope="col"`；
- 窄屏使用列优先级、横滚提示或摘要卡，不缩小字号。

### 表单与详情

- 原生 form + `Field/FieldGroup/ErrorSummary/FeedbackBanner`；
- 提交失败把焦点移至错误摘要，分组表单同时激活第一个错误分组；
- pending 禁止重复提交；成功和失败不只依赖颜色；
- 开关使用 `role="switch"`、`aria-checked` 和业务名称；
- 详情使用 `<dl>`，不为纯展示重复造表单。

### 格式化与 presentation meta

格式化函数名称显式包含单位：`formatCurrencyCents`、`formatFractionPercent`、`formatBasisPoints`、`formatDateShanghai`。`null/undefined` 显示 `—`，零不能被当空值。缓存 Intl formatter。

值展示使用领域内 `satisfies Record<Union, PresentationMeta>`；tone 返回语义，不返回色值。角色和通用状态可放 client-safe 公共文件，市场/导入/AI 等枚举继续留在各自领域，未知服务端值必须有 fallback。

## 10. 权限与登录边界

`useCurrentUser` 明确区分：

```text
checking | authenticated | anonymous | forbidden | error
```

当前把所有 `/api/auth/me` 失败吞成“访客只读”的行为应先拆开。外壳迁移初期可以继续保留已确认的访客展示，但 403、500 和网络错误不能再伪装成 anonymous。

完整阻断式 `AuthBoundary`（401 登录卡、403 禁止、500 重试、authenticated 渲染 AppShell）属于行为变化。实施前需要单独确认是否正式取消访客壳，并与生产匿名策略和本地直连开发模式对齐。

`RoleGate` 只改善体验：写 API 继续调用 `requireAppPrincipal(allowedRoles)`；scope 始终服务端过滤；403 显示无权限而非暂无数据。若抽取角色类型，`lib/auth/roles.ts` 必须是纯模块，不能把 Cloudflare/D1 依赖打进 client bundle。

### 建议按子页拆分的模块

- 销售：销售总览 → 渠道 → 财报 → 目标设置；

## 12. 各模块必须保持的验收口径

| 模块 | 关键验收 |
| --- | --- |
| BI | KPI、趋势、排行、告警逐项等价；图表提供可读摘要；375px/200% 不覆盖 |
| n8n | viewer/analyst 不挂 iframe；operator/admin 仍受 helper 状态控制；页面加载不执行流程 |
| 设置 | Switch 可访问；权限不足原因可见；保存中/成功/失败清晰；市场高危部分不提前迁 |
| 运营事务 | 创建、截止时间、状态迁移、附件、删除全路径；移动端用摘要卡而非 7–9px 表格 |
| 库存 | `刷刷仓` 排除不变；四 tab 可恢复；写入口按 principal；关键仓库+货品身份可见 |
| 销售 | 净额、退款、毛利、同比/环比等价；错误不等于零数据；多选和旧请求取消不回退 |
| 网店 | `platform + shop_name` 隔离；京东 SKU、跨平台 SPU、京东/天猫推广口径不混用 |
| 货品 | 多货品搜索/粘贴、筛选、排序、详情返回状态保留；金额/毛利不在前端重定义 |
| 客服 | 双文件关联和标注字段不变；原始聊天不进日志/截图夹具；移动端逐层查看详情 |
| 导入 | 上传、分块、取消、duplicate、预校验拒绝、落库回查全覆盖；上传成功不等于导入成功 |
| AI | 停止生成真正取消；切会话/模型不被迟到响应污染；密钥不进 DOM、日志或快照 |
| 市场 | 类目/scope/SKU-SPU/正式价身份不变；任务并发、暂停、恢复、复核和入库逐字段回归 |

## 13. 实施提交序列

每个提交保持应用可运行，建议公共层先拆为：

1. 导航事实源和 URL 纯函数，无视觉变化；

## 14. 测试与验收矩阵

### 纯函数与结构测试

- 12 个模块和精确分组顺序；
- URL parse/serialize/normalize 幂等；
- 非法、重复、空 module/view/source/period；
- 上海时区今日、昨天、月初、跨年、闰年、自定义反向范围；
- push/replace/popstate 不循环；
- 全局周期只有一个 publisher；
- sticky offset 只来自 token；
- `TableColumnFilters` 迁移期仍挂载；
- CSS 变量已定义、无新增小于 12px 业务文字；
- presentation meta 对联合类型穷尽。

### 真实浏览器

- 深链、分享、刷新、前进/后退；
- 普通点击和 Ctrl/Cmd/中键打开链接；
- 侧栏折叠 Tooltip、移动抽屉 Escape/焦点圈定/焦点归还；
- 全局搜索、周期、Select、Tabs、Dialog/Drawer 的纯键盘操作；
- n8n 隐藏周期后返回分析模块仍保留原周期；

### 工程门禁

浏览器测试必须使用临时环境，不复用京东/天猫业务 profile，不读取或修改真实 D1/R2、下载目录、Cookie 或 `.dev.vars`。
