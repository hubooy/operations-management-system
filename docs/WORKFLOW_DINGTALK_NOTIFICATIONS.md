# 工作流钉钉通知规则

本规则适用于吉客云、京东/天猫店铺数据、市场榜单及运营事项归档等系统工作流的运行通知。2026-09-08 起，以完整工作流为完成单位，替换原来的逐店铺数据集、逐节点、逐类目或逐归档事项完成通知。

## 发送时机

只发送以下三类通知：

1. **工作流完成**：本轮计划内的全部步骤、文件校验、导入精确批次与落库覆盖回查及资源收尾均已通过，发送一条汇总。恢复后的完整成功也使用这条完成通知，不再额外发送“已恢复”或总汇报。
2. **需要人工协助**：失败已经确认必须由人工操作，立即发送一条提醒，写明卡点、影响范围、已完成部分及具体需要用户做什么。验证码、登录/权限或身份异常、业务点击结果未决，以及恢复需要额外授权等，均不得等待重试次数才通知。
3. **持续阻塞**：现有安全恢复措施已经用尽，或同一卡点连续 3 次检查没有实质进展，或持续 30 分钟没有实质进展，任一满足即发送一条知会，写明开始时间、已尝试措施、仍受阻部分和下一步。检查次数不是业务重试次数；不得为凑次数重放业务或扩大既有恢复权限。正常队列等待、平台任务仍在约定生成期限内或有可验证进度时，不算失败卡点；达到原流程等待上限则按失败处理。

运行开始、排队、下载中、单个节点/数据集/店铺子步骤完成、短暂且可安全恢复的异常、排查过程和普通根因变化仅记录在当前任务，不单独发钉钉。未触及人工协助或持续阻塞条件的失败继续按原恢复门禁诊断；不得为了少发消息隐瞒已知无法恢复的失败。

## 完成单位

| 工作流 | 一条完成消息覆盖范围 |
| --- | --- |
| 吉客云导入系统 | 本轮五表全部完成校验、导入、精确回查和收尾 |
| 京东四店下载与导入 | 同一整条工作流的四店、每店三类数据全部完成；不拆成 12 条 |
| 京东市场榜单 | 本轮全部计划类目和目标日期完成；不逐类目通知 |
| 天猫店铺数据导入 | 每店自己的完整 A→B→C→P→M execution；不拆成 C/P/M 三条，不另发六店重复汇总 |
| 京东 AI 推广 | 每店各自的完整工作流；两条独立工作流分别完成时各发一条 |
| 每日钉钉事项归档 | 全部扫描、创建与回查结束后汇总一条；不逐条归档事项通知 |

无缺口、已覆盖、内容重复、未到期等正常结果合并到整条工作流完成消息，如实写“无需新增导入”“复用已确认批次”或“未到期及下次日期”；不能伪报新增导入。只有部分步骤成功时不得写“全部完成”，仍有历史缺口时只说明本轮计划完成并列出剩余范围。任一失败、待人工、回查未通过或收尾未完成均不满足工作流完成条件。

## 防重与恢复

- 完成键使用工作流 ID、本轮逻辑运行标识、业务范围/日期和 completed。逻辑运行标识优先使用原始 execution ID；恢复产生新 execution 时关联原执行与原业务计划，不得因换了 execution 而重发同一完成事实。无 n8n 的归档使用 automation ID 和上海业务日。
- 异常键使用工作流 ID、业务范围、同一故障事件和所需人工动作；同一卡点同时满足“人工协助”和“持续阻塞”时合并为一条。已提醒后，重复检查、重复报错、恢复换 execution 或仅更换错误文案都不重复发送。
- 仅当影响范围实质扩大或需要用户采取新的动作时补充一条异常更新；故障恢复且整条流程最终完成后发送一条完成消息。故障已明确解决后再次出现，才作为新故障事件。
- 发送前核对当前任务的投递记录与对应会话的可用回执。确认投递成功后才记录 sent；投递结果不确定时先查原回执或对应私聊/群消息，不能盲目重发。认证失效或目标无法唯一核验时停止发送重试，在当前任务保留脱敏未投递错误。

## 路由与内容

2026-09-14 起，“需要人工协助”只由名称精确等于“志高助手”的唯一企业机器人发给用户本人钉钉单聊，绝不发群。同一卡点的“持续阻塞”若需要用户采取行动，也合并到这条私人提醒，不向群披露人工动作；完成通知和不要求用户行动的纯状态阻塞仍按原规则发到唯一“测试群聊”。不得把这一改动扩展为库存备货群发、新品周报或系统运行告警等其他业务的收件人变更。

每次发送前读取当前 dws 技能。私人提醒通过 `dws profile list`、`dws contact user get-self` 与 `dws contact user search` 动态交叉核验：当前唯一组织账号应为“佛山市登荣科技有限公司”的“邓伟章”，搜索结果唯一且 userId 与本人一致；再用 `dws chat bot search` 唯一核验“志高助手”，以 `dws chat message send-by-bot --users <动态核验的本人userId>` 投递，绝不同时传 `--group`。群通知仍须动态唯一核验群标题、机器人及其已安装可用。不得在工作流或通知正文持久保存/暴露 userId、robotCode、凭据；身份、机器人或会话不能唯一确认时停止外发并在当前任务说明未投递，不回退群或其他个人。未经确认不得发送试探性消息。

消息使用简短脱敏摘要：工作流/店铺名称、上海时间、业务日期范围、整体结果，以及适用的回查结果、剩余缺口或人工下一步。技术细节仅保留排障必要的 workflow/execution 标识，不发送 Cookie、Token、账号标识、本机路径、用户 ID 或原始业务数据。

## 核验示例

| 场景 | 预期通知 |
| --- | --- |
| 吉客云五表中仅一表完成 | 不发送 |
| 京东四店已完成 11/12 步 | 不发送完成消息 |
| 天猫 C/P 成功，M 未到期且全部收尾通过 | 一条该店工作流完成，注明 M 未到期 |
| 天猫 C/P 成功，M 要求人工验证码 | 立即一条人工协助，说明部分完成；不发完成消息 |
| 一次网络失败后安全恢复并完成整条流程 | 一条工作流完成 |
| 同一卡点第三次检查仍无进展 | 一条持续阻塞；后续相同检查不再发 |
| 人工协助已通知，之后又满足持续阻塞 | 不重复发送同一卡点 |
| 新 execution 恢复同一业务计划并完成 | 一条逻辑运行完成；重复回查不再发 |
| 无缺口、没有新增导入且整条流程收尾完成 | 一条正常完成，明确无需新增导入 |
