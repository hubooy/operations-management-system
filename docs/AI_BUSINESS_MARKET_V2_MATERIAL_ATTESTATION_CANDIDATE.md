# 市场 v2 三表材料准入候选（0045）

此阶段为 0044 停放报告增加每报告最多一条、不可修改的材料 sidecar。原报告和工作流仍为 `paused / market_material_not_admitted`，`marketMaterialReady=false`，允许工具仍为空；不启动 Agent、模型、renderer8 或文件交付。

`prepare_candidate` 先根据停放报告的精确源报告、价格带、当前/基期来源及观察日，调用拥有方 `business_market_report_material.prepare`。拥有方完整重放封存页链、验证三张类型表，并在退出上下文时完成末端账号/报告栅栏。退出后只携带有界清单、摘要和三份类型表规格，不携带已关闭的表流。随后才允许独立提交步骤。

0045 建立专用 `teruisi_ai_market_attestor` 角色，默认 `NOLOGIN`、无成员关系、无直接表读写权限。仅该角色的真实 `session_user` 可以调用窄 SQL 函数提交 sidecar；函数短事务锁定停放报告、工作流、来源报告、原始封存证据及两份所选市场来源，核验当前管理员身份、来源页完成状态和查询/日期覆盖，再核对清单的选择器、算法、来源描述、三张规格的行数/页数/字节数合计及保守权威标志。清单和摘要各自的正文与提交摘要须一致，完整字节另计 SHA；同一材料的并发提交收敛到一条，异材料拒绝。普通 AI reader/writer 均不能读写此表或执行提交函数。

**候选边界**：当前没有受保护的独立 attestor 凭据、最小权限只读桥接或单次执行器，且角色保持 `NOLOGIN`；因此生产路径不能真正提交材料。隔离 PostgreSQL 测试可由测试超级用户临时切换会话身份，验证 SQL/触发器，不代表角色已投入运行。SQL 核对提交的正文与摘要和材料总量，但无法独立验证这些 JSON 字节采用 Python 的规范化编码，也不重算源事实、类型表逐行摘要或证明市场原始数字正确；只有将独立会话与拥有方完整准备过程受保护地绑定后，sidecar 才能成为后续工具读取的输入。sidecar 本身不保存三张完整数据表，未来工具仍须重放/核对同一封存材料。即使测试 sidecar 存在，也不授予 Agent、审批、renderer 或跨域销售相加权限。

下一步须先完成独立 attestor 的最小权限读取/提交方案、凭据保护和单次任务绑定，再添加材料读取回执和第五市场工具的持久同 Agent 栅栏；之后另做内容人审与 renderer8。旧 renderer 1–7 和已封存词货报告不因本候选而改变。
