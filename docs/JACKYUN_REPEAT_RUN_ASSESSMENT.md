## 结论

可以支持同一天多次完整运行。现有 API 五表流程在上一轮 `completed` 后，已经允许新的 n8n execution 建立新计划；不存在“一天只能成功一次”的限制。业务内容去重、事务内替换和精确批次回查已有基础。当前故障来自登录及未闭合运行，增加调度次数本身不能修复它。

推荐口径：同一业务范围内，以**来源可验证、采集时间更新、完整校验通过且成功发布**的文件为准；内容相同则记录重复并复用当前批次。不要以文件名、文件修改时间或上传先后判断业务新旧。

## 当前行为与覆盖范围

| 数据 | 现有业务身份与范围 | 相同内容再导入 | 内容变化后 |
| --- | --- | --- | --- |
| 货品 | 货品编号；全量主数据 | 比较标准化业务内容，复用当前批次 | 事务内替换全量主数据，新文件缺失的旧货品移除 |
| 组合装 | 母件编号＋子件编号；全量关系 | 同上 | 事务内替换全量关系 |
| 分仓库存 | 快照日＋仓库＋货品 | 同日同内容且原批次仍持有完整事实时复用 | 替换同一天全量快照，不把两次库存相加；保留其他日期 |
| 库龄 | 快照日＋仓库＋货品 | 同库存 | 替换同一天全量快照，保留其他日期 |
| 销售 | 明细身份；明确日期及渠道范围 | 比较该范围标准化内容，复用或登记幂等批次 | 更新本次行，并移除同一导入范围内未出现在新文件的旧行；范围外不变 |

销售当前仍为本月 1 日至昨天，月初为上月整月；库存及库龄使用实际采集日。每日增加执行次数不会自动把当天未结束的销售纳入。若需要当天实时销售，应另定截止时点与报表口径。

核心证据：`tools/jackyun-export-first-pipeline.ts` 的 active/phase 检查；`backend/erp_reference/import_service.py` 的 `import_payload`；`backend/inventory/import_service.py` 的 `_import_inventory_payload`；`backend/sales/write_service.py` 的 `_reserve_scope`、`_publish_import`。本次是代码与既有测试核验，没有执行生产重复导入验收。

## 需要补齐的能力

1. **源数据新旧门禁**。当前规范化入参没有完整携带并持久校验源任务采集时间，事务锁和状态版本只能保护写入顺序，不能证明后上传的文件更新。应从已绑定的 ERP 导出任务传递采集/任务时刻、execution、模块、范围、原始文件摘要与内容摘要，在数据库写事务内比较来源水位。旧文件晚到要拒绝；时间相同但内容冲突要停止；原时间证据未知时不能自动覆盖已确认的新版本。较新采集与当前内容相同也应审计并推进来源水位，同时复用业务批次，避免中间时刻的旧文件随后覆盖。数据跨月、范围重叠要逐覆盖范围检查，不能只按整文件时间比较。历史手工纠错应走单独授权的范围替换，不能伪造采集时间。
2. **导入前差异清单**。C 阶段输出每表新增、变更、移除、未变化和冲突数量，绑定当前数据库版本；D 阶段锁内重新核对版本，期间发生手工导入则重新校验或停止。全量导出须校验字段、来源行数、范围和异常骤减；不完整或空文件不能自动当成全量删除指令。
3. **明确两种重复**。跨次相同数据已经能幂等处理。单文件内，货品/组合装/库存的重复业务键当前会拒绝；销售解析器使用业务身份加出现序号保留可能合法的多条明细（`lib/imports/sales-ledger.ts`）。建议只折叠有充分身份依据且内容完全一致的误重复，并记录原行数与折叠数；同键不同值拒绝，不按“最后一行”猜测。销售不能仅按 SKU、订单号或整行相似度去重，避免漏计合法拆单和重复货品行。
4. **失败分类与恢复**。保持共享 helper 串行。明确证明尚未提交导出、没有文件和导入效果的失败，可在版本受控、证据完整的恢复协议下闭合；验证码、身份不符需要人工处理。已经提交导出须复用原任务，已经部分导入须核对精确批次，不能清除 active 后全量重跑。DPAPI binding 的底层原因仍未定位，关闭 3134 不等于修复自动登录。
5. **多表一致性与历史**。五表各域原子发布，但不构成五表整体事务；若第四表失败，前三表仍可能已更新，应显示部分完成并停止，不伪报整轮成功。新批次替换后旧批次为历史，不应要求旧批次继续持有当前全部事实。原始文件、摘要、差异和批次关系继续保留；库存日内多次替换还要回归广东仓健康复位与备货核算，不能把快照差异当作完整入库流水。

## 推荐验证及实施顺序

先恢复本次零业务效果失败并排查自动登录；再补齐源水位与差异清单，最后增加每天执行时点。每次新 execution 仍走完整 A/B/C/D/E，保留小时安全重试的成功停止和未知结果不重放规则。

隔离环境至少验证：A→A 内容相同但 XLSX 字节不同；A→B 更新及移除；B 后迟到的旧 A 被拒绝；不同日库存分别保留；销售范围扩大、缩小和渠道隔离；同键冲突；C 后人工写入；两次并发；第四表失败；导入响应丢失；跨日停止；成本变化；广东仓监控副作用。正式验收另需明确的运行/导入授权及五表精确批次回查。
