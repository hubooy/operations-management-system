# ERP 逐事实五层级回卷候选

`business_analysis.erp_fact_rollups.prepare` 只消费同一进程中已完整核验的 ERP 逐事实归属账本，产生五张临时数据表和完整 NDJSON：店铺/日、当前主数据平台品类/日、SPU/日、SKU/日、未分配原因/日。它尚未接入 owning 服务、Agent 工具、正式报告或文件发布，`authorityVerified=false`、`registeredRenderer=false`。

店铺/日包含每一条 ERP 事实。只有线上规格码唯一指向完整 SKU、SPU、平台类目身份的事实才进入三个商品层；同 SPU 下多个 SKU、缺失任一身份或无候选者，按原业务日及 `ambiguous`、`incomplete`、`unmatched` 状态进入未分配表，原金额不摊到商品层。当前主数据归属不是历史所有权证明。每层均保存十一项 ERP 原生有符号整数指标，退款负销售和源成本不改写；零成本可保留，但这些源毛利不是商品净利润。

一次扫描以源行 ID 唯一约束建立临时分组。每行保留源事实数、首末源行 ID 和全部源行 ID/摘要的连续链摘要，不在结果中放无界的源行数组。发布表前同时核验：店铺层所有十一项等于账本源总额；三个商品层各自等于已唯一匹配金额；未分配层按状态、行数和十一项金额等于原未分配池。单行、输出总量、输出行数、临时 SQLite 页数和每个 NDJSON 摘要都有上限；超过即失败，绝不取 TOP 样本冒充全量。

表中的店铺金额只来自 ERP 发货销售事实。网店支付/访客、推广花费、市场样本、B 端和月财报金额没有叠加；不存在可据此计算的店铺 UV、商品净利润或跨来源统一 GMV。下一步需由封存 owning Reader 建立真实页绑定、按比较窗口执行三期回卷并定义跨来源展示关系，在此之前该候选不得作为正式五维经营诊断的授权事实。
