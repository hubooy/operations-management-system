# v4 封存消费候选：0043 默认关闭

0043 新增唯一、不可变的 `ai_business_v4_seal_consumptions` 回执表，并在每条新 seal 插入后安装延期到提交的约束：同一事务里若没有精确 run、attempt、版本和正文摘要的消费回执，整笔封存回滚。消费回执还必须对应已领取的准确票据、请求摘要、当前最新尝试、账号版本、目录根及有效租期；普通 AI reader/writer 与专用 seal_writer 都没有该表的直接读写权。误授 INSERT 也受表所有者与会话身份双重门禁拒绝。

本片**没有**可执行的消费/提交包装函数，也没有 CLI、独立凭据或角色 LOGIN。0038 直接封存对 seal_writer 仍被撤权。数据库无法校验应用正文 HMAC：随机 64 位十六进制串只满足形状，绝非真实签名。即使隔离测试临时授予旧封存函数执行权，并提交真实应用 MAC，只要缺消费回执，提交阶段仍全部回滚；不能把本片称为已可正式封存。

0043 安装前已经存在的 0038 seal 行原样保留，不追认消费。当前代码的内部 `verify_seal` 必须看到 0043 消费验证函数，并核与该行同 run/attempt/版本/摘要的消费回执；函数或回执缺失均返回冲突，旧行不授予报告或下载权。只有持原票据 nonce、领取 token 与精确 request digest 的专用角色可通过窄结果函数查询**已经完成**的消费摘要；未完成一律返回不可用，不返回正文或其他运行信息。这为未来网络结果未知时避免重放预留了接口，目前不可能得到完成结果。

后续提交包装必须由受保护的应用先独立完整验真 HMAC，并在单一数据库事务中短锁源、复核当前账号/目录/attempt、调用0038状态转移、插入消费回执，然后提交；失败或延期触发器拒绝时三者一同回滚。参考约 57.5 万行的重放与180秒领取租期仍未证明可行，续读与签名密钥轮换另行验收。当前76张AI表历史清单冻结，0043仅新增一张回执表为77张；备份/健康须核延期触发器真实函数体、SECDEF、ACL和表不可变门禁。
