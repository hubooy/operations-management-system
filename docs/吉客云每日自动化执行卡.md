# 吉客云每日自动化执行卡

正常日跑只读取本执行卡与 `config/jackyun-daily-policy.json`。完整手册仅在策略版本变化、页面结构漂移或异常排障时读取。

1. 北京时间计算昨天和销售区间，生成唯一 `RUN_ID`。确认 `localhost:3000`、吉客云登录和下载目录后，启动 `npm run jackyun:daily -- --run-id <RUN_ID> --snapshot <昨天> --as-of <昨天>`。
2. 只复用一个吉客云标签页，严格按 `products → inventory → inventory_age → sales → combos`。等待当前模块 `<事件>.result.json` 为 `completed` 后才进入下一模块。
3. 每次只修改一个字段并读回。货品确认 SKU；库存确认全仓；库存和库龄都必须找到历史日期控件并精确读回昨天；销售确认发货时间、月初至昨天。实时库存、无日期框或日期读回不一致立即以 `FIELD_MISMATCH` 停止。正常路径查询只点一次，并证明加载状态或表格指纹属于本轮刷新后，再每 500ms 读取一次，连续两次稳定即继续。出现“共 N+ 条 / 查看总数”时必须先读回精确总数，不能把当前页行数当成总行数。只有页面明确返回 0 行且尚未导出、下载或导入时，允许预先记录意图后重查一次；第二次仍为 0 或状态不明立即停止。
4. 导出前持久记录 `exportIntentAt` 并监听下载，只点一次导出。组合装选择“导出组合装及子件 → 导出所有页”后，核对提示同时包含“导出列中存在图片列”“最多只能导出2000条”“确定导出”，只点击一次“确定”，记录 `exportConfirmation`，然后等待下载。不得打开下载记录弹窗，不得重复查询、导出或确认。只接受本轮浏览器或白名单 OSS 下载事件绑定的 `D:\谷歌浏览器` 新文件；共享目录中“唯一新文件”本身不是归属证据。
5. 每个下载完成后向 `outputs/jackyun-browser-events/<RUN_ID>/` 原子写入对应事件文件：`01-products.json`、`02-inventory.json`、`03-inventory_age.json`、`04-sales.json`、`05-combos.json`。字段固定为：`schemaVersion=2`、`runId`、`policyVersion`、`module`、`filePath`、`navigationIntentAt`、需要查询时的 `queryIntentAt`、`tableStableAt`、`exportIntentAt`、组合装必填的 `exportConfirmation`（`prompt`、`button`、`confirmedAt`）、`downloadEventAt`、`expectedSourceRows`、同样绑定运行/模块/策略的 `downloadProvenance`（下载 ID、方式、完成时间、原文件名、SHA-256、字节数）、`fieldChecks` 和小型 `evidence`。库存与库龄还必须有目标日、日期读回时间、查询刷新来源/完成时间和稳定时间的 `snapshotEvidence`。
6. runner 自动处理：库存剔除刷刷仓和无效成本，保留明确零成本并按 0 元计入库存金额及补货；销售要求页面计数明确代表 XLSX 非空明细行并与文件精确相等，再剔除执行当天行、处理刷刷仓、白名单和成本；晚于执行当天的日期报错；组合装执行父子覆盖和历史 95% 门禁。dry-run 只产生 `prepared`，不能被当作完成或续跑提升。
7. 任一登录、状态、下载、文件、导入或批次核验异常立即停止，只报告 `browser-state.json`、模块 audit 和简短错误。成功时只读取 `daily-summary.json`，不要展开完整 DOM、完整 audit 或异常数组。

## 统一执行入口

首次专用 Chrome 登录（只需在该固定 profile 中完成；Chrome 提示时选择保存密码）：

```powershell
npm run jackyun:login
```

只读核验登录态：

```powershell
npm run jackyun:browser -- --check-login
```

程序不从文件、环境变量或命令行读取吉客云账号密码，也不记录表单值。日常任务优先复用登录态；会话过期时，只有 Chrome 已自动填充账号和密码且页面没有验证码/二次验证，controller 才点击一次“登录”。未自动填充或出现验证时安全停止，需再次执行 `npm run jackyun:login` 人工验证；这不是每天都要登录。

新任务：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-automation-runner.ps1" --run-id <RUN_ID>
```

同批次续跑：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-automation-runner.ps1" --run-id <RUN_ID> --resume
```

公共自动化入口会在浏览器和 daily worker 启动前读取既有 `daily-run-contract.json` 与 manifest：已有任一运行证据却未显式使用 `--resume` 时零副作用拒绝。只有策略版本、快照日、销售截止日、本机 API 根地址和 formal/dry-run 模式全部与本次一致，且已完成前缀的原子 handoff、证据摘要、归档源/输出与批次仍可独立复验，才允许同 `RUN_ID` 续跑；缺少该契约的旧运行必须使用新 `RUN_ID`。不得重新导出清单中已完成的模块，也不得把 `prepared` 原地升级为正式完成。成功摘要包含每个模块的 `browserMs`、`runnerMs`、`totalMs` 和 runner 阶段耗时；日常报告只读取该摘要。

## n8n 三段式副本

仓库副本为 `automation/n8n/jackyun-five-dataset-daily.workflow.json`，工作流 ID 固定为 `J8kY2mQ5vR7sT4pN`，默认 `active=false`。它不使用 n8n 2.x 默认禁用的 Execute Command 节点，而只调用本地 Worker 守护的 `127.0.0.1:5791`：

1. `POST /jackyun/plan`：按 `Asia/Shanghai` 计算昨天，核验 `localhost:3000`、策略版本、专用 Chrome profile 与已有完整当日结果；存在已核验成功结果时生成 skip 计划。
2. `POST /jackyun/run`：复用 `jackyun-automation-runner.ts`，严格按 `products → inventory → inventory_age → sales → combos` 完成每类的导出、下载绑定、校验、预处理、导入和落库回查。该请求最多等待 90 分钟，任一模块失败即停止。
3. `POST /jackyun/verify`：独立重读 `daily-summary.json`、`run-manifest.json`、五类 audit 和规范原子 handoff，核对运行编号、策略版本、销售截止日、模块顺序、完成状态、归档输出 SHA 与精确批次身份；库存批次还须是系统当前选用快照，销售批次须回查原文件哈希与可选成本来源批次。核验完成后一次性辅助进程退出，由启动器重新拉起待命。

A、B、C 三个请求必须发送同一个 `X-TERUISI-N8N-EXECUTION-ID={{ $execution.id }}`。helper 只允许 A 首次领取；空/无效 ID、未领取即直跑 B/C、不同或旧 execution、同 execution 并发和乱序都返回 409。A 或 B 完成后若两分钟没有下一阶段，helper 释放本地所有权；后续执行必须从 A 重新领取，并由持久计划按原 `RUN_ID` 的恢复门禁决定是否续跑。

定时表达式为 `40 8-18 * * *`：每天 08:40 首次运行，之后到 18:40 每小时只做有界补跑检查；已有完整成功摘要时直接核验并跳过，不会重复导入。没有完整成功摘要但已有同日未闭环计划时，只允许复用原 `RUN_ID` 且必须同时证明当前模块尚未查询、导出、下载或导入；唯一例外是导入前因“当前页行数误作总数”被门禁拒绝，且同一文件路径/SHA、失败审计实际行数、页面精确总数、无 import 证据完全一致时，可修正元数据并复用原文件，禁止重新导出。任何其他动作证据不完整都失败关闭，不得新建运行或混用旧文件。首次启用前只手动执行一次并核对 A、B、C 全绿；确认无误后再由管理员发布和激活。
