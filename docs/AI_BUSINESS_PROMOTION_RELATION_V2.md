# 京东推广完整词链候选 v2

`business_analysis.promotion_relation_v2.prepare` 是纯进程内候选，不注册 Agent、报告或文件。调用方显式给出本期，以及可选的环比、同比京东推广来源、各自全部原始页和可信完整核对结果。比较来源必须是同一平台、精确店铺、原始日期范围和广告粒度；缺基期保持缺失。每个来源完整重放页链、来源身份、水位、元数据、日期覆盖、行号、内容摘要和全部指标控制总额。相同源行 ID 跨期重复、同一期不同 ID 使用同一非空内容摘要均拒绝，不静默去重。

每条源事实在临时 SQLite 中保留一次，再分别且仅一次进入三个独立分组视图：

- `full_relation`：业务日、关键词、搜索词、计划 ID/名称、单元 ID/名称、匹配方式以及**推广、触发、跟单**三个独立 SKU 身份。
- `promoted_sku`：相同词链与明确推广 SKU。
- `attributed_sku`：相同词链与跟单 SKU。

身份空缺保留 `null` 桶和原费用、点击、平台归因金额，不从顶层 SKU、触发 SKU、跟单 SKU 或商品名称替补推广 SKU。每个视图独立回加至同一来源控制总额；**三视图互为不同切面，不可跨视图累加**。推广归因金额不是 ERP 净销售、利润或订单级因果增量。结果携带每期来源、日期、源行数/页数、三视图完整行数、字节与摘要，`authorityVerified=false`。

输入按当前封存 v2 的全目录上限预检：最多 2,000 页、200,000 行、64 MiB 源材料；临时 SQLite 最多 256 MiB，输出最多 64 MiB，超限整次失败，不给前 N 行假完整结果。参考报告中的 575,095 行推广来源超过当前收集器行容量，明确报 `reference_scale_capacity_gap`，须先提升封存收集协议并重新验证真实性、容量和恢复链路，不能仅放大本候选内存。
