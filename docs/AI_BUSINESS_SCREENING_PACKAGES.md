# 五角色的完整筛查阅读包

第三十七批候选提供纯无损传输合同和内部授权读取服务，尚未注册模型工具或新报告协议。它解决跨分区逐页阅读的重复字段问题，不代表 Agent 已阅读、模型已获准运行或报告已完成人工复核。

所有角色均收到完整来源及其元数据、全部请求覆盖、执行表、规则分区计数和缺口。商品角色另读全部 ERP/商品保留候选，推广角色读推广候选，市场/B端角色读真实B端候选，独立复核和整合角色读全部保留候选。角色按固定计划及实际来源推导，不由模型自报领域标签。

传输使用固定列和字典，去除重复字段名、候选规则说明、表规则计数和每页重复目录。构造时完整验证真实选择计划，传输时只保留可核验表来源绑定，避免重复发送整份计划。解码须逐值还原全部必读来源、覆盖和本角色候选；不会截短文本、四舍五入或删候选。未保留的匹配数量仍完整披露。

`screening_package.build` 生成五个不可变包，支持 `page(offset)`、`pages()`、`unpack()`；`decode_pages` 验证从0到终页、严格数值类型、常量索引、固定角色集合、计数、整包及单页摘要，并重编码逐页比对。每页最多100条记录、38000 UTF-8字节，超宽记录拒绝。输入最多32MiB、单包24MiB、五包合计96MiB；这些是独立计算边界，不扩大模型上下文。

`business_screening_packages.prepare(screening_id, principal)` 从真实持久结果与当前报告元数据构造内部对象；`page(prepared, role, principal, offset=...)` 和 `describe` 每次前后重新核验账号、范围、计划、报告及封存摘要。读取不调用 `Reader.pages`，不写新记录，也不生成 Agent 已读证明。返回纯页保留 `authorityVerified=false`，授权由调用服务实际核验。返回副本以及内部包内容和摘要的变异均有拒绝测试。

隔离PG真实链路8项通过，纯合同及关联回归63项通过；独立复审重放6类数字、索引和内部内容变异均拒绝。详见 [候选证据](evidence/ai-business-screening-packages-candidate.json)。

实际双协议工具帧探针使用55规则分区的合成数据。90个保留候选时，复核/整合各4页，整合工具帧约148KB；720个候选时各12页、约486KB，明确超过192KiB限制。前者只通过必要的传输条件，尚未计系统/节点指令、工作流引用、下游依赖、预算及模型token，不能宣称完整模型准入通过。后续新协议必须用完整实际帧预检，并为每个Agent核验自己的全部必读页回执。
