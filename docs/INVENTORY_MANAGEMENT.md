# 库存管理板块说明

## 1. 目标与入口

库存管理用于把库存快照、销售需求、库龄、固定成本、在途与运营执行事项放在同一条链路中。页面包含：

- 库存总览：保留库存健康分布、优先补货建议和按货品、仓别展开的“库存健康明细（近30天）”；不再展示顶部库存 KPI 卡片、数据质量暂停横幅或重复的“销量近30天”表格。库存健康分布只统计京东仓、天猫履约仓（系统仓库分类 `cainiao`）、精确广东仓和自营仓，排除工厂代发、售后、样品、海外等其他仓别。
- 库龄分析：10 个精细库龄区间、数量占比、货值占比与明细。
- 备货计划：建议加入草稿、确认、完成或取消；支持下载标准 Excel 模板后批量导入多个规格，草稿可多选后一键确认并提交钉钉“备货管理”，已确认计划可批量重试同步、按采购/工厂发送群消息，也可生成采购执行事项。
- 滞销清理：高库龄、低动销与滞销候选；可生成清理执行事项。
- 京东入仓监控：RDC/DC 区域库存、在途、正向出库、计算周转、供应商与长库龄风险。
- 广东入仓监控：人工型号清单、广东仓库存与出库、供应商完整到仓周期、风险健康分布及 Excel 导入导出。上线须采用包含库存迁移 `0007_guangdong_monitor` 的版本。

所有库存、销售和成本分析继续排除 `刷刷仓`。

库存后端已完成 Django/PostgreSQL 正式单写切换：Worker 负责真实鉴权、XLSX 解析、HMAC 和有界传输，库存 reader/writer 固定使用 `127.0.0.1:8051/8052`。实现、迁移证据和运维边界见 [`DJANGO_INVENTORY_MIGRATION.md`](DJANGO_INVENTORY_MIGRATION.md)。

## 2. 公共筛选与跨 Tab 持久化

库存管理的六个 Tab 共用一套顶部筛选组件。货品编码或名称、仓库、品牌、品类属于公共业务范围，切换库存总览、库龄分析、备货计划、滞销清理或京东入仓监控时会保留并同步应用；各 Tab 的专属条件仍独立保留，例如总览的库存类型和健康状态、库龄页的风险状态和库龄区间、备货计划状态、入仓供应商。广东入仓监控固定使用精确名称“广东仓”，忽略其他页面遗留的仓库筛选，并以独立 URL 参数 `inventoryGuangdongRisk` 保存风险分类。

筛选状态写入当前页面 URL，浏览器前进、后退、刷新及复制链接后均可恢复。所有公共维度由各接口在服务端筛选，页面不加载全量数据后再做本地过滤；“库存健康明细（近30天）”同样只聚合筛选后的库存范围。库存总览不跟随全局自定义日期改变销量口径，固定以销售数据最新截止日向前 30 个自然日计算。筛选变化会重置对应分页、取消旧请求，并通过请求代次门禁阻止迟到结果覆盖当前范围。品牌和品类选项以各接口当前库存或库龄批次的未筛选全集为准，当前筛选没有结果时也不会把已选条件清空。

## 3. 数据来源与口径

| 数据 | 来源 | 主要用途 |
| --- | --- | --- |
| 分仓库存 | 最新完成的库存导入批次 | 可用、实盘、锁定、在途、库龄、固定成本、规格默认供应商 |
| 库龄报表 | 最新完成的吉客云库龄批次 | 库龄、7 日销量、30 日销量；存在时优先用于库龄分析 |
| 销售明细 | 最新截止日向前 30 个自然日的销售订单行 | 同货品、同规范化仓库的正向销量，以及货品近 30 天总销量；退款不冲减备货需求 |
| ERP 货品档案 | 货品主数据 | 品名、固定成本回退，以及老快照缺少规格供应商时的供应商回退 |
| 运营设置 | 系统设置 | 补货阈值、销量窗口、负库存、自动补货和预警开关 |

金额按人民币分保存。明确填写为 `0` 的固定成本是有效零成本：库存行正常保留，货值按 0 元计入完整金额口径，并继续参与库存健康与补货计算。成本单元格缺失或成本为负数仍属于无效数据，不能冒充零成本；成本不完整时页面必须标注覆盖率。

`config/inventory-warehouse-mapping.json` 固化用户提供的《仓库类型映射.xlsx》作为首次默认值：284 个仓库无重复，其中代发仓 220 个、京东仓 45 个、菜鸟仓 3 个，另含广东、售后、样品、海外、虚拟和异常仓；66 个仓库标记“计入库存=是”，218 个标记为“否”。系统设置中的“仓库映射”由库存 PostgreSQL 设置作为运行时唯一权威，管理员可逐仓编辑，也可导出、校验后批量导入；批量导入只新增或更新，不删除文件中未列出的仓库，并用映射摘要防止并发覆盖。库存或库龄资料首次出现未配置仓库时，只有成功导入事务才会把该仓库按受控名称识别结果加入映射并标记“待确认”；失败事务不留记录。待确认仓库在页面优先显示，可按确认状态筛选；管理员保存单条编辑或通过映射表导入后转为“已确认”。库存导入会先读取该权威映射，Django 落库再次复验；库存总览、健康、库龄、滞销清理和备货计划查询也在每次请求中读取同一映射。总览库存、健康和备货计划只使用标记为“是”的仓库，近 30 天工作台及库龄/滞销明细继续保留全部仓别并明确披露是否计入库存。

京东入仓仓库优先使用受控映射中的“京东仓”，同时兼容吉客云历史快照中的区域平台仓命名，例如 `上海常温C平台仓9号库-CHN`。兼容识别只影响查询分类，不改写历史事实。

## 4. 数据质量门禁

导入前拒绝以下高风险数据：

- 合计、总计、小计、汇总或 `total` 行。
- 系统未允许负库存时的负实盘或负可用库存。
- 单行数量绝对值超过 1,000 万。
- 库龄小于 0 或大于 3,650 天，避免把 Excel 日期序号误当库龄。
- 单件成本超过 100 万元或单行库存货值超过 10 亿元。

总览计算后还会执行全局门禁：

- 同货品、同仓库销量匹配率低于 60% 时，暂停精确补货数量、平均可售天数和新增备货计划。
- 自动补货设置关闭时，暂停自动建议。
- 库存快照超过 3 天时提示数据过期。
- 平均库存数量或平均库存货值明显异常时，暂停精确建议。

筛选或定位单一货品不能绕过全局质量门禁。页面不再单独展示质量暂停横幅，但创建计划的服务端门禁仍保持有效。“库存健康明细（近30天）”按近 30 天总销量降序最多返回 50 个货品，并按京东、供应商（映射分类为代发仓）、售后、广东、样品、菜鸟和自营仓展示库存、销量、计算周转与在途，同时汇总计入库存范围内的总库存、已覆盖库存金额、总在途、货品近 30 天正向总销量、总周转、建议补货和预警。`刷刷仓` 始终排除。

## 5. 库龄结构

精细库龄区间为：`0–7`、`8–15`、`16–30`、`31–60`、`61–90`、`91–120`、`121–150`、`151–180`、`181–360`、`1 年以上`。

每个区间同时展示：

- SKU × 仓库记录数；
- 可用库存数量与数量占比；
- 已覆盖库存货值与货值占比。

页面可同时选择多个库龄区间，并可按品牌、品类、仓库和风险状态多选；筛选在服务端应用，并同步更新指标、分布图和明细。品牌优先取 ERP 货品档案，库龄快照没有对应货品档案时明确显示“未设置品牌”；品类沿用当前库龄或库存快照，空值统一归为“未分类”。分布图使用“库存数量柱状图 + 库存金额折线图”的双纵轴表达；库龄金额统一按“正向可用库存 × 固定成本价”计算，不采用报表中的零售价或其他金额字段。

库龄分析明细同时展示品牌、库龄分布区间、库龄天数、库存数和库存金额；当前页 CSV 使用相同字段与口径，库存金额以人民币元导出。

数量、货值占比只以库龄已识别且可用库存大于 0 的记录为分母。缺失库龄的库存单独披露，不进入区间占比。旧四区间响应仍保留，避免现有消费者失效。

## 6. 执行闭环与权限

- `viewer`、`analyst`：只读查看。
- `operator`、`admin`：维护备货计划、从已确认计划创建采购事项、创建滞销清理事项。
- `operator`、`admin`：可把已确认计划同步到配置绑定的钉钉多维表；受限数据范围账号不得执行。
- `operator`、`admin`：可多选已确认且已填写采购、工厂的计划，先预览，再确认发送到系统设置绑定的钉钉群；受限数据范围账号不得执行。
- `admin`：另外允许同步库存文件。

库存总览可从“库存健康明细（近30天）”打开“创建备货计划”。货品名称、品牌、供应商、现有库存、近 30 天正向总销量和预计消耗周期由当前权威数据回填，其中预计消耗周期允许人工调整为 0–3,650 天、最多一位小数；入库库房只能来自映射表标记为“计入库存=是”的当前库存行。部门预填“志高项目组”且允许清空；人工填写的备货数量、对应采购、对应运营、部门、备货类型、下单日期、预计到货日、验货和备注随计划持久化。没有精确系统建议时仍可创建人工计划，但必须显式填写正数备货量并保留“人工创建”原因；这不会把低可信建议伪装成系统建议。

备货计划页可下载《备货计划导入模板.xlsx》，填写货品编码、入库库房、备货数量及可选的采购、运营、部门、类型、日期、预计消耗周期、状态、验货和备注后一次导入。货品编码按文本读取以保留前导零；单次最多 200 行、文件不超过 4 MiB，不接受公式、额外列或重复的“货品编码 + 入库库房”。状态留空默认“已确认”，部门留空默认“志高项目组”，验货留空默认“否”。导入会一次性回读最新权威库存快照并校验每个规格与仓库，任一行无效则整批不落库；过期快照必须由用户明确确认。系统从库存权威数据回填货品、供应商、库存、销量与建议，只把表中人工字段写入计划。导入本身不会自动调用钉钉，避免未复核数据直接产生外部写入。

采购事项只能来自已确认的备货计划，并记录计划类型、供应商、入仓仓库、计划数量和预计到货日。滞销清理事项在保存前会重新核验最新库龄快照，只接受当前仍属于高库龄、低动销或滞销的货品。执行事项进入“运营事务”并关联来源对象；不会自动修改、删除或重新导入库存事实。

通过页面单条表单保存为“已确认”或把草稿确认时，页面会在本地确认成功后立即把同一计划提交到 `config/dingtalk-replenishment.json` 绑定的《备货计划进销存表》/“备货管理”。草稿支持当前页多选并一次确认后顺序执行“本地确认 → 钉钉幂等提交与写后回查”；每条草稿使用页面当前备货数量，完整成功项取消勾选，本地确认或钉钉提交未完成的项目保留勾选。混合选择草稿和已确认计划时，两个批量按钮只处理各自状态，不互相丢失选择；批量导入仍须在复核后显式操作。历史未同步计划或同步失败计划保留手工重试按钮。同步前回读表、字段和单选项契约。对应采购、对应运营和部门按钉钉真实 ID 精确解析；重名、无法匹配或单选项缺失时失败关闭。每条记录的备注包含 `[运营管理系统备货计划ID:<id>]` 标记；查询仍兼容历史 `[TERUISI备货计划ID:<id>]`，下一次受控同步会更新原记录而不是新增重复行。写后逐字段回查；系统同时保存钉钉记录 ID、当前格式摘要和同步状态，因此重复点击或边缘请求重放不会静默新增重复行。钉钉不可用只影响本次外部同步，不改变已完成的本地确认，页面会明确提示并保留勾选以便重试。

多个已确认规格可在同一页勾选后点击“批量提交钉钉表”。浏览器按顺序复用单条计划的幂等同步、计划 ID 标记和写后回查链路，最多处理当前页 50 条；成功项自动取消勾选，失败项保留勾选并显示首个错误，便于修正人员映射、权限或单选项后只重试失败记录。该操作只更新钉钉“备货管理”表，不等同于发送群消息；群消息仍要求采购和工厂完整，并经过预览与再次确认。

备货计划群发只允许选择已确认、且对应采购和工厂均完整的计划。库存域固定使用“志高助手”发送到“志高/特睿思备货计划群”，与新品周报的通知目标相互独立；预览与正式发送都会动态精确核验目标群、机器人及入群关系，并把采购姓名解析为唯一钉钉用户 ID。正式消息先 @ 对应采购，再按工厂使用“**▸ 工厂（N 条）**”分组，每行使用“货品编码 货品名称，× 数量台”；供应商分组和货品行通过 Markdown 硬换行稳定展示。确认发送前页面完整展示目标和正文；正式发送前会再次同步所选多维表记录。群消息按 DWS `im.batch-write.v1` 逐目标账本确认成功，并保存去重账本；已成功、发送中或结果不明确的同一批内容不会自动重复发送，账本只保存回执摘要，不保存原始外部回执或凭据。

同步适配器复用当前 Windows 用户已安装的 DWS 与其钉钉 OAuth profile；仓库配置只保存稳定的组织/用户 profile 标识、Base/Table/Field ID 和字段契约，不保存 access token、密码或应用密钥。部署前须以同一 Windows 用户完成 DWS 登录并对目标 AI 表格保有写权限；授权失效时按钮明确失败，不回退到群机器人 Webhook、浏览器自动化或其他账号。

## 7. 京东入仓监控边界

当前版本提供的是可复核的第一阶段监控：

- 只统计京东 RDC/DC 与受控规则识别的京东区域平台仓。
- 7/30/90 日出库只统计正向销量；退款不计为出库。
- 计算周转天数为 `当前可用库存 / 近 30 日平均正向出库`。
- 库存货值使用系统固定成本；不是京东供应价或结算价。
- 供应商优先来自吉客云分仓库存的“规格默认供应商”，老快照缺失时回退 ERP 货品档案，页面明确标记来源；两者都缺失时标记待补映射。

京东原生库存、原生周转、供应价/结算价尚未接入，因此系统不得输出“与京东完全一致”、原生差异、残差 SKU 或对账通过结论。后续接入原生数据后，应保留原始指标与系统计算指标两套口径再做对比。
