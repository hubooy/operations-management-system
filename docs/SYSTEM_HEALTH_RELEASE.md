## 首轮问题、修正与验证边界

首轮新主数据正常，但三个榜单变体均因单条 SQL 超过原 6 秒限制返回 503。只读 EXPLAIN 显示：有效价格条件高度相关，哈希长度与字符表达式过滤使价格侧估算降到 1 行，产生无索引的 Nested Loop / Materialize，合成库未覆盖该执行计划。

补丁保持状态、类型和正价过滤，把哈希校验改为结果表达式：无效哈希对应 NULL 正式价。唯一快照身份保证原语义和条数不变；没有放宽超时、修改数据库统计或生产配置。相同正式统计下的 EXPLAIN 改为 Hash Join，价格侧估计 1,999 行。第二次受控切换后榜单恢复，首页完整响应 SHA-256 与发布前一致。

补充验证为隔离 PostgreSQL 29 项通过，覆盖 10 万行关联条件、25 万行以上分页、结果等价、价格边界、主数据及签名/权限契约；SQLite 7 通过、2 个 PostgreSQL 场景跳过；迁移 dry-run 无变化。新增关联条件样本在原实现上也能通过，不能声称它稳定复现了正式慢计划；正式 EXPLAIN 与最终接口回读是此次修正的直接证据。原候选的 199 项集成测试等记录保留，不把它们冒充补丁后的全量重跑。
