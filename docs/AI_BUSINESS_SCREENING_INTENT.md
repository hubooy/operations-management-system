# 新筛查报告的固定准备意图

第四十批固定未来筛查报告的身份与范围，并增加数据库约束。尚未注册报告创建 API、调度、模型工具、读取证明或文件协议；旧报告不能因此自动获得筛查能力。

内部 `business_screening_runtime.prepare` 从实际所属用户的封存目录和来源元数据生成完整选择计划，首次固定报告 ID、筛查 ID、计划摘要、选择/算法/容量/角色包策略。可选商品关联和预算也在首次快照及工作流输入中固定。它不读取事实；`revalidate` 和 `bound` 重新核对真实账号、报告、工作流、封存、来源及完整计划，不信任公开 JSON。

后续完整计算仍经 `prepare_for_report`，短事务发布沿用两张固定存储表。新协议必须使用首次预分配 ID；重放、描述、分页读取都会再次核验该 ID 及规则绑定。报告快照和工作流输入无需在扫描后回填，未知或未支持协议继续拒绝旧文件交付。

迁移 `0024_business_screening_runtime` 不新增表或权限，AI 自有表仍为65张。它为新报告与所属工作流增加约束，并精确扩展既有预算/映射及筛查发布门禁：

- 七字段意图精确匹配，拒绝缺失、额外键、重复键、错误类型及策略。
- 报告、工作流、实际证据、owner/scope、可选映射与预算双向绑定；映射从实际封存来源验证。
- 含意图的孤立工作流不能提交；已发布结果 ID/计划/算法/策略须等于原意图。
- 只要已有新报告或工作流意图，即使尚未发布筛查结果也拒绝逆迁移；空库逆迁移恢复原函数。
- 健康检查核对实际函数体、权限属性及触发器，不只检查迁移名称。

预算绑定的内部互相核验使用显式 `check_budget=False` 截断递归，外层继续完整核对固定预算。没有预算不能返回空成功冒充预算已核验。

隔离测试覆盖映射×预算四种组合、真实封存后完整筛查发布、幂等回读、错误恢复身份、实时授权及旧存储行为。首次一项测试错误地要求原值写回失败，修正为实际改变内容后验证不可变；没有修改既有允许原值写回的语义。最终证据记录升级、受限角色、独立恢复与回归结果，见 [候选证据](evidence/ai-business-screening-intent-candidate.json)。

下一步仍是运行接入：扫描完成前禁止产生专业子任务，实际模型/目录容量准入，每个 Agent 独立读取固定包，同一证据的诊断与双格式文件。当前实现只解决这些步骤所需的固定绑定。
