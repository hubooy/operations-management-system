# 同一封存 v2 报告的 13 表预览候选

`business_report_composition_owning.prepare()` 是内部拥有方入口，必须显式传入 `enabled=True`。它不注册接口、Agent 工具或 renderer，也不写文件表、下载授权或 Agent 已读回执。返回的 HTML/XLSX 是内存中的一次性候选字节，不代表正式交付。

入口先重建当前管理员、同一 `AiReportRun`、工作流、封存 v2 证据、mapping plan 和所有选中来源的 revision/证据摘要。三期 SKU 拥有方结果与三期逐日材料再分别完整回放并核对材料摘要。品类和 SPU 使用同一报告的 ERP 回卷 category/spu 原生流以及商智 SPU 封存页重算；历史 ERP 身份的增长率保持空值。没有对应来源时，表中列明缺口。关键词目前仅列未提供的来源表头；财报、B 端、市场只列背景/缺口，不向店铺销售金额相加。

纯 `report_composition_v1` 先验证由拥有方生成的同报告证明；`report_composition_tables_v1` 形成固定 13 张表，其中第 13 张逐表记录来源摘要、实际行数与行摘要。同一个 `Table` 元组进入 `report_files.write_pair`。入口独立复验 HTML 的规范行 SHA、XLSX 的 manifest 与各工作表物理行数、写入器回执和表审计，再重读管理员/报告/映射/封存/来源修订。任何前后漂移或文件差异均拒绝完整候选。纯合成测试覆盖正例、品类/SPU 全来源回放、三表缺源、HTML/回执篡改及终点 revision 漂移；隔离 PostgreSQL 测试另覆盖真实封存报告、默认关闭、跨账号、管理员撤权和来源漂移。测试文件已写，须由整合任务串行运行 PostgreSQL。

此入口继承 v2 单来源最多 2,000 页、64 MiB 的读取上限，组合表另限 50,000 行、32 MiB；参考店铺两期推广合计约 575,095 行，**不能**据此声称全量报告完成。后续须接 v4 分段流及跨来源容量/恢复证明、关键词完整行表、财报/B端/市场同报告身份关系、真实 Agent 引用与持久已读、正式受保护发布和生产外的原生 Excel 验收。在这些完成前不得注册或对用户称为正式工程报告。

整合隔离 PostgreSQL 三项 `.runtime/ai-pg-f7246bac2aae/tests.log`（14.771 秒）通过，覆盖同一封存报告的 13 表双格式字节/摘要、缺来源与当前账号/修订漂移拒绝；纯相关17项通过。测试只用小规模合成来源，不替代参考57.5万行、财务/B端统一根、市场真实Agent或正式文件发布验收。

推广明细文件的独立有界分卷暂存子能力已见 `docs/AI_BUSINESS_REPORT_COMPOSITION_VOLUME_STREAM.md`；它通过合成 575,095 行规模，但不扩大上述 v2 来源读取上限。
