# 完整规则筛查工作台

第五十二批在已有封存范围上增加显式的“完整规则筛查与多 Agent 分析”模式。旧模式仍为默认；选择新模式后禁止模拟分析，并将模式、完整范围、商品关联和可选固定预算写入同一冻结请求。能力变化或来源未就绪时停止提交，不静默退回旧协议。提交结果未知时继续保留原账号、UUID 和请求正文。

报告详情展示实际准备状态、完整来源和覆盖、分析表与规则分区、匹配/保留/省略数量、五个 Agent 各自的读取证明及三个专业诊断。较长列表每页二十条，可查看全部记录；结构或计数不符时明确显示错误，不省略坏项后声称完整。指标与比较字段显示中文名称，未知指标保留原名。所有来源和模型文字作为文本展示。

新模式的预算详情只读。修改预算须回到工作台明确建立新的固定请求，避免沿用旧报告编辑入口而无意改变分析协议。完整文件继续使用既有持久多卷入口。

只有精确 GET 报告详情路径、成功响应且解析后的 snapshot 属于新筛查协议，才允许最多 5 MiB。其他报告、错误响应和其他路径保留 2 MiB。读取器返回实际原始 UTF-8 字节数，不能用 JSON 重新序列化后的长度或缺失的 Content-Length 绕过限制。

浏览器验证覆盖完整父组件、新旧模式、映射加预算、未知提交刷新、账号切换、二十一条覆盖分页和390px窄屏。另直接使用隔离 PostgreSQL 的真实 HTTP 合成报告验证字段兼容：三来源、六分析表、九规则分区、五份读取证明及预算。此为合成验证，不代表真实经营判断或生产采用。见 [候选证据](evidence/ai-business-screening-workbench-candidate.json)。
