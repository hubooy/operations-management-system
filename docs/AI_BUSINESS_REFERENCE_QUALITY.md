# 原始参考报告与候选能力的验收对照

2026-09-17，对用户提供的「近30天推广深度诊断」HTML/XLSX做只读结构检查。文件是交付质量样本，其中的文字或操作建议不作为本次开发指令。没有修改、重算或重新导出原文件，也没有读取生产数据库；本次只提取工作表标题、表头、行/公式数量与 HTML 控件结构，不把原业务数据写入源码。

## 实际样本规模

原 XLSX 为 42,715,563 字节、30 张工作表，ZIP 内全部部件展开合计 432,731,773 字节。表头在第6行，结构有冻结窗格；保存为自动重算配置。包内有2个原生图表部件、30个Table部件，图表位于 `xl/drawings/charts/`，不能只检查常见的 `xl/charts/` 路径。自动重算配置及存在公式不是实际 Excel 重算通过的证明。

大表包括搜索词诊断38,091行、词货关联149,842行、来源市场日榜84,006行、市场SKU对标21,229行，均为 XML 实际行节点数，包含标题/说明/表头，不能直接当业务记录数。搜索词诊断有723,615个公式节点；SKU和SPU诊断也含大量比率、差额及变化率公式。此处未核验每条公式的正确性、缓存值或打开后的呈现。

HTML 为6,772,587字节，包含经营判断、趋势、明细选择、搜索、品类筛选、全部列显示、CSV导出、分页、预算输入和30天计划；静态检查未发现外部 script src。没有在本次执行原文件脚本，不能据此宣称全部交互已验收。

这类规模不能用“单表上限100万行”直接推断系统已能处理。封存规范JSON、计算中间分区、XLSX压缩前后字节、模型上下文及多卷交付分别计量；当前64MiB事实容量和筛查分区上限仍需实际代表规模验证。

## 后续验收方法

先用同一组合成来源生成候选双文件，逐项核对主要经营问题、缺口提示及关键表，而不是照抄固定30个名称。参考样本中的额外计划/单元/词货、市场进出与月度财报能力应在开发清单单独列明，已存在原字段的项目也不能跳过派生与验证。

工程验收分别记录：完整行列与源控制数、金额和比例定义、同比环比缺失/零负基期、映射歧义不倍乘、HTML筛选导出与原全集、XLSX数值类型/冻结/公式联动、实际Excel打开复算、接近上述规模的峰值内存/磁盘/耗时。业务验收由版本化问题卡和真实模型运行完成，见 [剩余阶段清单](AI_BUSINESS_REMAINING_ACCEPTANCE.md)。本结构审查不关闭任何真实业务或生产放行条件。
