# 上新销售周跟进与钉钉同步

## 业务口径

- 周期和发送时间均取运行机器的本地时区；默认报表是上一个完整的星期一至星期日，不固定为 `Asia/Shanghai`。
- 销售事实只按 `sales_order_lines.product_code` 与吉客云 `erp_product_master.product_code` 精确关联，不用商品名称做销售归集。
- “产品线名称”是用户维护的展示与管理层级。例如“油水分离器”可以包含 10 个吉客云货品代码；代码对应的货品名称始终从吉客云主数据读取。
- 净销售额允许包含负值退款；退款额单独展示；毛利沿用销售事实的毛利字段，周报不会重新定义销售口径。
- 产品线从各自监控开始日持续跟踪，不再设置或计算跟踪周数；操作员可在产品线列表暂停或重新启动监控。暂停项保留配置和历史数据，但不会进入周报预览、Excel 或钉钉截图。
- 图片周报的周维度固定从本机日历的 `2026-08-03`（星期一）开始，每经过一个报告周追加一列并保留全部历史周；周值使用吉客云货品代码的净销量。产品线早于自身监控开始日的历史周仍显示为 0，不反向补造监控前事实。
- 图片表格固定展示“品牌、产品图、产品名称、趋势、连续周销量”。新建和编辑产品线时从本地选择 JPG、PNG 或 WebP，浏览器在保存前将图片转换并压缩为不超过 300KB 的 JPEG，随后作为 PostgreSQL 中该产品线的受控图片内容保存；页面和 Excel 通过鉴权接口读取，钉钉周报生成时使用同一图片内容，不再要求操作员维护公开图片链接。历史记录中已经存在的合规 HTTPS 图片仍只读兼容。品牌取当前吉客云/ERP 主数据中该产品线有效货品代码的品牌集合，多个品牌显式并列，缺失默认展示“志高”。

## 代码学习

用户为产品线维护展示名称及“吉客云名称（学习关键词）”。每次 `products` 吉客云货品主数据导入完成后，公开导入路由都会调用新品学习接口；若 PostgreSQL ERP 投影尚未追上，本次导入仍正常完成并返回 `newProductLearning.status=deferred`，页面载入、人工“学习新代码”和周报任务还会再次对完整主数据做幂等学习。

未归属代码的吉客云名称只命中一个产品线名称/关键词时自动补入；同时命中多个产品线时列入 `ambiguous`，不自动猜测。手工录入代码必须已存在于吉客云主数据，且同一代码不能同时归属多个产品线。

## 页面与接口

入口为“运营事务 → 上新跟进”，支持：

- 新建和编辑用户命名的产品线、本地上传或移除产品图、吉客云名称学习关键词、监控起始日及可选周目标；产品线从开始日起持续跟踪；
- 在产品线操作区暂停或启动监控；暂停项不会进入钉钉预览、Excel 和发送截图；
- 查看产品线和代码级本周/上周销量、净销售额、退款、毛利及累计；
- 查看与钉钉投递一致的表格预览、横向滚动全部历史周并生成带同色表头、斑马纹、产品图和趋势折线图的 Excel 表格；钉钉投递仍使用同版式 PNG；
- 在“系统设置 → 钉钉机器人”独立子页查看 Stream/DWS 接入方式、图片投递方式并设置机器人名称、目标群、本机发送日和本机发送时间；“运营事务 → 上新跟进”的图片预览区提供直达入口；
- 配置默认关闭。当前通知安全边界固定为企业机器人“志高助手”发送到群聊“测试群聊”，页面不能改成个人或其他群。
- AppKey、AppSecret、OAuth token 等凭据只由本机 DWS 安全凭据库管理，不进入 PostgreSQL、页面回包、日志或仓库。

## 安全发送器

受保护 runtime 的生产发送入口为：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\teruisi-runtime\django-sales\app\tools\django-workflow-service.ps1 -Action RunWeeklyReport -Json
```

受控人工立即发送一次使用：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File D:\teruisi-runtime\django-sales\app\tools\django-workflow-service.ps1 -Action ForceWeeklyReport -Json
```

底层 Django 命令无参数时只学习代码并输出周报 JSON；`--dry-run` 会通过 `dws` 完成群、机器人及入群关系的动态核验，同时验证图片布局但不生成钉盘文件、不发送；`--send` 只在配置启用且本机时间落入设置时间后的 10 分钟窗口时发送。正式发送先用独立无状态 Chrome 将同一表格渲染为 PNG，再通过 `dws drive upload` 上传到当前授权身份的钉盘，最后由“志高助手”机器人仅发送“新品销售周报”文案和该截图的钉钉在线预览入口，不附加销量摘要、排行或异常清单。受控人工补发应通过 `ForceWeeklyReport` 入口调用底层 `--send --force`，仍要求配置启用并执行全部目标核验。

仓库提供默认 `active=false` 的 `automation/n8n/new-product-weekly-dingtalk.workflow.json`。它每 5 分钟调用一次受保护 runtime 入口，由数据库配置中的本机星期和本机时间门禁决定是否发送；同一 10 分钟窗口内的再次调用由投递账本去重。生产发布时必须先导入、检查并手工激活该模板，不能让页面保存配置隐式发布 n8n 工作流。

发送前必须满足：群标题精确且唯一、机器人名称精确且唯一、机器人已安装到该群，PNG 通过签名和字节上限校验，钉盘预览链接必须是允许的钉钉/阿里 HTTPS 域名。外部调用开始前写入 `workflow_new_product_weekly_deliveries`；同一报告周、群和机器人只允许一个投递键。图片上传或机器人发送结果不确定时都记录为 `uncertain` 并禁止自动重试，避免重复文件或消息，需人工核对钉盘与群消息后再处理。数据库只保存脱敏回执摘要，不保存预览链接或凭据。

生产迁移、reader/writer 权限、命令运行环境、定时器启用和第一次真实发送都属于受控发布步骤；合并代码不会自动迁移数据库、启动调度或发送钉钉消息。
