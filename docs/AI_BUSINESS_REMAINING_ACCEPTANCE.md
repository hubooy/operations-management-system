## 判断口径

用户目标是让系统按不同经营问题，结合店铺、市场、店铺销售和 B 端销售，由多个 Agent 协作产生可追溯诊断、调整规划及工程级 HTML/XLSX。两个参考文件是质量样本，不是固定模板。原五阶段仍是「数据与计算基础 → 多 Agent 闭环 → 完整诊断与规划 → 工程级文件与规模 → 工作台与正式验收」，开发批次数不是阶段数。

候选已具备主要工程链路，不能再将预算、持久多卷或商品关联全部列为尚未开发；也不能据此宣称五阶段全部验收。用户已授权持续开发，下面的普通开发、合成测试与独立复审可以连续推进，无需逐批询问。真实付费运行、生产采用及服务维护按现有授权与项目流程处理；不要把这些验收边界变成日常开发的反复确认。

四种状态必须分开：

| 状态 | 含义 |
| --- | --- |
| 已实现候选 | 实际代码存在，并有对应测试；不等于该版本全部回归已通过或已上线 |
| 真正未开发 | 当前链路没有该能力，必须增加协议、实现或产品交互 |
| 合成待验 | 能力已有，但仍需在最终组合版本执行特定测试；测试文件存在不等于已运行通过 |
| 真实验收 | 需要真实来源、真实模型判断或受控采用才能完成；不得用 mock、合成金额或截图替代 |
