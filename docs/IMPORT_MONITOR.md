# 数据导入：运行记录与链路规则

数据导入工作区保留文件导入，原导入历史改为运行记录，新增链路规则，移除数据连续性子板块。旧 `view=history` 链接继续有效；`view=chains` 打开链路规则，旧 `view=continuity` 规范化回文件导入。以下描述源码行为，生产页面需另行受控发布。

## 运行记录

页面复用销售、库存、ERP、财务、网店、客服和 SKU 快递费率的七个有界只读批次接口，仍由各 Django 业务域执行权限检查。列表是各来源最近返回批次的集合，并非全量历史；数据类型、状态筛选和每页 20/50/100 条分页明确只作用于已经读取的集合。

按参考系统采用创建时间、类型、来源、链路/主体、状态、结束时间、失败原因、发起人列；展开可查看批次 ID、文件、工作表、行数、告警及批次处理耗时。接口没有提供的发起人、原因和结束时间显示未知或未提供，不从文件名或时间猜测。未知、进行中、失败、重复和部分完成状态不会误标成功；没有结束时间不以创建时间代替。

导入批次成功不能证明整个 n8n 工作流成功。当前系统没有按权限授权的 n8n 持久化执行投影，下载、登录及导入前失败不会出现在业务批次中；通过链路详情打开原 n8n 执行记录，继续使用 n8n 自身登录态。刷新失败明确显示缺失来源，取消与请求代次保护继续阻止迟到响应覆盖新状态。

## 链路规则

矩阵横向为 n8n 工作流类别，纵向为吉客云 ERP 和店铺，可按 ERP、京东、天猫过滤。当前包含 5 类链路、11 个执行主体和 11 份工作流配置。单元格展示今天状态、完成时间、频率和启停状态；详情显示模块、步骤、主数据周期及共用工作流的主体。共用的京东四店工作流显示整链状态，不虚构四份独立调度或逐店完成证据。

展示投影由 `tools/build-import-chain-catalog.mjs` 读取精确白名单内的 n8n 工作流模板及店铺配置，生成 `lib/imports/chain-catalog.generated.json` 和后端工作流 ID 白名单 `backend/workflow/import_chain_catalog.json`。前端仅加载名称、主体键、模块、工作流 ID 和计划频率等字段；不打包完整店铺配置、Profile、下载路径、凭据或可执行节点参数。

修改工作流模板或店铺配置后，运行 `node tools/build-import-chain-catalog.mjs` 同步目录，再运行 `tests/import-monitor.test.ts` 的一致性检查。仓库定义中的 `active=false` 是安全导出默认值，不代表线上停用；候选模板也可能尚未采用。频率是仓库配置，下次运行继续在 n8n 查看；实时启停和今天状态只来自下述只读元数据接口。

### 今天完成口径与接入

公开 `GET /api/imports/chain-status` 经真实 principal 和无限制数据范围校验后，薄适配至 Django workflow reader 的 `GET /api/workflow/import-chain-status`，后端再次鉴权。只允许读取白名单工作流，不接受客户端路径、日期或筛选参数。既有 AI `get_automation_run_status` 工具复用同一 reader，按选定工作流返回有界字段并沿用工具审计；受限数据范围在读取前拒绝。

Django 读取由运维显式配置的 `TERUISI_N8N_STATUS_DATABASE_PATH`。默认空值，未接入时显示无法核实；不回退用户目录、业务批次或历史 D1。2026-09-11 本机受控发布已为 workflow reader 配置 n8n SQLite 的绝对路径并确认读取权限，运行时包含生成的 JSON 白名单，11 条链回读 `source=n8n_execution_metadata`；采用记录见 [统一发布证据](evidence/guangdong-replenishment-health-production-20260911.json)。使用 SQLite `mode=ro`、`query_only` 和一致性读事务，仅查询 `workflow_entity` 的 ID/启停及 `execution_entity` 的 ID/状态/时间/工作流 ID；不读取凭据、节点参数或执行载荷，不写 n8n 或业务数据库。

按服务器上海日期统计当日结束的自动执行（`trigger`/`webhook`），并显示尚未结束的自动执行；页面明确区分“定时完成”和“自动重试完成”。手动调试、已删除记录和未来记录不计入。`success` 且有结束时间才算今天完成；当天成功后再次失败会显示最近失败并保留较早完成时间；运行中/等待优先展示，不能标绿。无保留记录显示“未查到今日自动记录”，不能解释成从未运行。执行级成功也不替代各业务域导入结果的回查。

人工从完整入口恢复成功仍属于 n8n `manual` 模式，不会把此前失败的定时/自动重试记录改写为自动成功。矩阵失败徽标明确写“最近自动执行失败”，并提示从 n8n 完整执行及业务批次核验人工恢复结果；不能仅凭任意手动节点调试成功把自动链路标绿。2026-09-24 吉客云自动执行 4143/4146 失败、手动完整恢复 4148 成功就是此口径的实例。

京东多店铺商品数据列固定绑定当前正式使用的 Chromium 静默下载副本 `JdN8nSilentCopy2026`；旧兼容工作流 `JdN8nM3uL7tI2026` 不进入页面目录或后端状态白名单。

页面每 30 秒自动刷新，切回可见页面时刷新，也可手动刷新；以 `checkedAt` 标明核查时间，过日或读取失败清除旧结果。查询上限为 32 个白名单工作流、2,000 条执行记录、2 秒 SQLite 执行预算，超限/锁定/缺失来源失败关闭，不以截断集合推断完成状态。

页面不保存规则、不启停调度、不触发导入。操作员/管理员可打开 n8n 的工作流及执行记录；只读用户仅查看配置详情。不会复制参考系统的调度器或退役其外部执行器的业务结论。

本机受控采用时，将明确核验后的 n8n 绝对路径保存为当前 Windows 用户的 `TERUISI_N8N_STATUS_DATABASE_PATH` 环境变量，并在本次受控启动进程中设置相同值。全部旧 Django 服务与守护停止后再部署、启动，使新 reader 和新守护继承同一配置；后续登录从用户环境继承。它是只读元数据路径，不包含密钥。发布回查必须返回 `source=n8n_execution_metadata`，配置缺失时仍返回无法核实。

## 隔离验收

在独立 worktree 使用既有 `preview:isolated` 入口。预览仅 GET/HEAD，合成销售、库存和 ERP 批次可以检查记录展示；其他域以空态为主。启动器额外创建一份独立 n8n 形状的合成 SQLite 元数据，覆盖成功、运行、失败、等待和无记录；以 SQLite application ID 标明来源，接口返回 `synthetic_n8n`，页面显示“合成状态演示”。不复制或读取生产 n8n 数据库。真实 n8n 执行、规则修改、生产部署和服务重启均不属于本次页面验收。
