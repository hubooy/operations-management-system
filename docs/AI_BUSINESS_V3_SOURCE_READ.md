# v3 封存来源内部签名读取候选

仅已暂停的 v3 报告意图可调用后端内部 `business-v3-source-read` 签名路径。首次目录请求在当前无范围管理员身份下重放完整封存、所有拥有方来源和 0032 工具收据，然后签发 10 分钟、按目录或精确来源区分的后端 HMAC 句柄。句柄固定意图、证据 ID/版本、封存原字节摘要、候选摘要、账号邮箱与版本、来源证明、用途、到期和随机数。续页不依赖进程内缓存；每页重新查当前账号、已封存父任务、选定不可变事实块的原始 SHA 和成功工具收据，返回前再次核验句柄与身份。某来源句柄不能用于另一来源。

正式 AI reader 角色没有全量审计日志读取权；首次完整核验需要该日志。因此这里只用 **签名 writer 进程 POST 做只读操作**，不调用 `write()`、不生成写回执、任务、模型调用或 Agent 阅读回执，也不扩大 reader 数据库授权。Next.js 公开代理不接受此路径；TS 适配器尚未注册到 Agent 工具目录。每次目录或事实切片严格小于 38 KiB，行切片最多 10 行，不把切片冒充完整事实页；超限拒绝而不截断。

当前桥只支持最多 **64 个事实页、8 MiB** 的整份封存进入首次核验。超过任一上限直接返回 413（即当前读取桥容量不支持），绝不先返回部分目录；纯角色计划也会显式给出 `currentReadBridgeCapacitySupported`。用户参考报告所需的约 64 MiB 全范围仍超出此只读桥，是后续 Agent 激活前必须解决的规模门禁。五角色阅读计划目前只是纯候选，标明每角色所需来源、最大切片调用与缺少的推广/B端来源；没有持久的 Agent 本人逐页阅读回执，也不能凭句柄声称某个 Agent 已完整阅读。v3 意图继续 `paused/v3_agents_not_registered`，模型、报告和 HTML/XLSX 文件生成仍关闭。
