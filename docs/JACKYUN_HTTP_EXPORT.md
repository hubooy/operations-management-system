# 吉客云网页校验与 HTTP 导出

## 适用范围

当前本机已采用工作流为 `automation/n8n/jackyun-five-dataset-http.workflow.json`。它与原工作流使用同一 n8n ID，部署时更新已有工作流，不能另外激活一条竞争链。文件默认未激活、只有手动触发；生成命令是 `node tools/generate-jackyun-export-first-workflow.mjs --direct-http`。不带参数的原生成命令和原工作流文件仍用于历史网页会话协议；后续发布当前版本应使用 HTTP 定义。

本版本借鉴独立签名请求、异步导出任务和统一续期，不依赖他人的源码。采用的是已登录网站自身的接口协议，并非吉客云官方开放平台的 AppKey 接入。该版本仍需专用浏览器初始化、读取动态仓库和字段、验证 SKU/日期/货主/权限；不能称为零浏览器取数。网页客户端发布后协议可能变化，签名比对或参数结构不符会停止。

## 执行过程

1. n8n 领取共享 helper，调用 `plan-direct-http` 创建绑定 execution、实际采集日及销售截止日的计划。
2. 五表共用专用浏览器与现有 DPAPI 登录。仍执行现有查询、字段回读、总数和组合装图片数量确认。无头浏览器固定为 1920×1080，避免复用的小窗口使库龄筛选按钮横向滚出视口。
3. 保留网页的实际校验请求，在最终 `startExcelExport` POST 发出前拦截。核验报表服务、模块、全页选择、双工作表、SKU、销售发货时间及月初至昨天边界。签名字段只存在内存，交接证据只保留业务参数 SHA-256。
4. HTTP 阶段把专用浏览器 context 设为离线，本机唯一会话所有者提交任务、按有界任务窗口轮询，沿用任务 ID、时间、标签、行数和 OSS 域名校验。平台确认提交后才向被拦截的浏览器请求返回结果；浏览器请求不会再次到达导出服务。
5. 全部五表下载后，复用原有文件验证、导入演练、Django importer、内容指纹、精确批次与落库回查。顺序和业务口径不变。

导出顺序：分仓库存、组合装及子件、销售单明细账、库龄、货品 SKU。导入顺序：货品、分仓库存、库龄、销售、组合装。销售按发货时间，截止昨天；每月 1 日沿用上月整月范围。库存及库龄是实际采集日快照。

## 会话与异常处理

- 签名上下文从当前账号的运行时获取，并与网页签名做一次包含中文和特殊字符的等价校验。不能只依据界面 `plate` 名称选择签名；网页还会依据自身 `isInJkyunCef()/signPlate` 分支选择协议。
- HTTP 请求复用浏览器的 Cookie、User-Agent 与 ati；这些值和 access token、refresh token、签名材料、签名 URL 只保存在内存，不写入 n8n、日志或工作流 JSON。DPAPI 账号凭据继续使用现有机制；没有新增明文会话文件。
- 只有可重放的任务查询/校验遇到平台明确的过期错误才按需续期；并发过期合并为一次续期。更新浏览器 Cookie 与 localStorage 前先比较原令牌对，同步写入后回读。刷新或发布结果不确定时封闭当前所有者，要求重新登录，不重试刷新旧令牌。
- HTTP 所有者只在专用浏览器离线且持有既有运行锁的阶段使用。浏览器恢复在线后结束该所有者，下一 HTTP 阶段重新读取当前会话，不共享旧内存令牌。
- 仅任务 GET 查询的传输异常最多重试一次；非 JSON、风控或业务错误不按传输异常重试。导出 POST 不自动重放，提交超时沿用网页的 120 秒预算，并保留网页选择的同步或异步模式。网络异常、权限/二次验证/风控响应或任务不唯一均保留原运行。
- 最终 POST 使用 Playwright Route 拦截。取消、校验失败或浏览器确认失败时先中止被暂停的确切请求，再卸载原页面，最后解除拦截，避免解除拦截释放原 POST 或迟到回调补发导出。
- 进程中断后，只允许对尚无导出意图、尚未下载的模块重新发起只读筛选；保留查询尝试历史，最多五次。已有导出意图的模块继续核对原任务，不能通过重置查询状态再次提交。
- 新传输版本 `web_prepared_http_v1` 与 `web_session_batch_v1` 的计划和 controller 状态隔离。原运行未闭合时不能通过改计划类型新建重复任务。
- 销售发货时间同时识别旧 `selectTimeStr=tradeOrder.consign_time` 与网页实际转换后的数值 `timeType=4`。若两者并存必须一致；付款、下单、货品级发货时间、字符串时间类型或缺少成本列仍拒绝。日期仍精确限定月初至昨天。
- 不采用截图里的滚动 45 天范围、5% 错行容忍或强制每 30 分钟刷新。零成本分类及补录政策不属于本次改动。
