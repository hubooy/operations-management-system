# 运营数据查询规范

适用范围：所有 TERUISI 运营管理系统的数据查询、核对与口径说明。

## 1. 数据源与权限

1. 优先使用 `teruisi_operations` MCP 数据源；查询开始前必须调用 `get_data_freshness`。
2. 如果 MCP 不可用，且用户明确指定本机运营管理系统或已导入数据源，才可使用本机只读数据源作为替代。回复中必须说明这是替代来源。
3. 连接和查询均为只读。不得导入、修改、删除业务数据，也不得声称已执行过这些操作。
4. 不得用记忆、样例数据或估算结果代替可查询的运营数据。

## 2. 查询前的固定检查

1. 读取并记录数据覆盖截止时间；输出结果时必须给出数据截止日期。
2. 确认时间范围、指标定义、渠道、平台、店铺、规格（SKU）等筛选条件。
3. 日期范围统一使用左闭右开区间。例如“2025 年 7 月 1–13 日”应筛选：

   ```text
   sales_time >= 2025-07-01 00:00:00
   sales_time <  2025-07-14 00:00:00
   ```

4. 店铺查询同时核验三个字段：

   ```text
   channel   = 平台-店铺名称
   platform  = 平台名称
   shop_name = 店铺名称
   ```

   若业务源只有渠道字段，使用 `channel` 作为店铺身份的主筛选，并将该情况写入结果说明。

## 3. 中文筛选与编码要求

1. 所有中文筛选值必须使用参数化查询；禁止把中文文本直接拼接进 SQL。
2. 通过 PowerShell、Python 或其他命令行脚本查询时，必须保证 UTF-8 传递；如果运行环境不能可靠传递中文，使用 Unicode 转义（如 `\u5929\u732b`）构造参数。
3. 查询结果为零时，不能立即认定“无数据”。依次检查：

   - 数据日期覆盖是否包含目标期间；
   - `channel`、`platform`、`shop_name` 的实际枚举值；
   - 中文参数是否在命令行或脚本中发生编码失真；
   - 时间边界、退款行和业务类型口径。

4. 只有上述检查均完成后，才可以报告“未查到记录”。

## 4. 金额、销量和退款口径

1. `allocated_amount_cents` 默认单位为人民币分；展示为元时必须除以 100。
2. 净销售额：

   ```text
   SUM(allocated_amount_cents)
   ```

   其中退款应以负值参与求和。
3. 同时需要正向销售额和退款额时：

   ```text
   正向销售额 = SUM(金额 > 0 的金额)
   退款额     = SUM(金额 < 0 的金额绝对值)
   净销售额   = 正向销售额 - 退款额
   ```

4. 销量必须明确口径：

   - 净销量：销售数量加退货数量后的结果；
   - 正向销量：仅正向销售行；
   - 需要退货拆分时，分别给出正向销量、退货量和净销量。

5. 金额默认保留到分；如用户要求整元或系统页面只显示整元，须注明采用四舍五入展示。

### 4.1 环比日期口径

- 完整自然月对比上一完整自然月；月度进行中对比上月相同日序范围。
- 单日对比前一日；近 7 天、近 15 天和近 30 天对比之前紧邻的等长滚动区间。
- 同一自然月内、超过一天的自定义范围对比上月相同日期范围，例如 9 月 5–20 日对比 8 月 5–20 日。
- 跨月自定义范围对比之前紧邻的等长区间。若上月不存在相同日期，则将日期收敛到上月月末。
- 页面或查询结果必须同时展示实际环比起止日期，不能只显示百分比。

## 5. 固定输出格式

每次运营数据结论至少包含：

| 项目 | 必填内容 |
| --- | --- |
| 数据来源 | MCP 或经用户授权的本机只读数据源 |
| 数据截止 | 数据覆盖的最新日期 |
| 筛选条件 | 时间范围、渠道、平台、店铺、SKU 等 |
| 统计口径 | 净额/正向/退款、净销量/正向销量等 |
| 结果 | 数值、单位和必要的小数精度 |
| 异常说明 | 缺数、字段映射、编码或退款口径等影响因素 |

## 6. 本次问题的防复发规则

对于“天猫 + 店铺 + 指定日期”的净销售额查询，必须使用渠道、平台和店铺三字段交叉验证，并使用 Unicode 安全的参数化输入。不得因为一次中文等值筛选未命中而认定数据未导入或店铺没有销售。
