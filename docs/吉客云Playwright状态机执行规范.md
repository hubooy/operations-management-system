# 吉客云五类数据导入：Playwright 状态机执行规范

适用范围：吉客云五类固定模块的日常导出、下载后处理和运营管理系统导入。

模块顺序固定为：

1. `products`（货品）
2. `inventory`（分仓库存）
3. `inventory_age`（库龄）
4. `sales`（销售单明细）
5. `combos`（组合装及子件）

## 运行架构

日常路径采用以下分层，不让模型参与每一步浏览器操作：

```text
计划任务 / 人工启动
  -> Playwright 状态机（隔离 Chrome profile）
  -> 下载事件与 OSS 白名单证据
  -> 统一下载后 runner（校验、筛选、分片导入）
  -> localhost:3000 批次核验与审计
```

- 页面导航、DOM 读取、鼠标输入和页面级超时由 Playwright 执行。
- CDP 仅用于吉客云旧式 MiniUI 导出不稳定时的网络/下载证据捕获；不是页面操控主通道。
- 不使用视觉识别或桌面鼠标兜底作为日常路径，避免影响用户办公。页面改版时先修复 Playwright 语义定位。
- 下载后处理、白名单过滤、刷刷仓/无效成本剔除、明确零成本保留、成本匹配和导入仍由正式 runner 执行，不允许浏览器层绕过。

## 与日常电脑隔离

- 使用专属 Chrome profile：`D:\运营管理系统\.runtime\jackyun-chrome-profile`。
- 使用独立调试端口：默认 `9223`。
- controller 在专属 profile 中创建或复用 `window.name=codex-jackyun-worker` 的独立工作页；模块切换只发生在该工作页，不依赖人工预先打开的标签。
- 用户日常 Chrome 可保留自己的吉客云标签或标签组；正式 Playwright runner 不控制该窗口。两边共享同一账号菜单配置时，也不得把用户标签当作自动化状态证据。
- 日常任务默认无界面（headless），不接管用户正在使用的 Chrome、鼠标或键盘。
- 首次登录、登录失效或需要人工排障时，以有界面模式打开专属 profile；不要连接用户日常 Chrome。

首次登录专属 profile（在 Chrome 提示时选择保存密码）：

```powershell
npm run jackyun:login
```

只读核验：

```powershell
npm run jackyun:browser -- --check-login
```

controller 不读取密码字段值，也不接受账号密码文件、环境变量或命令行密钥。登录态失效后，仅当 Chrome 已自动填充登录表单且没有验证码/二次验证时自动点击一次；其他情况失败关闭并等待人工验证。

日常执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-automation-runner.ps1" --run-id <RUN_ID>
```

仅在排障时显式显示专属浏览器窗口：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "D:\运营管理系统\tools\jackyun-automation-runner.ps1" --run-id <RUN_ID> --headed
```

## 状态与幂等规则

每个模块必须按以下状态推进：

```text
进入模块 -> 字段写入并读回 -> 查询（如需要） -> 表格稳定
-> 记录 exportIntent -> 仅一次导出 -> 下载事件/文件落地
-> 下载后处理 -> 批次完成 -> 下一个模块
```

- 每次字段操作只修改一个字段，并立即读回核对。
- 分仓库存和库龄必须使用可按日期查询的历史来源；日期控件精确读回目标日后才能查询。实时页、无日期框或日期读回不一致均停止，不能靠 runner 参数补写成历史快照。
- 销售日期固定为当月 1 日 00:00:00 至昨日 23:59:59。
- 表格必须先证明经历了本轮查询的加载状态或指纹变化，再在刷新停止、总行数连续稳定后才能导出；旧表本来就稳定不算本轮证据。
- 分页显示“共 N+ 条 / 查看总数”时先点击一次“查看总数”并读回精确值；MiniUI `totalCount` 可能只是当前页（例如 51），不得优先于页面精确总数。页面明确返回 0 行且没有任何导出/下载/导入证据时，只允许一次持久化后的查询重试，第二次仍异常即停止。
- 模块入口使用吉客云稳定菜单类名直接触发，再以激活标签或内容 iframe URL 验证；禁止在驾驶舱先固定等待二级菜单文本。
- 货品、分仓库存、库龄在提交导出前拦截 MiniUI 导出配置，仅保留运营系统必需列；销售继续使用最小列导出；组合装保持母件/子件双表原格式。
- `exportIntentAt` 已写入但没有下载结果时，恢复时只恢复监听或报告阻塞，绝不重复点击导出。
- 组合装必须确认包含“图片列”“最多 2000 条”“确定导出”的提示，且只点击一次“确定”。
- 仅接受本轮下载事件绑定的原始文件；`RUN_ID`、模块、策略版本、下载 ID、方式、完成时间、原文件名、SHA-256 和字节数必须齐全，文件必须直接位于本轮模块专属目录。原文件名仅用于审计，合法 OSS 数字对象名不得因不符合中文名称而被拒绝。不得扫描“最新文件”、重用历史文件或处理后文件。

## 等待与超时策略

当前策略版本：`2026-08-06.1`。

| 项目 | 默认值 | 目的 |
| --- | ---: | --- |
| 快速轮询 | 200ms | 等待页面状态、下载后处理结果，避免固定长等待 |
| 单次页面动作 | 15 秒 | 点击、菜单、字段读取失败时快速报出 |
| 表格稳定 | 20 秒 | 以连续两次相同行数确认查询完成 |
| 货品模块 | 30 秒 | 页面准备与切换超时 |
| 库存、库龄、组合装 | 45 秒 | 查询或页面准备超时 |
| 销售模块 | 60 秒 | 日期筛选和大表查询超时 |
| 下载后处理结果 | 15 分钟 | 留给大文件筛选、分片导入和数据库核验 |

最小导出列固定为：

| 模块 | 列 |
| --- | --- |
| 货品 | 货品编号、货品名称、固定成本价、基础单位 |
| 分仓库存 | 货品编号、货品名称、规格、单位、仓库、固定成本价、库存数量 |
| 库龄 | 仓库、货品编号、货品名称、库存数量、库龄(天) |
| 销售 | 由销售最小列配置控制，必须包含白名单、金额、成本和日期校验所需列 |
| 组合装 | 不缩列，保留母件表和子件关系表 |

`browser-controller-state.json` 按模块记录 `enterModuleMs`、`tableStableMs`、`exportToDownloadMs` 和 `postDownloadMs`。页面出现“【导出任务】…执行中”时，耗时归入吉客云服务端导出阶段；不得通过加快轮询或重复点击解决。

超时意味着当前页面状态或下载证据不足；停止后续模块并保留审计，不做连续点击或盲目重试。

## 下载与导入证据

浏览器事件写入：

`outputs\jackyun-browser-events\<RUN_ID>\`

运行清单、浏览器状态与模块审计写入：

`outputs\jackyun-import-runs\<RUN_ID>\`

每个模块至少要保留：handoff schema 版本、`RUN_ID`、策略版本、原始文件路径、下载 ID/方式/时间、文件 SHA-256 与字节数、页面稳定总行数、字段核对、导航/查询/表格稳定/导出时间、导入批次号、警告和异常。库存与库龄还必须保存目标日、页面读回日、读回时间、查询时间、`queryRefreshSource`、`queryRefreshCompletedAt` 和表格稳定时间的 `snapshotEvidence`；销售模块还必须记录库存成本源与数据截止日期。

## 验收

正常任务只有在五个模块均返回 `completed` 后才算完成。任一模块出现登录验证、页面超时、导出不完整、文件校验失败或导入失败时：

1. 停止后续模块。
2. 保留当前 `RUN_ID` 的状态和审计文件。
3. 使用同一 `RUN_ID` 和 `--resume` 恢复；不得另起运行混用旧文件。自动续跑只接受连续完成前缀、当前模块有完整证据证明从未查询/导出/下载/导入的前置失败，或经精确页面总数、同路径/SHA 文件、导入前失败审计和无 import 证据共同确认的行数元数据修正；修正路径只复用原文件，不重新导出。其他 `BLOCKED` 状态继续要求人工核验。
4. 修复页面适配或数据规则后，先跑相应单元测试，再进行一次受控实际验证。

## 维护原则

- 优先修复接口或 Playwright 语义定位；视觉操作只可作为隔离环境中的最后手段。
- 新增等待必须以事件、DOM 状态或稳定行数为条件，禁止在成功路径增加固定长睡眠。
- 新模块或字段变化必须同时更新状态机、策略、文件校验和测试。
- 正式日常任务只运行本地 runner；模型只用于异常诊断、代码维护和优化建议，以减少 token 消耗与运行时间。
