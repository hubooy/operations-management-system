# v4 规模京东推广完整词链纯流式候选

`business_analysis.promotion_relation_v4.prepare` 每次只处理一个精确来源窗口。本期、环比和同比须分别提交自己的来源描述、全部原始页及 `business_v4_promotion_replay.inspect` 形状的完整重放证明；任何页的过滤器、来源引用、修订或日期不属于该窗口即拒绝。证明在本模块里仅做自一致性约束，调用方即使能重算摘要，也不能因此获得封存或上游签名权威。当前内部 owning 已支持同一固定 run 的三个京东推广窗口分别采集与重放；这些来源尚未父封存，纯算法支持不等于报告可用。

词链按业务日、关键词、搜索词、计划 ID/名称、单元 ID/名称、匹配方式与**明确推广、触发、跟单**三种 SKU 身份分组；同时输出独立推广 SKU 和跟单 SKU 两个切面。缺词、缺搜索词或缺 SKU 留明确 `null` 桶，费用和平台归因金额不挪给其他身份。每条源事实只进入临时 SQLite 一次，分别且仅一次归入三个切面；每个切面都与该来源的全部指标、行数、有值/缺值行数守恒，切面之间不能相加。真实首页即使因为字节上限不足 100 行且仍有下一页，也按原签名 cursor 链继续核验，不按“满 100 行才翻页”猜测完整性。

从已完成证明与页载荷重新核对 run/source 身份和版本、原查询、sourceRef/revision、页序和 cursor、规范字段、页 SHA、完整控制总额和实际日期覆盖。来源描述、证明和逐页输入先做有界拷贝；额外指标在进入累积器之前被拒绝；重复源行 ID、重复非空内容摘要、漏页或错基期均整次失败。分组使用临时 SQLite，不把最多 1,638,400 条 v4 源行装入 Python 列表；`max_page_count` 将**主 SQLite 文件**限为 4 GiB，完整输出限为 2 GiB，每个输出分片限为 38,000 字节，超限拒绝而不截断。SQLite 的操作系统排序临时文件不受 `max_page_count` 约束，因此 4 GiB **不是整个临时目录的硬上限**；虽然当前按 `(view,key)` 主键顺序扫描，真实规模仍须单独做磁盘峰值与耗时验收，不能把本候选称为已通过参考数据容量终验。

参考来源 575,095 行处于 v4 物理行数上限内，但真实页宽、分组基数、临时磁盘、耗时与最终输出大小尚未实测。另用每行独立词/搜索词/SKU 的高分组合成数据做隔离观察：1 万行的分组与守恒为 17.1 秒、主 SQLite 文件 135 MiB、NDJSON 31.6 MiB；5 万行分别为 65.3 秒、674 MiB、158 MiB。临时目录峰值只是定时采样，且未覆盖 SQLite 系统排序文件；不能线性外推 575,095 行。结果始终 `sourceAuthorityVerified=false`、`upstreamSignatureVerified=false`、`sealed=false`，不注册 Agent、正式 renderer、下载或生产采集。
