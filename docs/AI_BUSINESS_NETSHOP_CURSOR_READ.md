# 网店过期游标内部续读候选

2026-09-18。`backend/netshop/analysis_cursor.py` 新增内部只读取页能力，尚未接入 AI 采集器、公开路由或恢复按钮。不能据此宣称生产长任务恢复已修复。

只有原网店签名通过且实际抛出 `SignatureExpired` 时才允许同次请求中生成临时游标。未过期游标继续使用正常读页流程；坏签名、错误 salt、身份撤销、版本变化、原查询或主数据批次变化均拒绝。读取复用 `netshop.analysis.read_page`，不复制其来源绑定和分页公式，不扩大原日期、窗口或页长。

调用者提供的 `expected_source_ref`、`expected_revision` 和 `expected_last_id` 仅是额外一致性约束，不是检查点授权。此服务不接受续签 proposal 作为权威，不写检查点，不修改旧事实块。

## 下一步接入要求

1. AI 数据所属服务从当前任务和来源行读取原目录及原始检查点，再从真实不可变末块复核字节摘要、sequence、最后主键、nextCursor、sourceRef 和 revision。禁止使用客户端自述代替。
2. 固定当前账号、任务版本、来源版本、计划与范围；仅针对事实页签名过期调用内部续读。不得将所有 409、版本变化或网络错误当作游标过期。
3. 临时 token 只用于同次取页。`PageReconciler.consume` 仍使用原检查点中的逻辑 request cursor，保留旧页的 nextCursor 字节，成功页自然给出新的下一页游标。
4. 保存新页时保留现有任务/来源/完整检查点 CAS，并重新核验权限、取消和封存状态。并发恢复只允许一个提交；丢失响应只能重读，不能重复落页。
5. 补充真实 AI 末块篡改、并发推进、取消、响应丢失及原链完整重放测试，再连接 UI。销售和市场事实页需分别实现所属数据服务验证，不能直接复用网店 salt 或绑定公式。
