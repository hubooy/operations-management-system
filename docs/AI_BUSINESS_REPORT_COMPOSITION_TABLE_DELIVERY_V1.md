# 三期经营组合表格交付候选（v2 小规模）

`report_composition_tables_v1.prepare` 在 `report_composition_v1` 的同报告封存复验通过后，从相同的逐日材料重算店铺和 SKU 候选，产出固定 13 张 `report_files.Table`。前 12 张是店铺逐日、店铺比较、ERP 未分配池、品类、ERP SPU、商智原生 SPU、SKU、关键词来源覆盖、财报自然月来源、B 端来源、市场样本来源、30 天行动；第 13 张是逐表核对。所有表在交给写入器前完整物化并受 5 万行 / 32 MiB 总容量限制，超限整份拒绝，不截断。

逐表核对行保留上游清单摘要及其原行数、投影后实际行数、列数和规范行摘要。一个上游逐日行会展开成多个指标行，因此上游行数不等于交付表行数。核对表本身不做自引用；其摘要单独写在 `auditTableDigest`。HTML 与 XLSX 必须同次调用 `report_files.write_pair`、消费相同 `Table` 元组；结果回执中的每张表行数和摘要须与预先核对值相同，任何异常都不得发布临时文件。

缺来源、缺日期、缺值和不可比较基期保留原状态与 `null`。ERP 历史品类/SPU/SKU 归属未经证明时，差额与增长率保持 `null`。ERP 未分配池是 ERP 的子集，商智支付、ERP 销售、广告归因、财报、B 端和市场样本不跨域合并。关键词目前仅展示已核表头与缺口，不展示或假定完整关键词数据；财报、B 端、市场仅为来源/上下文表，没有销售或利润数值列。行动表全部不可自动执行。

本候选未注册 renderer1–11，也不写报告数据库。当前封存 v2 页数容量不足以覆盖 57.5 万推广事实的参考规模；v4 全量需要版本化分片 Table 流及同样逐表摘要与中途失败清理。上线门槛还包括：拥有方跨来源同报告/账号/版本复验、真实多 Agent 同 job/provider 已读与数值引用、人审动作、HTML/XLSX 文件权限及下载围栏、完整规模和原生 Excel 验收。合成测试对同次写出的 HTML JSON、XLSX 工作表实际行数、写入器回执和预先核对表逐项比对，不代表上述业务验收已完成。
