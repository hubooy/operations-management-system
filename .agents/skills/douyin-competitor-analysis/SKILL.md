# 抖音竞品分析与获客打法

## 先确认交付范围

- 识别竞品主页、我方主页、行业/品类和用户需要的交付形式。
- 用户未明确品类时，从主页简介和近期作品推断当前主营方向，并在结论中标注该假设；不要因此停下分析。
- 用户说明页面已登录时，复用现有登录会话，不退出、不切换浏览器资料目录、不要求重复登录。
- 分析默认只读。不得点赞、关注、评论、私信、下单、开播、发布作品或修改账号资料，除非用户另外明确授权相应动作。

## 证据采集

按 [复用手册](references/douyin-competitor-analysis-playbook.md) 的字段采集，并保留数据截止时间。

每个账号至少取得：

1. 账号名、主页链接、简介、抖音号、地区、作品数、粉丝数、获赞总数、店铺/直播等公开承接入口。
2. 近期作品的主题分布，用于判断账号实际在向算法和用户发送什么信号。
3. 一至三条代表作品，记录发布时间、点赞、评论、收藏、分享、关联搜索和公开评论中的购买意图。
4. 代表作品优先选择能说明获客机制的内容，不机械选择点赞最高的视频。购买型评论、参数问题、场景描述、报价询问和长期搜索价值优先于纯情绪互动。

采样应有界。浏览近期内容并检查足够的公开评论，直到账号定位、内容支柱和咨询模式已稳定可判断；不要为了“看完全部作品”拖慢交付。

## 分析框架

对每个竞品依次回答：

- **定位**：服务谁、解决什么问题、凭什么相信它。
- **核心获客方式**：搜索/推荐/本地/人设/案例/直播/店铺如何形成从流量到咨询的路径。
- **核心种草内容**：反复强化哪些场景、参数、成本、案例、资质、服务或人物故事。
- **信任证据**：现场、客户、数字、检测、工厂、售后、资质或公开评论中有哪些可核验证据。
- **值得学习**：提炼可迁移的机制，不只描述表面题材。
- **不应照抄**：指出会带来低意图流量、同质化或专业度损失的做法。

诊断我方时至少比较：简介承诺与实际内容、目标买家是否一致、品类是否混发、选型问题覆盖、案例量化、人设承接、搜索资产、CTA 和线索归因。

不要默认“发得更多”就是答案。先判断是内容数量不足，还是账号信号、购买意图和转化承接不足。

## 策略输出

- 把建议写成“买家＋场景＋问题＋证据＋行动”的可执行结构。
- B2B 商用设备账号可把“40%选型、30%案例、20%人设、10%直播/服务”作为起始配比，但必须根据公开证据和用户业务目标调整，不把该比例写成平台通用规则。
- 30天计划应包含阶段、任务、交付物、检查指标、负责人、优先级和状态；先校准定位，再建内容模型，再放大胜出格式，最后追踪线索与成交。
- CTA 应收集可用于筛选线索的结构化信息，如场景、人数/产能、城市、水质/菜品、时间和预算，而不是只写“点击了解”。
- 选题应围绕真实采购问题，避免只有“高效、稳定、省力”等无法形成搜索和收藏价值的泛化卖点。

## 交付模式

- **对话分析**：先给核心结论，再给逐账号拆解、我方诊断、行动建议、来源与边界。
- **复用 MD**：使用复用手册中的 Markdown 模板，保留占位符、来源链接、数据截止时间和分析假设。
- **Excel**：用户要求工作簿时调用电子表格能力，默认包含总览、账号原始数据、代表作品证据、竞品拆解、我方诊断、30天行动计划、选题库和 KPI 追踪模板。
- **HTML**：用户要求网页时生成自包含、响应式、可离线打开的 HTML；加入来源链接、打印样式和必要筛选。用户只要求本地文件时不发布、不托管。

### 快速模式

用户明确说“不用渲染”“快速做出来”或同义要求时：

- 不做工作簿图片渲染、浏览器截图或额外视觉复查。
- 仍执行最低限度的结构检查：文件可打开、公式错误扫描、必要工作表/章节齐全、链接和日期对应正确、HTML 标签与脚本语法基本完整。
- 在交付中说明已跳过视觉渲染，不把未执行的视觉检查写成已通过。

否则，按对应文件能力的标准验证流程执行。

## 数据边界与质量门禁

- 所有账号指标注明采集时间；粉丝、获赞、作品数会波动。
- 主页获赞总数、代表视频互动和账号后台播放/成交不是同一口径，不得混写。
- 页面没有播放量、投流、私信、报价、订单或成交数据时，明确写“未取得”，不得推断真实转化率或 ROI。
- `获赞总数 ÷ 作品数` 只能标为“获赞/作品的简单效率指标”，不能冒充平均单条点赞。
- 公开评论仅摘录短句或概括需求模式，避免保存个人身份信息和无关原始评论。
- 每个结论应能回指主页、代表作品、公开评论或我方后台数据；证据不足时降低结论强度。
- 最终交付列出账号主页和代表作品链接，并说明数据来源、截止时间、缺失字段和关键假设。
