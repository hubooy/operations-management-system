# 抖音竞品分析复用手册

本手册用于把一组竞品抖音主页与自有账号，快速转化为可执行的定位判断、获客机制、内容策略、30天计划和数据追踪方案。适合商用设备、B2B 制造、门店服务和需要从公开视频获取线索的账号。

## 1. 快速输入模板

复制以下内容并替换占位符：

```markdown
行业/品类：{{行业或产品}}
本次业务目标：{{获客 / 品牌 / 招商 / 到店 / 直播成交}}
目标客户：{{采购角色、公司类型、地区}}
竞品主页：
1. {{竞品1链接}}
2. {{竞品2链接}}
3. {{竞品3链接}}
4. {{竞品4链接}}
我方主页：{{我方链接}}

需要输出：
- 每个账号的定位、核心获客方式、核心种草内容
- 值得学习和不应照抄的地方
- 我方诊断、30天行动计划、选题库、KPI
- 交付格式：{{对话 / MD / Excel / HTML}}
- 是否快速模式（不渲染）：{{是 / 否}}
```

## 2. 证据采集表

### 2.1 账号层

| 字段 | 记录内容 | 说明 |
|---|---|---|
| 身份 | 竞品1 / 竞品2 / 我方 | 固定编号，避免链接串号 |
| 账号名 | 主页显示名称 | 保留完整名称 |
| 主页链接 | 短链或完整链接 | 交付时保留可访问来源 |
| 抖音号、地区 | 公开资料 | 没有则写“未展示” |
| 简介 | 公开简介的核心承诺 | 概括即可，不需全文复制 |
| 作品、粉丝、获赞 | 主页公开数字 | 写明采集日期 |
| 店铺/直播 | 商品数、是否正在直播等 | 只记录采集时可见状态 |
| 实际内容主题 | 近期作品的业务线和栏目 | 用于检验“简介与内容是否一致” |
| 初步定位 | 服务谁＋解决什么＋凭什么 | 一句话完成 |

### 2.2 代表作品层

| 字段 | 记录内容 |
|---|---|
| 账号与作品链接 | 防止证据串号 |
| 标题、发布时间 | 以页面显示为准，统一上海时区 |
| 点赞、评论、收藏、分享 | 缺失时写“未展示” |
| 关联搜索 | 判断平台把内容归到什么需求词 |
| 公开评论需求 | 参数、场景、报价、地区、安装、售后或情绪互动 |
| 购买意图 | 很高 / 中高 / 偏低，并写判断依据 |
| 证明的机制 | 搜索、案例、人设、教育、直播或店铺承接 |

代表作品不一定是点赞最高的作品。优先选择能够说明“流量为什么来、信任如何建立、用户为什么咨询”的内容。

## 3. 单账号拆解模板

```markdown
### {{账号名}}

- 账号定位：{{目标买家＋核心问题＋信任身份}}
- 核心获客路径：{{搜索/推荐入口}} → {{内容证据}} → {{咨询/店铺/直播承接}}
- 核心种草内容：{{场景、参数、成本、案例、人设、服务}}
- 代表作品证据：{{链接、互动、评论需求、关联搜索}}
- 值得学习：{{可迁移机制}}
- 不应照抄：{{低意图、同质化或专业风险}}
- 我方可应用：{{具体栏目、脚本、CTA 或承接方式}}
```

定位句建议用：

> 面向【谁】，解决【什么高成本问题】，通过【什么证据或身份】建立信任，并用【什么入口】完成咨询或成交。

## 4. 获客机制判断

| 机制 | 常见入口 | 有效证据 | 典型风险 |
|---|---|---|---|
| 高意图搜索 | 型号、参数、人数、吨位、成本、故障、地区 | 评论出现具体场景、规格、价格或采购时间 | 只有参数，品牌与服务弱 |
| 本地/工程案例 | 城市、学校、工厂、医院、门店、项目 | 现场、客户类型、安装过程、验收和售后 | 案例同质化、隐私暴露 |
| 创始人/员工 IP | 创业、家庭、员工、工厂日常 | 长期稳定出镜、真实经历、明确专业观点 | 情绪流量多、采购意图低 |
| 采购教育 | 避坑、成本、配置、合同、售后 | 数据、清单、前后对比、部件和流程 | 没有证据时变成泛知识 |
| 直播/店铺 | 选型门诊、现场报价、商品卡 | 问题记录、连麦、型号边界、服务承诺 | 只做促销，无法沉淀搜索资产 |

一个账号可以组合多种机制，但应有一个清晰主入口。分析重点是找到“主入口—信任—承接”的闭环。

## 5. 我方诊断清单

逐项回答“当前证据、业务影响、竞品基准、30天动作、完成标准”：

1. **定位一致性**：简介承诺与主页首屏是否一致。
2. **受众一致性**：不同场景是否属于同一采购者与预算体系。
3. **品类信号**：多品类是否互相稀释，是否需要英雄品类或分账号。
4. **内容结构**：是否回答明确购买问题，而非堆叠通用卖点。
5. **选型内容**：人数、峰值、产能、原水、点位、成本、滤芯、安装和售后是否讲清。
6. **案例证据**：是否有数字、现场、过程、前后对比和结果。
7. **人设信任**：是否有人稳定承接专业判断与售后承诺。
8. **搜索资产**：关联搜索是否出现非品牌高意图词，旧内容是否持续获客。
9. **转化承接**：CTA 能否收集完整需求，线索能否追溯到作品。
10. **发布策略**：内容量是否形成复利，还是重复发布低意图模板。

## 6. 内容策略模板

对 B2B 商用设备账号，可先测试以下配比，再依据有效线索调整：

| 内容支柱 | 起始占比 | 要回答的问题 | 必须展示的证据 |
|---|---:|---|---|
| 高意图选型 | 40% | 怎么选、选多大、总成本、安装条件、售后边界 | 参数、计算、检测、部件、现场读数 |
| 真实案例 | 30% | 别人为什么买、怎么装、效果如何 | 场景、人数/产能、过程、结果、验收 |
| 顾问人设 | 20% | 为什么相信这个人和团队 | 现场判断、质检、试机、售后工单 |
| 直播/服务 | 10% | 如何得到个性化方案 | 选型门诊、案例拆解、评论答疑 |

每条视频使用“五要素”：

> 一个买家 ＋ 一个场景 ＋ 一个问题 ＋ 一个证据 ＋ 一个行动

通用 CTA：

> 私信“场景＋人数/产能＋城市”，领取免费配置方案或成本表。

根据品类替换需求字段，例如水质、菜品、餐数、预算、设备型号、现场尺寸或采购时间。

## 7. 30天行动计划模板

| 阶段 | 时间 | 核心任务 | 交付物 | 检查指标 |
|---|---|---|---|---|
| 校准 | D1—D3 | 审计最近内容；确定英雄品类、核心买家；更新简介、合集和三条置顶 | 内容审计表、定位句、3条置顶脚本 | 团队能在15秒内复述账号价值 |
| 建模 | D4—D14 | 建立选型、案例、人设、服务四个内容支柱；统一 CTA 和私信字段 | 首批高质量视频、问题词库、私信 SOP | 关联搜索出现非品牌问题词，出现具体需求咨询 |
| 放大 | D15—D21 | 根据搜索、收藏和有效线索选出胜出格式；固定直播与评论回复 | 胜出模板、放大视频、直播切片 | 有效线索/条高于前一阶段中位数 |
| 转化 | D22—D30 | 追踪私信、报价、订单和成交额；停止无效模板；形成下月计划 | 线索台账、归因表、月度复盘 | 作品到线索、报价、订单可追溯 |

执行表还应包含负责人、优先级、状态和实际完成日期。

## 8. 选题生成公式

优先从评论、搜索建议、销售问答和售后工单提取问题，再套用以下结构：

- 【人群/规模】＋【采购动作】＋【最容易忽略的数字】
- 同样写【参数】，为什么实际【结果不同】
- 【异常场景】，选择【工艺/设备】前必须检查哪几项
- 【旧方案】一年花多少钱？现场算一遍总成本
- 采购只比【设备价】，为什么后面的【耗材/售后】更贵
- 【真实客户规模】改造：从【问题】到【结果】用了多久
- 免费【试机/勘察】到底看什么？完整流程
- 【质保/全国售后】具体保什么、多久到、谁承担费用

选题表建议字段：业务线、内容支柱、核心买家、标题、开头钩子、必须展示的证据、CTA、漏斗阶段、负责人和状态。

## 9. KPI 口径

按以下顺序看指标：

1. **高意图关联搜索词**：是否从品牌词变成参数、场景、成本、安装或售后问题。
2. **有效评论/私信**：是否包含场景、人数/产能、城市、时间、预算、型号等具体信息。
3. **主页访问、商品点击**：目标用户是否进一步验证账号与产品。
4. **报价、订单、成交额**：必须回填来源作品和搜索词。
5. **3秒留存、完播率**：用于判断钩子和表达效率，不能单独代表线索价值。
6. **收藏率、分享率**：选型与教育内容优先看收藏，案例和服务内容结合分享及咨询判断。

推荐首月北极星指标：

> 有效线索数 ＋ 有效线索/条

建议追踪字段：发布日期、作品链接、业务线、内容支柱、核心买家、标题/搜索词、播放量、3秒留存率、完播率、点赞、评论、收藏、分享、主页访问、商品点击、私信、有效线索、报价、订单、成交额、复盘备注。

## 10. 交付结构

### Markdown 报告

1. 执行摘要与核心结论
2. 账号数据快照
3. 每个竞品的定位、获客、种草、学习点和风险
4. 代表作品及评论证据
5. 我方账号诊断
6. 内容结构与置顶/合集建议
7. 30天行动计划
8. 选题库与 KPI
9. 来源、截止时间、缺失字段和假设

### Excel 工作簿

推荐工作表：

1. `总览`
2. `账号原始数据`
3. `代表作品证据`
4. `竞品拆解`
5. `我方诊断`
6. `30天行动计划`
7. `选题库`
8. `KPI追踪模板`

输入单元格应有明确底色；日期、数值和百分比使用正确格式；账号与作品链接保留完整 URL；公式列与输入列分开。

### HTML 报告

推荐章节：核心结论、账号规模、竞品卡片、代表作品证据、我方打法、30天路线图、选题筛选、KPI 和来源。文件应自包含、响应式、可打印，并可离线打开。用户仅要求本地 HTML 时不执行托管或发布。

## 11. 快速模式与质量检查

用户明确要求不渲染时，跳过 Excel 图片渲染、浏览器截图和额外视觉复查，但仍检查：

- 文件可以打开，必要工作表或 HTML 章节齐全。
- 公式扫描没有 `#REF!`、`#DIV/0!`、`#VALUE!`、`#NAME?` 或 `#N/A`。
- 竞品编号、主页和作品链接没有串号。
- 公开数字、日期和时区对应正确。
- HTML 的关键标签数量闭合、内部锚点存在、脚本语法可解析。
- 交付说明明确写出“未执行视觉渲染”。

标准模式还应按文件能力的要求进行视觉检查。

## 12. 最终交付检查表

- [ ] 所有账号指标注明采集日期。
- [ ] 主页获赞、作品互动和后台转化没有混为同一口径。
- [ ] 没有播放/投流/成交数据时，没有推断真实 ROI。
- [ ] 每个竞品至少有一条代表作品或明确说明证据不足。
- [ ] 学习点描述的是机制，不只是模仿题材。
- [ ] 我方动作有负责人、完成标准和可追踪指标。
- [ ] 所有链接可回溯到正确账号或作品。
- [ ] 公开评论只保留必要短句或需求模式，不保存个人身份信息。
- [ ] 未经授权没有执行点赞、关注、评论、私信、发布、下单或账号修改。
